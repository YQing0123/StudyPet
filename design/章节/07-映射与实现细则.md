## 16. 组件与数据映射约定

### 16.1 公开契约与存储字段

HTTP DTO是服务端显式投影，不能直接把数据库行序列化。下列映射固定由应用repository/assembler实现，单元测试检查往返和敏感字段剔除。

| 对象 | API/领域字段 | 数据库映射与规则 |
|---|---|---|
| 教材切片 | kind、node_id、normalized_text | source_slices.slice_kind、node_id、normalized_text；kind仅context/sentence/word |
| 题目 | objective_ids | 每个题目恰好1个主目标，对应question_versions.objective_id；多目标蓝图拆成多个槽位 |
| 题目 | prompt/instruction、public_payload | prompt_text/instruction_text与题型JSON分开，payload受题型Schema校验；答案、解释不进入公开列 |
| 选项/空/词块 | UUID子ID | 选项对应question_options.id；词块/空UUID保存在受限public_payload与private评分引用中 |
| 题目状态 | published/retired | question_versions.status为生产状态，published_at/retired_at派生运行发布状态 |
| 计划 | revision、active_revision_id | 计划修订revision_no和最后已发布且未退役修订；不能把task.revision当plan revision |
| 任务 | stable_slot、required | stable_task_key、is_required；奖励资格使用entitlement.stable_slot并冻结映射 |
| 学习日期 | finish_deadline | learning_day收尾时刻与session.submit_deadline_at；补做另有受权审计 |
| 学习声明 | source、date_precision | DB使用self_report/parent/historical/authorized_external来源，API别名统一转换，不与assessment来源混淆 |
| 库存 | item_id、unit_kind | item_definition_id、unit；nutrition_point为营养最小单位，piece为材料/饰品 |
| 宠物 | life_stage | pet_states.growth_stage baby→juvenile、young→adolescent、adult→adult、elder_reserved→senior；后者未启用 |
| 宠物 | care_mode | normal→active、resting→resting、hosted→boarding |
| 宠物 | scene_key、disease_state | location_key；疾病由当前hospital_case与允许规则派生，不新增客户端可写生命字段 |
| 学习证据 | independence | independent→independent、hinted→prompted、demonstrated→answer_exposed、parent_confirmed→parent_confirmed |
| 文件 | finalized | 媒体通过校验且文件落定的运行状态；upload临时阶段不作可评分资源 |
| 后台作业 | retry_wait | queued且available_at晚于当前时间，显示为retry_wait；重试不增发业务资格 |

### 16.2 会话状态的存储映射

created/ready/submitting/paused中的一部分是界面状态，不能全部直接写到SQL CHECK枚举。持久化session使用created、active、submitted、pending_review、completed、expired、cancelled；task承担scheduled、active、pending_review、completed、cancelled、content_blocked生命周期。

| 领域/显示状态 | 存储/判定 |
|---|---|
| created预加载中 | 创建命令尚未提交或客户端本地状态；完整题单提交后DB created对应ready |
| active/paused | DB active；paused为本机草稿/最后活动信息，恢复仍校验租约和窗口 |
| submitting | 客户端请求中；DB submitted表示提交已收齐且待终结评估 |
| awaiting_review | DB pending_review，review_reason=oral或assistance |
| late_review | DB pending_review/expired并有late_sync复核请求；late标签永久保留 |
| needs_support | 存储原尝试与缺少要求；task仍active，结束旧session为completed但不标task成功，再新建补救session |
| blocked_content | task.content_blocked，受影响session不能继续评分；原form保留，新替代表单另建session |
| completed | session已处理完；TaskCompletion是否成功取决于task.status=completed和有效证据，不仅看session终态 |

P1每个verification session的任务完成要求仍由task_requirements决定。补救session关系保存在版本化会话payload/审计关联或显式parent引用，不能重置曝光历史。无task的诊断session不参与奖励；若数据库约束要求证据学习日，则创建无奖励diagnostic task/day容器，不能借用正常发粮资格。

家长选择unrecognized不写approved，不生成passed证据；可以保留pending并说明“需重录/现场确认”，或以needs_help结束此次复核，再另开有效尝试。接口review.status只返回pending/approved/needs_help/cancelled，未识别原因单独显示。

### 16.3 幂等和修订的边界

应用以数据库每个可编辑聚合的revision作为expected_revision依据，发布快照使用version_no/revision_no且不可原地改写。family_settings按policy_key和策略版本更新；发布后新建未来生效版本，不追溯改变历史窗口、学习范围和奖励。

idempotency_records的唯一范围为family＋operation＋key，保存请求者identity与摘要；相同键被不同请求者使用不得返回其他人的原结果。终结响应和私有答案反馈不可通过广泛幂等查询泄露，查询必须匹配原actor或明确授权家长。客户端总是生成高熵UUID避免无意义碰撞，数据库业务唯一键负责真正的防重复。

body.expected_revision用于资源乐观锁，不用payload_hash冒充整数版本；不可变源/题快照的修订传所读version_no，校验后产生新UUID。能力上报profile可使用device.id和capability revision，不必建立第二套重复能力真值。

### 16.4 运行控制表

family_settings记录策略key、schema、版本、未来生效日和payload。content_issues记录孩子/家长的题目或媒体问题、分类、状态、修复关联和revision。ai_provider_configs只保secret_ref和能力/model等配置，真实凭据从部署secret提供。ai_budget_reservations在生成前预留，调用后结算/释放，同run/job唯一。outbox_deliveries按event＋consumer唯一保存投递状态/重试，不能用outbox单个delivered_at代表所有消费者成功。

后台job payload只用于版本化作业参数与结果引用，不代替这几类需要约束、检索、权限和并发的实体。provider自动探测不得回显密钥；变更地址进行SSRF和协议限制，只有owner可配置。

### 16.5 逻辑复用边界

文本与词条采用词形/父词义/多词单位关联，掌握证据不沿父关系自动扩散。源内容与生成题包分离，固定ID和版本支持增量生成。判分采用纯函数、每空允许答案、词块多重集合和逐项反馈，通用容错不覆盖拼写目标。

练习筛选先基于实际接触范围与能力，再按薄弱、到期与近期独立错误排序；错题清除需要之后有意义的独立成功，不能因为同次提示重试最后答对就消失。发布内容只返回公开投影，连线必须服务端校验真实配对，不采用客户端自报错误数。相关具体开源文件和许可映射单列于开发附件，运行产品不依赖这些外部项目在线服务。
