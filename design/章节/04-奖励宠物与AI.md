## 6. 奖励、库存与事务设计

### 6.1 稳定资格

RewardEntitlement保存child、period_kind(day/week)、period_key（本地学习日或周一日期）、stable_slot、冻结policy_version、条件与物品清单。唯一资格不包含可变任务ID、题目ID、内容包版本和规则版本。TaskOccurrence映射已有资格，改计划或补做不得重新铸造。

日粮默认40营养点。N项必需任务以稳定slot排序，前N−1项分配floor(40/N)，最后一项取余；N不能为0，首版N≤3。一天两项各20，一项40。日建材wood=2、cloth=1在冻结必需集合全部完成后一次发放；周履约wood=4、cloth=2一次发放。重复自由练习、诊断、任意新建任务不新增基础资格。

无宠物时仍可获得家庭通用营养券，领养时按物种映射适合食物；首版领养需先于学习可简化此分支。食物适用种属在服务端item_definition中，孩子不能把猫狗食物用于兔类。食品库存单位明确为nutrient_point，界面按40点一餐呈现，不承诺现实动物医学热量。

RewardGrant是某资格成功发放的一次凭据；GrantItems不可变；InventoryLedger记录每个物品delta，InventoryBalance是同事务更新的快照。赠物、补偿与冲正另有source_type和actor，不伪造学习成果。

### 6.2 任务完成与发奖事务

```text
BEGIN;
  bind authenticated family/child context;
  lock child row -> learning_day -> task_occurrence;
  validate session lease/revision and frozen requirements;
  load server attempts/reviews, compute completion (ignore client score);
  if task already completed: return existing completion + receipt;
  mark task completed and persist effective evidence;
  lock eligible entitlement rows in stable ID order;
  for each newly satisfied entitlement:
    insert reward_grant with UNIQUE(entitlement_id);
    insert grant_items and inventory_ledger;
    insert/update inventory_balances atomically;
  update day/week fulfillment using frozen/revised authorized denominator;
  enqueue outbox events inside transaction;
  persist idempotent response;
COMMIT;
return receipt; animate after commit.
```

服务端完成判断、grant和余额属于同一事务。并发设备即使各自请求UUID不同，也被同一资格唯一约束挡住。不要先标任务完成再异步发粮而没有恢复机制；相册/统计可异步，核心物品不能等待外部模型。

所有会修改奖励/库存的命令首先锁同一个child行，之后以固定表顺序/ID升序锁资格与余额，减少死锁。数据库仍保留唯一键和余额非负CHECK。发现40P01/40001最多自动重试3次，重试保留同一幂等键；锁等待超时返回可重试，不转成答错。

### 6.3 请求幂等

写接口需要Idempotency-Key（UUID），服务端组合family、actor scope、operation和key建立记录，保存规范化request_hash。相同key同payload返回原HTTP状态和结果；相同key不同payload返回IDEMPOTENCY_PAYLOAD_CONFLICT；处理中返回202和查询位置。

幂等记录默认保留30天，但奖励资格、grant和消费事件的业务唯一键永久保留至家庭删除。不能用请求幂等TTL承担“一生只领奖一次”。过期重放命令通过source_event/business key仍受保护。

### 6.4 喂食与消费

孩子发送pet_id、item_id、requested_units、expected_revision，不能发送最终饱腹值。服务端materialize宠物后计算need=floor((10000−satiety_cp)/100)，consume=min(stock,requested,need)。consume=0时返回PET_FULL或ITEM_NOT_AVAILABLE，不扣库存。非主食上限、适用种属、每日零食次数和当前疾病限制独立检查。

事务顺序：锁child→pet/state→相关inventory→校验→写唯一PetEvent→扣库存ledger→更新余额和satiety_cp→写outbox/幂等结果→提交。实际吃不下的份额留库存。动画根据已提交event_id播放一次；关闭页面只跳过表现，不能撤销已发生消费。

制作装扮先检查全部材料余额、物种挂点和是否已拥有，再一次事务扣所有物品并增加装饰。预览和场景布局移动不扣费。首版不回售、不交易、不重复买同一非消耗装饰。场景布局保存使用expected_revision，冲突返回最新版供选择，不后写覆盖。

### 6.5 审计与对账

定期对账：balance=Σledger.delta；grant每个entitlement至多一个；ledger的grant/consumption来源可追；周奖次数和日粮额度符合策略；余额非负。差异进入ops告警，停止受影响消费，不能静默重置余额。

账本错误通过追加冲正项修复并引用原项。坏题或评分错误只修证据，不默认回收已发学习物品。家庭整体删除通过专门purge任务和受控角色执行，与日常不可修改账本权限分离；备份按保留期清理，不能宣称主库删除就立即清空旧备份。

## 7. 宠物生命、场景与情感逻辑

### 7.1 宠物状态与时间推进

Pet保存种属、昵称、性格、主宠标记和包版本；PetState保存satiety_cp、hydration_cp、energy_cp、mood_cp、health_cp、hygiene_cp（均0–10000）、成长日、关系里程碑、life_stage、care_mode、disease_state、scene_key、revision、last_evaluated_at和rules_version。不同维度并行，不把“开心的少年生病小狗在公园”编码成一个巨型枚举。

数据库快照与PetEvent互相校验，但首版不要求全面事件溯源。状态推进通过materialize(now)在读取或写命令时惰性执行；后台每天补充里程碑即可，不做逐秒扣饥饿任务。

采用固定5分钟步长的确定性积分，步长和余数存规则/时间字段；重复读取不多扣。每步先计算照护模式、低值边界和休息，再计算资源与情绪。正常陪伴日饱腹衰减总量上限3000cp；饮水可免费补足；active每分钟energy−10cp，resting且饱腹/水分充足每分钟energy＋20cp（上限10000）；具体为试运行参数，可版本化调整。

服务恢复时只补偿最后一次正常心跳之后的安全范围。连续缺席或低饱腹触发托管，托管段不继续不利演化；server_now小于last_evaluated_at时不逆向结算并告警。单次最多计算一个安全窗口，超出时间进入托管，不以长时间停机直接算死。

托管可由请假提前设置，或陪伴模式下satiety≤1000cp/连续24小时未活动触发；进入时照护员保障饱腹/水分最低安全值、暂停疾病恶化与增长，记录非学习照护事件，不发学习材料或伪造照顾日。返回后欢迎并由孩子恢复照护，必要水和托管不限于挑战窗口。

### 7.2 成长与关系

PetDailyRecord唯一pet＋learning_date。当天至少一项有效计划验证与一次成功照护形成growth_day，日上限1；提示后完成和人工确认可计，不把所有状态依赖考试满分。纯赠物、诊断或反复摸头不刷成长。幼年0–13日、少年14–41日、成年42日起，按冻结规则版本执行。

亲密以共同经历里程碑累积，缺席不清零；短期心情可变化，但不使用“你没学习我不爱你”台词。PetMemory使用受控fact_type＋source_event_id唯一，语言模型可改文案但不创造未发生的事实。删除原录音后记忆保留文字里程碑，回放入口显示已删除。

### 7.3 行为与动作调度

BehaviorController接收权威快照和已提交事件，管理四层：attention（眼神/头部朝向）、body（待机/走动/吃喝/睡眠）、expression（表情）、accessory（耳尾/围巾跟随）。动作强度与时长有上限，呼吸和眨眼可本地随机但用seed使重放可测。

优先级：安全暂停/页面隐藏→已确认照护剧情→主动点击回应→短情绪反馈→低频待机。进食动作可在安全点打断为完成姿态，不在网络重试时重复排入长队列；最多保留1个主要动作和1个可替换回应。相同event_id表现去重，重连时取状态而不是重播整天历史。

白名单动作look_at、walk_to、play_action、set_expression、speak_approved_line、equip_owned_item；参数校验stage bounds、duration≤10秒和已拥有装饰。行为控制不允许set_health、grant_food、unlock_window或die。

### 7.4 医院

疾病case状态healthy→mild→examined→recovering→resolved。首版事件仅在家长开启疾病剧情时触发，周冷却至少7天，答错不会随机生病。必要治疗立即开始；复习帮助推进康复互动，不作为紧急生命保障的唯一门槛。

HospitalCase关联pet、cause_event、eligible_scope策略与可复用task_id。进入医院先选择今天未完成的预排复习task，创建presentation=hospital的同一verification session；没有可抵扣任务时可以创建无奖励practice，不额外铸造粮食。复习来源为已接触scope中的薄弱/到期目标，不仅选过去成功题。

康复成功写care_event和case进度，学习证据与奖励仍走learning/rewards服务。服务不可用或两次求助后家长可启用care_assistance完成安全康复，不伪造独立能力证据。宠物医院不能调用另一个独立发奖接口。

### 7.5 公园、装扮与真实户外

公园采用固定热点和路径，点击对象可调用符合当前scope的微训练；自由探索无额外粮食。虚拟散步消耗精力并适量改善心情，每日次数受限，不能通过无限散步创造能量。真实户外记录由家长确认，仅形成关系/心情和相册，不默认采集GPS。

布局采用场景槽位＋有限拖动区域，保存item_id、slot_key、x/y、scale、layer；坐标归一化0–1，后端限制安全区，物品不得遮住宠物主要交互区。TV用槽位选择与方向键微调，提供撤销/重置和布置锁定。

### 7.6 真实生命模式的扩展点

首版life_mode只启用companion；realistic模式保留策略版本字段和feature flag，不启用未定数值。后续需要家长显式开启、展示周期与可暂停规则，健康危急有预警、确认与托管/急救出口。生命结束必须来自明确领域命令及家长确认，不由ASR、AI对白、后台长时间补算触发。

死亡保留档案和相册，不物理删除宠物；系统事故由审计和快照恢复。真实生命模式上线前必须另行完成参数、儿童体验和回滚规则验收，不能将预留状态视为已实现功能。

## 8. 自动素材与AI服务

### 8.1 PetDefinition与SceneManifest

PetDefinition包括definition_version、generator_version、seed、species、比例/颜色参数、parts、hierarchy、pivots、anchors、slots、hit_regions、动作clips、混合/打断规则、声音事件、LOD和runtime_capabilities。SceneManifest定义背景、前后景、可行走区域、热点、喂食/窝坐标与安全区。

参考图精灵路线增加frame_rects、frame_duration_ms、baseline、direction、逐帧挂点与遮挡；无稳定挂点的图集不能宣称支持任意换装。程序化路线支持明确部件层级，复杂大转身需要额外姿态，不仅整体左右翻转。

资产包保存manifest摘要、文件hash/MIME/尺寸、生成模型及参数、许可范围、构建工具版本、检查报告和兼容映射。首版建议单场景加载资源压缩后≤8MiB、解码纹理≤64MiB作为待真机校准预算；2048²RGBA单页约16MiB，不含mipmap与额外副本。

### 8.2 构建与发布

制作请求→规格校验→隔离生成→固定时点渲染→自动几何/时序检查→AI辅助视觉检查→局部重试→打包→能力预览→发布。构建环境只读模板、独立输出目录，无家庭数据和运行库凭据；执行生成的代码必须限制网络、路径、CPU/内存和时长。

检查部件缺失/裁切、透明边缘、接缝、脚掌接地、动作语义、围巾遮挡、连续点击中断和低配静态输出。单动作最多3次生成重试，超过预算进入failed_needs_decision，不能为了自动完成而绕过质量门槛。人工风格评审是选择结果，不能要求用户手工修图绑骨。

发布写入新package版本，所有文件校验后原子更新active指针；活动会话继续使用旧包直到安全切换，旧装饰ID映射到新slots。保留上一版和被历史/活跃会话引用的版本，GC只删除无引用且过保留期的产物。

### 8.3 模型网关

ModelGateway暴露generate_questions、review_questions、generate_dialogue、transcribe、assess_pronunciation和generate_asset意图，provider通过适配器实现。输出必须是受控schema；provider URL由管理员配置且防内网敏感地址访问，用户上传文档中的“指令”只当资料，不影响系统权限。

所有调用经过预算reserve→执行→settle/release，记录run_id、usage、成本估算与实际值、错误类别。每家庭默认同时1个内容生成任务，每调用60秒、整个job15分钟；网络/429/5xx最多3次指数退避并带随机抖动，结构错误允许1次修复，语义失败只重生失败项。超预算停止新调用，已有题库与已发物品不受影响。

宠物对白默认固定模板；AI对白P3每次最多2句、单轮不超过适龄长度、每日预算、时间截止检查。对话超时使用本地句库，不显示“系统提示/Token错误”给孩子。外部模型不获得完整孩子历史、真实身份或任意录音；家长明确开启需要传输的能力。

### 8.4 资产与内容的安全处理

SVG清理script、foreignObject、外部URL和事件属性，必要时栅格化；上传ZIP检查路径穿越、解压体积、文件数和压缩比；媒体MIME与实际解码结果一致；教材宏、脚本、主动HTML均不执行。来源文本进入LLM时用数据边界与明确证据ID，模型没有文件/网络/发奖工具权限。
