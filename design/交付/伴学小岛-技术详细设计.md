# 伴学小岛技术详细设计

## 1. 系统结构与技术决策

### 1.1 服务结构

系统采用模块化单体。一个Web应用提供儿童端、家长端和电视布局；一个API服务处理身份、内容、计划、学习、奖励和宠物；一个轻量任务进程执行可恢复的后台任务；PostgreSQL保存业务真值；媒体保存在持久化目录。文档解析、语音模型和素材构建为可选独立进程，不参与儿童作答的同步关键路径。

开发工程采用pnpm workspace。领域规则写成无网络、无界面的TypeScript纯函数；数据库事务、文件服务、模型调用和HTTP路由分别作为适配层。API与worker共享领域包，Web只共享公开契约、展示枚举和可复用校验代码，不导入私有答案、发奖算法或数据库凭据。

| 技术层 | 设计选择 | 使用方式 |
|---|---|---|
| 运行时 | Node.js 24 LTS、TypeScript | 应用与轻量worker同版本，镜像锁digest |
| Web | React 19、Vite、React Router | 一套业务路由，child/parent/tv三种布局 |
| 数据读取 | TanStack Query | 缓存服务端查询、失效刷新；不把缓存当余额真值 |
| 表单 | React Hook Form＋应用生成的校验器 | 复杂家长表单、错误定位；儿童端保持一题一动作 |
| 状态机 | XState稳定5.x | 会话与行为编排，快照带machine_version；不负责数据库幂等 |
| 图形 | PixiJS 8 WebGL | 用ref封装场景生命周期，逐帧不触发React重渲染；@pixi/react非必需 |
| 轻量回退 | DOM/SVG＋CSS/WAAPI | WebGL失败时仍可学习、喂食和显示静态宠物 |
| 后端 | Fastify 5＋TypeBox/JSON Schema＋Ajv 8 | 统一参数校验、公开/私有DTO、OpenAPI导出 |
| 数据访问 | PostgreSQL 16＋node-postgres＋Kysely | 显式事务、行锁与SQL约束；DDL迁移独立管理 |
| 文件 | 本机持久化目录＋内容摘要键 | API受控读取；未来可替换S3适配器 |
| 任务 | PostgreSQL任务表、SKIP LOCKED、租约 | 单家庭无需Redis/Kafka；并发与重试可配置 |
| 导入增强 | 独立Python/Docling worker | CLI/队列处理PDF/OCR，核心应用不携带大模型 |
| 部署 | Docker Compose、NAS反向代理 | amd64/arm64镜像，可信HTTPS，同源API与媒体 |
| 验证 | Vitest、Fastify inject、PostgreSQL集成测试、Playwright | 测试与业务风险对应，真实iPad/TV另行验收 |

依赖的精确patch版本在初始化工程时写入锁文件并通过兼容检查；框架主版本是设计约束，不复制预览版文档的API。首版不加入向量数据库、微服务、开放代码插件、完整LMS、实时三维或浏览器常驻语音大模型。

### 1.2 模块职责与依赖

| 模块 | 拥有的数据和命令 | 允许依赖 | 禁止行为 |
|---|---|---|---|
| identity | 家庭、账号、孩子、设备、会话 | audit、配置 | 前端提交family_id就授予访问 |
| curriculum | 原文、版本、节点、切片、目标、媒体映射 | media、identity | 修改已发布原文payload |
| authoring | 导入、AI候选题、质量报告、发布/撤回 | curriculum、jobs、model-gateway | 模型输出直接给孩子作为正式题 |
| planning | 周计划、修订、学习日、稳定任务与scope | curriculum、question-bank、identity | 改计划重置奖励资格 |
| learning | 接触声明、训练、挑战、作答、复核、证据 | planning、question-bank、media | 计时自动产生掌握；相信客户端正确率 |
| rewards | 资格、发放、库存、账本 | learning的确认结果、identity | 动画回调发奖；内容包自定奖励数 |
| pet-world | 宠物状态、照顾、成长、医院、场景、回忆 | rewards、learning、asset-registry | 自行判定题目或绕过账本扣库存 |
| asset-factory | 参数化角色、生成图集、动作与场景包 | 隔离构建器、质量工具 | 在儿童端执行生成的TS/Python |
| companion | TV配对、输入命令、录音伴侣 | identity、learning、sync | 手机和电视各自成为会话真值 |
| operations | 备份、健康、审计、后台任务与同步 | 所有模块的受控只读/管理接口 | 公开数据库管理端口或返回秘密 |

模块之间通过应用服务接口和版本化领域事件通信。核心学习完成、奖励、库存变更在一个数据库事务中完成；推送、统计、相册和外部模型使用事务outbox在提交后执行。所有“可选增强失败”不能回滚已经确认的学习奖励。

## 2. 业务标识、权限与全局约束

### 2.1 标识与数值

所有业务ID为应用生成UUID。教材/题目/宠物包另有稳定业务key和不可变版本号。API字段snake_case；领域代码可使用内部命名，但序列化只有一套映射。时间戳为UTC ISO8601，学习日期用date，家庭时区使用IANA标识，服务端计算后冻结到学习日。

库存使用bigint最小单位，JSON对可能超过安全整数的通用计数字段使用十进制字符串。首版营养1单位等于1饱腹点；宠物状态使用0–10000整数，100单位等于界面1点。比例、时长、成本必须声明单位，禁止将浮点金币写入账本。媒体时长用毫秒，文件大小字节，模型成本以微货币单位及currency保存。

| 规则ID | 必须成立的约束 |
|---|---|
| R-01 | 访问资源的family/child从认证会话与资源归属核验，不信任请求body声明 |
| R-02 | 计划引用确切的已发布内容版本与scope；题目主要源片段属于scope |
| R-03 | 已计划、接触声明、训练参与、验证证据、掌握趋势分别存储 |
| R-04 | 客观答案由服务端按固定规则判定；公开题目不携带标准答案 |
| R-05 | 本次同题提示后成功不算新的独立掌握证据；能力不能互相冒充 |
| R-06 | 每日/每周资格稳定，换内容版本、规则版本、任务ID或设备都不新增资格 |
| R-07 | 任务确认、奖励发放、库存账本和快照在同事务提交 |
| R-08 | 消费先通过数据库事务，再播放动作；跳过动作不改变业务结果 |
| R-09 | 家长次日复核归原学习日；复核权限不受儿童开始挑战窗口限制 |
| R-10 | AI、场景包与动画事件不能直接写奖励、健康、死亡或开放时段 |
| R-11 | 未识别、内容故障、媒体失败与网络失败不记知识错误 |
| R-12 | 已发布payload不可变，修订新建版本；退役状态可独立变化 |
| R-13 | 旧设备迟到提交和旧快照不覆盖新租约、新修订号 |
| R-14 | 断网可保存待同步证据，未确认库存不可消费 |
| R-15 | 默认陪伴模式安全托管；系统停机不触发不可逆生命后果 |
| R-16 | 自动素材构建可重建、可检测、可停止，不依赖隐藏手工资产 |
| R-17 | 客户端没有正确率、余额、时钟和宠物状态的最终决定权 |
| R-18 | 删除题目或修正错误不追扣孩子已经获得的学习物品 |

### 2.2 权限模型

账号只用于家长/管理员身份；孩子是家庭内的独立学习主体，儿童设备会话固定child_id。成年人通过家庭成员关系获得owner/parent/content_editor权限。owner可管理家庭和其他成人；parent可编排、复核和照护；content_editor可处理教材和候选题，发布可由owner/parent授权。首个家庭可一人兼任。

儿童入口通过家长授权设备或家长登录后切换获得受限会话，不要求孩子真实邮箱。家长入口必须重新验证成人身份或使用短时step-up授权；隐藏按钮或一道简单算术题不能保护管理接口。

| 资源/命令 | owner | parent | content_editor | child | TV伴侣 |
|---|---|---|---|---|---|
| 家庭与成人成员 | 管理 | 只读基础 | 无 | 无 | 无 |
| 孩子档案与时间策略 | 管理 | 管理 | 无 | 读自己的显示字段 | 仅本配对孩子 |
| 教材草稿/候选题 | 管理 | 管理 | 管理授权库 | 仅已发布学习范围 | 仅当前题 |
| 内容发布与撤回 | 可 | 可 | 需显式权限 | 无 | 无 |
| 周计划与请假 | 可 | 可 | 无 | 只读/受限选择顺序 | 只读当前 |
| 口语与过期证据复核 | 可 | 可 | 无 | 录制自己的音频 | 仅当前授权录音上传 |
| 学习提交 | 可诊断不发孩子奖 | 同左 | 无 | 本人任务 | 指定题授权命令 |
| 发奖/赠物/冲正 | 系统或管理命令 | 受控赠物 | 无 | 无 | 无 |
| 喂食与装扮 | 可 | 可 | 无 | 自己拥有的物品 | 白名单命令 |
| 原始录音、导出、删除 | 可 | 按家庭设置 | 无 | 仅本人当前回放 | 无列表权限 |

数据库RLS作为第二道家庭隔离。每次事务通过SET LOCAL绑定经过认证的family_id，不用连接级永久SET；连接池复用不能泄漏上下文。应用角色无BYPASSRLS，表owner迁移角色与运行角色分开；worker逐任务按family执行。私有答案schema只向学习判分服务的数据库角色开放，不向Web资源服务开放。

### 2.3 安全会话

家长使用Argon2id密码摘要，参数在目标NAS校准；会话采用高熵随机opaque token，数据库只保存摘要，HttpOnly/Secure/SameSite=Lax Cookie，默认7日滑动有效、30日绝对上限。管理敏感操作要求近期认证；同源Origin检查＋CSRF token保护写操作。口语录音授权与对外模型授权分开。

配对码有效期5分钟、一次性、短码限次尝试，二维码可携带更高熵的随机挑战；创建TV会话后仍由家长设备确认家庭与孩子。服务端保存token摘要，配对设备可撤销，撤销后租约和WebSocket一并失效。首次部署无固定默认密码，用一次性引导凭据创建owner后关闭初始化入口。

### 2.4 错误和可重试语义

所有HTTP响应带request_id和server_time。错误对象包含code、message、retryable和可选field_errors；错误文本不回传SQL、密钥、完整原文或模型原始异常。校验失败400，未登录401，无权403，隐藏跨家庭资源时404，修订/租约/幂等冲突409，窗口或业务前提不满足422，频率/额度429，临时能力故障503。

客户端只对网络、408/429/5xx做有上限退避；409先拉取最新状态或按幂等键查询，不能盲目重新生成请求ID。系统错误不被转换为孩子答错。

## 3. 功能规格与交付阶段

P1为最小可用家庭闭环，P2补全宠物选择、生活场景与内容运维，P3加入电视壳、自动语音与智能陪伴，P4为真实生命等选择性扩展。接口可先预留P2/P3结构，未实现功能用feature flag明确不可用，不暴露假按钮。

功能清单附件每行包含功能ID、所属模块、功能、阶段、角色、输入/前提、输出/规则、验收点和主要operation_id。功能与接口不是一一对应：一个功能可由多个接口协作，一个查询可以服务多个页面。

首版必须覆盖身份、教材内容、导入与AI题库、周计划、外部学习声明、训练/验证、录音确认、奖励/背包、宠物喂养、自动素材生产和部署恢复。不能只实现漂亮小家，将教材和题目生产推到后续。

### 3.2 前端组件契约

QuestionRunner只接收公开题目DTO和当前会话模式，通过registry按question_type选择执行器。执行器必须提供render、validate_response_shape、serialize_draft、restore_draft、focus_first和dispose；不存在gradeCorrect客户端权威接口。

AudioCoordinator统一调度指令、题目音频、宠物声、TTS与录音。题目音频优先；录音前停止所有扬声器音源并等待短缓冲，结束后不自动播放答案。用户首次操作激活AudioContext，play失败显示重播入口。

PetStage接收只读PetSnapshot与已提交PetEvent，输出选择意图，如feed_requested或inspect_item；没有balance写入口。BehaviorController控制注意力、身体、面部与附属物多层动作；RendererPort有Pixi和静态实现。组件卸载取消ticker、监听与资源引用。

家长端复杂表格可筛选与批量处理，儿童端一屏一个主要行动。所有拖动同时支持点击/键盘替代，TV从同一题目使用不同布局，不把精细触摸当必需。儿童题意指令可朗读，目标词的朗读权限由所测能力决定。


## 4. 教材与AI题目生产

### 4.1 内容系统与运行边界

内容系统负责真实教材入库、版本对齐、语义切片、目标标注、题目生产、质量检查、发布与修订。儿童端负责在已发布内容中按计划训练和验证，宠物场景只提出需要复习的目标与呈现意图。素材生产采用免费开源工具和AI脚本，不要求人工修图、绑骨或调整动作；教育内容允许不确定项由家长审核，不能因此承诺AI零误题。

制作环境与日常运行分离。重型OCR、音频转写、图像生成和语言模型调用在可选worker执行；NAS核心应用保存教材、题库、证据和奖励，不因生成服务离线而停课。首版不依赖向量数据库或完整LMS，先以UUID、教材版本和明确范围筛选内容，再按需要补上下文。

所有业务JSON使用snake_case，标识实体与媒体的字段使用UUID。Schema自身保留Draft 2020-12标准关键字。family_id由认证与服务端资源归属注入，不出现在模型输入输出中。模型不得生成外部URL、任意脚本或评分代码；媒体仅能引用预注册asset UUID。题目候选是私有生产对象，儿童公开题目是服务端白名单投影，两者不是同一个接口。

### 4.2 通用教材树

curriculum_series表示教材系列，curriculum_editions表示明确版本，content_versions表示一次不可变内容快照。content_nodes通过parent_id和ordinal构成树，节点类型使用series_group、level、volume、book、unit、lesson、page、passage、dialogue、utterance等受控枚举。展示名称由教材适配器决定，业务不能通过中文标题或“第几课”判断身份。

RAZ映射为版本→级别→具体绘本→页→句段；同名绘本在不同版本不自动合并。新概念映射为经典/青少等版本→册→单元/课次→对话/段落→说话人轮次。家中点读版册序、APP课号与内部节点通过external_locator保存多条对应关系，不要求外部平台提供接口。新增同结构教材只增加适配配置和数据；新交互能力才增加题型执行器。

不将RAZ级别直接等同CEFR，不凭年龄决定识字能力。词汇以vocabulary_senses区分词义、词形、词性和语境，bank的河岸和银行不合并；原句可关联多个词义和learning_objectives。objective_id指具体能力目标，例如“在本绘本语境下看词识别bag”，不是单纯的单词字符串。skill锁定listening、word_recognition、oral_reading、sentence_comprehension、spelling、oral_expression；modality锁定audio、visual、text、speech。

父词条关系用于释义、例句检索和内容编排。例如dogs关联dog、has关联have，保留实际出现词形和语法功能；短语“look at”作为一个多词单位，不能因为空格就失去整体意义。一个词形可关联多个候选父词义，但进入具体教材目标前必须确认当前语境。父词条掌握不自动传给全部变形，朗读证据也不通过父关系扩散到未读过的短语。

新增教材的适配器必须声明支持的节点种类、页码基准、外部定位规则、语言变体和音频对齐方式，输出统一中间结构。适配器不能依靠一串教材名称执行隐藏下载；每次取材都要登记输入及权利。初次适配先对一本或一课走完整回归，确认树顺序、原文、媒体、切片和目标后再批量处理同系列。

同一句子出现在两本书中可以共享语义检索标签，但源片段身份仍各自独立；孩子选择其中一本时题目追溯到那一本。跨版本迁移需要明确对应关系和差异报告，不能只凭文字相同把整个已学历史平移。词义与目标版本改变时，历史证据仍指原目标版本，新snapshot按兼容规则决定是否可复用。

### 4.3 原文来源与权利

数字教材原文必须来自上传的真实文件、授权结构化包或可核对的资料。LLM可提取、整理和提示差异，不能凭记忆生成“某本RAZ原文”“新概念第某课原文”。原始文件、提取文本、显示规范化文本分开保存。保留not、标点、引号、说话人和顺序，模型建议的改写不得覆盖原文。

来源分publisher_original、family_authored、ai_authored。AI原创短文可以入库，但归为自编扩展，不能冒充出版社材料。扫描/OCR得到的文字必须可回查页图与位置；转写草稿必须可回听音频片段。合成音频标记tts_reference，不能声称它就是教材配套录音。

每份源文件与衍生媒体关联权利记录，包括来源、许可文本/凭据引用、家庭使用范围、再分发范围、是否允许向外部模型发送、到期与撤回情况。家庭购买纸书或订阅不自动等于取得再分发权；模型和词典代码开源也不自动授权其附带内容。未明确允许云处理时只本地解析或待家长决定，不能为了完成出题绕过该限制。

### 4.4 导入格式与状态机

P1支持CSV/XLSX模板、UTF-8文本及受信结构化包。模板列至少含edition_key、node_path、external_locator、page_label、original_text、language和媒体引用；家长通过列映射预览操作，不编辑JSON。PDF/EPUB/DOCX、扫描图和字幕由可选worker扩展，解析器接口统一为“节点候选、原文候选、定位、媒体引用、问题列表”。Docling等解析工具只提供提取能力，不证明绘本语义与阅读顺序正确。

import_jobs状态为received→validating→parsing→aligning→slicing→checking→review_required/ready→published。failed、cancelled独立记录，不能用一个failed覆盖已完成阶段。job保存输入摘要、adapter_version、parser_version、stage、checkpoint、attempt_count、错误码和产物引用；worker重启从最后完整checkpoint继续。状态变更使用修订号，旧worker提交不得覆盖新尝试。

文件接收先检验实际MIME、扩展名、大小、页数和压缩展开预算，再进入只读暂存。全局分类门槛为文档50MiB、ZIP100MiB、解压合计500MiB、单张图片与单条录音各10MiB、单任务最多500页和2000文件；均为可配置资源门槛而非性能承诺。解压禁止路径穿越、符号链接和嵌套压缩炸弹；文档宏、外链、SVG主动内容均不执行。解析超时只使当前任务失败，不阻塞儿童接口。

### 4.5 重复、增量与失败恢复

先用源文件SHA-256识别完全重复，再用教材版本、外部定位和原文摘要识别结构重复。重复导入返回既有job/内容版本，不创建第二套课次；标题相同而文件不同进入差异预览，不能按名字覆盖。一次导入至少展示新增节点、未变节点、修订节点、删除候选、未识别内容和缺媒体项。

同一版本修订生成新的content_version及源片段UUID，保留supersedes映射。没有变化的内容可以复用不可变媒体和权利记录，不能将旧片段ID指向新原文。增量重生成只针对受影响片段、目标和题目；未变内容继续运行。

解析或生成阶段写入暂存区，整个单元的结构与引用校验通过才进入ready。允许按绘本/课次单独发布，失败页保留问题标记，不因部分失败丢弃已完成产物。取消任务不删除已发布版本。失败重试沿用相同输入与阶段幂等键；修订输入产生新任务，不能复用旧成功标记。未引用暂存媒体按保留期清理，活跃会话和待审核录音不被当作孤儿删除。

### 4.6 上下文片与原子片

source_slices存储kind为context、sentence、word；概念上context为上下文片，sentence/word均为原子片。对话话轮按sentence节点并保留speaker，短语按word片保留完整target_text，不额外扩数据库枚举。内容包和OpenAPI均采用node_id、kind、normalized_text；落库时kind映射slice_kind，其他字段直接或按媒体绑定表转换，禁止把API字段名直接当数据库列名。导入任务API的status、stage、checkpoint与数据库import_jobs和background_jobs字段通过显式映射转换。

所有选项、词块、空位、匹配端点和candidate_slots均使用UUID；模型不生成实体身份，服务端预分配并校验。

context保存完整页段、连贯对话或图文场景；原子片保存句子、话轮、词或短语。原子片通过slice_contexts中relation_kind=parent_context表达父上下文，不另存parent_slice_id。指代句“It is blue.”需要前句对象，问句及答句不被机械字数截断。固定token窗口仅用于分批传输，不决定教材语义边界。

source-slice契约中的id、content_version_id、node_id、source_media_id均由服务端产生或读取。original_text是提取后的忠实文本，normalized_text只做经规则允许的排版规范化；source_hash为original_text按UTF-8编码的SHA-256，不能用图像文件hash替代。文件摘要另存在媒体登记。文本范围采用Unicode码点、零起始、end exclusive，不能混用UTF-16索引。

context_slice_ids仅引用同家庭同content_version的真实片段。禁止self引用和循环；上下文可包含未被选作测试目标的句子，但不得暗中考其中新目标。目标片用于scope判断，上下文片用于理解，两者必须分别传递。片段过大时保留完整父上下文，出题批次只带足以解释本题的子范围和明确源ID。

### 4.7 页图、音频和多模态绑定

media_bindings统一登记image和audio。图片绑定asset_id、用途以及归一化region，region用x、y、width、height表达，均在0到1且不能超出页界。页图只负责原文对照；题目选项图片优先使用可清楚区分的独立素材，避免整页复杂图导致多解。

音频绑定asset_id、start_ms、end_ms、transcript与来源角色。起止必须递增且落在登记时长内；文字与音频逐片对齐，省略、重复和说话人差异进入质量问题。录音原声、TTS示范与指令语音分开。音频文件可复用，切片通过时间范围引用，不必物理切出大量副本。

出题前注册可用素材UUID、类型、摘要、语言、语义标签和已检查状态。模型可选择这些UUID，但不能填HTTP地址或用猜测路径创建素材。需要新图片/音频时先发生产任务，完成权利与质量检查、注册后再重试出题。图像语义识别和ASR只能辅助；低龄声音、短单词、颜色/数量歧义要保留待确认路径。

### 4.8 学习目标与允许范围

每个目标关联具体片段、词义、skill和modality。一个目标可以在多个教材中复现，但其定义与证据维度稳定。看词选图主要测word_recognition/text，听词选图测listening/audio，朗读测oral_reading/speech；图片选词不能自动升级为拼写或朗读证据。

计划scope固定content_version_id、目标源片段UUID与objective_ids。复习scope来自孩子已接触内容及目标适配结果；未学词不可成为题干理解前提。干扰项可来自已学词集合或事先批准的基础词，不因为它们与目标“相似”就自动允许。词义相同也不能擅自引入复杂句法。

scope解析先查精确ID与版本，再补上下文闭包。生成和组题不得用向量相似度替代这些约束。目标缺少媒体或适用题型时返回coverage_gap，让家长缩小范围或等待补题，不能临时添加超纲题满足题数。

### 4.9 AI生成蓝图

generation-blueprint由服务端组装，包含id、phase、content_version_id、source_slice_ids、context_slice_ids、source_snapshots、objectives、registered_assets、allowed_vocabulary、learner_capabilities、candidate_slots、template_version、prompt_version和quality_policy_id。不包含family_id、孩子姓名、完整家庭历史和提供商密钥。

source_snapshots按真实输入UUID包含原文与摘要；candidate_slots预分配候选id、题型、目标、能力、范围和难度。模型只回显这些id，不创造新的实体身份。服务端记录generation_inputs，确保审计可重现当时看到的资料。蓝图与最终题目都带版本，不把当前源文替换进历史生成记录。

蓝图中的learner_capabilities只描述can_read_instructions、can_spell、supports_touch、supports_dpad、supports_recording等必要能力，不根据年龄猜测。P1口语任务没有录音能力时允许家长现场确认，不能改成选择题后仍标口语通过。目标时长与每批数量有限制，默认每批不超过16题，避免一次生成过大而无法局部修复。

### 4.10 题型范围和呈现契约

P1固定四类：audio_to_picture、word_to_picture、picture_to_word、oral_reading；前三类服务端客观判定，oral_reading使用人工确认。P2增加sentence_choice、cloze_choice、cloze_text、matching、word_order、reading_choice、retell。P2题型在P1蓝图中必须被拒绝，不能因为候选schema包含它就绕过功能阶段。

public_payload按question_type使用严格分支，操作指令独立放instruction_text。听词选图包含audio_asset_id与图片选项，不带音频转写；看词选图的目标词放顶层prompt_text，载荷只放图片选项；看图选词含image_asset_id与文字选项。oral_reading含target_text和录音上限，目标文字是要读的内容，不是“隐藏答案”。选项、词块、空位的id均为UUID，客户端提交id而不以文字下标当身份。运行服务将instruction_text投影为PublicQuestion.instruction，将prompt_text放入公开载荷的共同题干字段；provider候选原始对象不直接发给孩子。

P2阅读与句子选择保留必要刺激材料；填空选择和手输严格区分，matching支持先点左项再点右项，word_order保留独立词块。公开词块不携带原顺序索引。retell提供提示与可选源图/源文，按rubric人工确认；不能仅靠关键词出现即声称完整口头表达正确。

### 4.11 模型输出与私有答案

question-candidate包含id、blueprint_id、question_family_key、question_type、phase、source_slice_ids、context_slice_ids、objective_ids、skill、modality、difficulty、estimated_seconds、presentation_kind、prompt_text、instruction_text、requires_microphone、requires_typing、public_payload、answer_spec、explanation、quality_risks、source_quotes。每候选恰有一个主objective_id，列表形状用于与API一致，蓝图可以包含多个目标。unknown字段拒绝，媒体使用注册UUID，引用原句需给出slice_id、source_role、quote和码点区间。

question_family_key是候选分组建议，不是数据库UUID。服务端依据目标、源片、变换模板与答案语义形成规范家族指纹并分配question_families.id；同源同题换序、换文案不会成为新家族。模型填入family_id或擅自指定question_family_id均拒绝。家族归并可由管理员修正并保留映射。

answer_spec按类型区分single_choice、text、matching、sequence和manual_review。客观答案引用公开选项ID，允许答案集合、文本规范化与多种词序均显式列出。explanation和answer_spec仅存private server，验证题API不得返回，provider response也不得直接转发儿童端。训练需要解释时经单独投影与时机策略返回；验证提交后只给本次允许反馈，不发送整个题库答案。

### 4.12 多层质量检查

第一层使用Draft2020-12 Schema检查字段、长度、枚举和分支，不把结构正确称为题目正确。第二层领域lint检查UUID归属、版本、scope、目标、媒体类型、源引文、答案引用、题型与能力映射、重复选项、音频范围与阶段。全部硬规则通过后才调用较昂贵语义复核。

第三层独立解题：复核调用只看到源文、必要媒体、题干与公开选项，不看生成答案，先输出答案或“无法唯一确定”，再由服务端比较。可用不同提示/不同模型降低同源偏差，但两模型一致不是事实无误的证明。判定为多解、上下文不足、媒体歧义时进入review_required或重生成，不通过多数投票强行发布。

第四层运行预览执行正确、错误、未答、重复提交、恢复和输入替代样例。题型控件需要在iPad、电视能力档中分别检查；标准例验证评分器与目标契约，语义例验证题目不超范围。失败记录检查器版本、错误码、定位和修复建议，禁止只保存一个综合分数。

### 4.13 阈值与分级发布

硬门槛零容忍：越scope、假UUID、引文不符、未注册媒体、错误类型答案、非法阶段、源码缺失或权利禁止处理，均blocked。LLM自报confidence不能抵消这些问题。OCR工具的置信分数不是校准概率，不能跨引擎采用“0.9就自动正确”。

G0为源文已核对、确定性模板、三种P1客观题、媒体通过检查且独立解题唯一一致。家长启用自动发布策略后，G0可进入ready，服务端再按发布策略进入published。G1包括原文可信但变式较大、语义复核意见需判断、疑似多解或媒体边界，必须review_required。G2为开放口语、retell、OCR未核对或复杂阅读，首版需要审核与运行人工判定。blocked只能修复后重新检查，不允许点“忽略全部”批量跳过。

初始重复检测可采用“同目标＋同源片＋规范题干相同”确定归并，再用文本相似度作为提示，建议相似度≥0.9触发家族审查而非自动认定新题。阈值只对具体规范化方法生效，随标准样本校准并版本化；发布质量不用未经实测的整体百分比宣传。

### 4.14 文本答案和歧义处理

文本答案按任务选择NFC规范化、首尾空白、连续空格、大小写和末尾标点处理。拼写目标默认精确保留拼写，不接受把错误词“智能纠正”后判对；非拼写理解题可接受明确允许的等价形式。a/an、单复数、缩写、数字写法和英美拼写差异逐题定义，不能全局忽略。

cloze_text若语境允许多个答案，使用accepted_texts集合或改为cloze_choice；不要用任意正则和模型临场评判代替答案规则。word_order保存允许词块序列，存在多个语法正确顺序时全部声明或换题。matching必须明确一对一还是可复用；本阶段契约限定一对一，避免执行器猜测。

图片选项不同ID却同一图、同义词或都符合目标时拒绝。颜色题图片包含多种显著颜色、数量题画面对象遮挡、方位图镜像造成歧义都需重新生成或换题型。指令音频与目标音频分离，阅读目标不能被自动播报泄露。无障碍替代改变被测能力时标注accommodation，不能记录为原能力独立通过。

规范化仍不足以证明理解。评分器是无网络、无数据库写入的纯函数，先验证提交形状和长度，再按题目冻结的answer_spec计算。正确、提示后正确、轻微差异、需再试、未识别分开返回；是否发奖由任务完成服务根据证据判断，评分器不能修改背包。

词块排序除比对允许序列，还检查提交词块UUID的多重集与题目一致，避免少用一个词或重复使用同一块。原句里两次出现the必须是两个独立词块；公开词块只保留无序UUID，不附带原序号。匹配题提交全部左、右UUID关系，服务端校验双射后逐对判定，不接受客户端声称“错误次数为零”作为答案。

干扰项优先在本范围、同单元和同词性中选择，排除同文本、同义、包含关系和事先标注的不可对比项。例如“dog”对“animal”可能都是同一图片的正确描述，不能只因词不一样就作错误选项。类别与成员关系需要标签和语义检查，不靠翻译字符串完全相同来判断。同音词听写缺语境时换成短句，不把合理听辨差异当作拼写错误。

单空从原句完整词/词组边界定位，保留出现序号；多处同词却没有明确选定位置时不自动挖空。重构后的前缀、答案、后缀必须能还原被测原句，标点和空格由渲染器处理，不在字体中绘制下划线作为唯一空位。多空扩展后按gap UUID维护答案和提示，每空反馈可解释，整题通过策略明确为全部必需空或另行声明，不能平均分掩盖关键目标。

### 4.15 训练曝光与验证独立性

每次展示记录question_version_id、question_family_id、mode、answer_revealed、hint_level、played_assets和shown_at。source exposure与question exposure分别保存，看到整段教材原文不等于看过验证答案，看到某题解释则明确污染该家族的近期独立验证。

训练允许提示、重听、解释和反复练，结果记practice。验证优先同范围未暴露答案的家族或经审核的实质变式；只换选项顺序、宠物背景、题号和同义指令不构成独立证据。同一家族提示后正确记assisted，不为了发奖伪造independent。

独立复习证据需跨预定间隔且能力一致；当日连续刷对不能代替隔日回忆。题库不足时可完成帮助下验证并保留状态，或缩短本次题单并标待补目标，不能扩大范围凑题。学习奖励按计划规则结算，证据独立性不被宠物经济反向篡改。

### 4.16 已学声明、证据与历史初始化

study_exposures由孩子确认外部实际页句、家长声明、历史导入或授权平台记录形成，来源为self_report、parent、historical、authorized_external。exposure_slices保存确切集合。计划到期、计时结束、打开页面都不能自动产生掌握。孩子只学完部分范围时直接勾选实际片段，剩余保持待学，无需重新录入教材。

learning_evidence由实际attempt和objective形成，包含skill、modality、assistance、result、assessment_source和发生时间，采用业务证据键去重。训练、独立验证、提示后变式、家长确认、未识别分别记录；某词听辨通过而朗读待确认可以并存。掌握是可重算snapshot，不改写原尝试。

历史已学书课可批量初始化exposure，不补发过去奖励；可选少量诊断建立当前证据。医院从已接触且适合的薄弱目标选题，而不是只抽过去答对题。家长更正已学声明保留审计，不能悄悄删除已有attempt；授权外部成绩只证明其明确覆盖的能力，截图和OCR只作待确认材料。

### 4.17 挑战组题与缺题策略

组题输入是冻结的计划scope、实际exposure、必需目标、能力配额、设备条件、剩余时长及已暴露题目。查询只选published且未retired的兼容question_versions，再检查来源、媒体和版本。输出题单固定题目版本、顺序随机种子、目标槽位与评分规则，恢复会话不重新抽取。

generation_blueprint用于生产新候选，challenge blueprint用于从库组题，两者职责不同。医院、公园和家中场景传相同objective_ids和允许源片，只改变presentation_intent。场景不得直接调用LLM生成未审题、改标准答案或发材料。

缺题顺序为：同目标合格变式→降低非目标操作负担→已批准等价题型→家长帮助/暂停目标。听力点选不能填补朗读目标，未识别不能当知识错误。已发布计划因坏题退役出现缺口时转content_blocked，提供替代或复核，不判孩子失败；外部APP已完成测试时可缩短抽样，避免重复整套测验。

### 4.18 版本修订与传播

content_versions、source_slices和已发布question_versions不可变。词句修订新建版本，媒体替换新建资产，发布关系由content_releases和release_questions固化。修订传播先生成依赖图：源片→目标→候选/题目→未开始计划→活跃题单→历史证据。未变内容不全库重生成。

retired只停止新抽题，不删除历史快照。一般文案修订可让活跃会话继续原版本；答案错误、权利撤回或危险素材应阻止受影响未答项，标记需要替换或人工确认。已经作答的题保留当时内容和修正记录，证据可追加失效/纠正说明，不追扣已获得的食物和装饰。

发布在事务中核验全部资源与质量报告，切换release指针，失败保留旧版。消息通知使用outbox保证可重试，不能依赖模型回调完成发布。内容回滚不回滚奖励账本；回滚后的新计划读取前一兼容release，历史仍指原question_version。

### 4.19 成本、重试与模型适配

模型调用通过统一provider adapter，业务只传结构化蓝图与响应schema，不绑定某一收费平台。支持本地开源模型或家长配置服务，但模型权重和生成结果权利分别记录。每次调用保存model、prompt/template版本、source_hash、输入输出计量、时长、终止原因和成本估算，不保存API密钥。

生成缓存键包括源片摘要、目标、题型、模板、策略和模型版本；不同家庭共享是否允许取决于教材权利，默认不跨家庭缓存私有内容。批次中只修复失败候选；schema失败最多重试两次、语义失败最多重生成两次为初始建议，达到上限进入待确认，不能无限烧算力。

超时、限流、上下文过长和格式截断使用不同错误码。幂等键包含generation_run、slot和attempt，重复回调只登记一次产物；迟到结果保留诊断但不覆盖已选版本。源文改变立即取消受影响待发布候选。模型不可用时继续使用已发布题库，前台仅显示“新题准备中”。

### 4.20 内容工作台与运维

工作台提供教材树、真实内容预览、原图/原文对照、媒体回放、导入队列、差异确认、切片上下文、目标覆盖、候选题与质量报告、发布/撤回、反馈收件箱和生成预算。家长可选择“只看待确认项”，不承担逐个写题；模板题按策略自动检查，风险项明确解释原因。

家庭管理员可兼任导入和发布角色；共享资料时按角色分离，不仅前端隐藏按钮。批量操作先预览受影响书课、题目和未开始计划，记录actor与原因。导出时按权利范围剔除不可分发原图/音频；删除家庭资料按保留策略处理备份和派生缓存。

监控重点是导入失败阶段、题库覆盖缺口、自动检查阻断、家长推翻、题目撤回、语音未识别、生成成本与儿童实际验证用时。小家庭不足以估计可靠题目区分度或英语成绩提升，不用高答对率证明题目质量。保留一组标准正反例，更新模型和模板前运行回归。

运行预览和自动检查后的审核视图展示原图位置、原句、候选题、独立解题结果与具体风险，不要求家长重新阅读整本资料。可批量批准同模板且同风险级别的题，但必须先显示样例、数量和覆盖范围；开放题、多解或源文不确定项不能混入低风险批次。审核选“需修改”时保留原因，生成器只接收必要修复信息，不让模型自行改写教材解除问题。

问题收件箱以question_version_id和错误类型聚合，区分教材原文错误、题干错误、答案规则错误、媒体问题、操作问题与语音技术失败。同一题多个报告可归并，但不丢家庭隔离和报告者隐私。修复后用原报告构成回归样本，再检查相同模板生成的其他题；发现模板性错误时批量阻止相关新抽题，不只修被投诉的一条。

发布前覆盖预览以“必需目标是否具备合格题”为基础，不以候选数量充数。同一目标十个换序题不能算十个独立变式。仪表板显示可用家族、待审核家族、适用设备与缺失媒体；缺题原因能定位到目标和源片段。模型成功率低时提示缩小批次、换模板或延后生成，不把反复失败隐藏成一直加载。

### 4.21 契约文件与验收

内容目录提供三份自包含Draft2020-12 schema：source-slice.schema.json、generation-blueprint.schema.json和question-candidate.schema.json。每份均有有效样例，候选样例覆盖P1四类和P2七类；轻量CLI仅调用本机jsonschema，不访问网络、不调用LLM。示例使用自编“This is my bag. It is blue.”及登记的UUID，不宣称对应真实教材页。

Schema负责结构，CLI补范围、引用、引文、答案与媒体领域检查。生产库仍需验证家庭归属、发布冻结、数据库外键和事务，本机样例通过不替代真实教材审核。验收包括：伪造source ID、未知媒体、family_id注入、答案不在选项、P1混入P2题型、引文不匹配和公开payload夹带解释均被拒绝。

正式开发前用一周真实教材完成导入、版本对齐、切片、蓝图、候选题、风险分级和受控发布；至少验证一次错误源文修订传播、一次缺题恢复、一次已看答案后的证据降级、一次历史exposure初始化不发奖。只有内容生产与儿童运行两条链路都成立，才扩充整套教材和更多场景。


## 5. 周计划、学习日与时间策略

### 5.1 周计划状态与编译

WeeklyPlan为一个孩子某家庭周的稳定容器；PlanRevision保存草稿与发布内容，修改后新建修订。状态draft→validating→validated→published；校验失败回draft并附问题；旧发布修订转superseded，不删除已执行任务。

编译输入包括教材版本/片段、任务目标、能力前提、日期、开放时段、训练/验证蓝图、每日预算和奖励策略版本。编译输出LearningDay、TaskOccurrence、TaskScope、TaskRequirement和RewardEntitlement。发布是数据库事务，不在事务中调用LLM或解析文件。

| 编译检查 | 阻断条件 | 可修复方式 |
|---|---|---|
| 教材可用 | 源版本未发布/已退役、源片段缺失 | 更新未开始范围、选择合法版本 |
| 范围闭合 | 目标源不在scope；上下文不足 | 增加上下文只读片，不自动扩测量范围 |
| 题库覆盖 | 必需能力无合格主项或补救项 | 后台补题、人工确认策略或减少目标 |
| 认知前提 | 不会拼写却必需手输；阅读能力不适合 | 换题型但保持被测能力，或改计划 |
| 设备 | 必需口语无麦克风且无人工路径 | 伴侣录音、家长确认或改目标 |
| 时间 | 预计验证＋必要收尾超过可用窗口 | 减少任务/目标，调整窗口 |
| 奖励 | 分配日粮超出40；同日期多个不兼容日资格 | 固定日预算并复用原资格 |
| 计划冲突 | 相同孩子/日期已有进行中范围被替换 | 保护已开始，新增下一日或新修订 |

首版只允许一周一个有效发布容器；重复发布相同revision返回原结果。发布所需题库snapshot和coverage报告有版本/hash，校验后发布时再次检查hash与退役标记，避免校验通过后题目已失效。

### 5.2 修改、请假和补做

未开始的任务可在新修订替换范围与时段；stable_slot继续沿用，不因新task UUID或内容版本变化重新分配奖励。已经开始的task保留原scope与要求；允许暂停后由家长显式选择结束原实例并安排后续，不覆盖作答快照。

当日已有成功资格不得再通过降低要求产生第二次奖励。新增任务默认optional且不增加日粮/建材额度；若未来任务从必需改为可选，显示对周目标影响，保留变更审计。一天部分必需任务完成可按冻结份额先获得对应食物；日建材仅在当日冻结必需集合完成后一次发放。

请假只对未开始未来学习日设置excused。周目标初始D为非休息计划日数，target=ceil(0.8×D)，D=5时4；D=0不能领奖。批准请假后的未来D可调整，目标修订保留原因；已获得周奖励不回收，不再发第二份。补做关联原learning_day_id和稳定资格，记录completed_at真实时间与makeup授权，不在补做当天复制一份。

任务因坏题无法验证使用blocked_content，不算孩子未完成。系统可以保留周履约评估为待处理，家长选择替代题或免除此目标；免除记录不生成能力掌握证据。

### 5.3 时段判定

每个LearningDay冻结family_timezone与本地日期；发布时将本地时间映射为UTC open_at、last_start_at、close_at和finish_deadline。默认19:00开放、19:25最晚开始、19:30常规结束、19:35收尾，实际日期与时区必须一起保存。P1不跨午夜设置窗口；旅行时区变更下一学习日生效。

```text
can_start(now, day, task):
  authenticated child owns task
  day not excused; task not completed/cancelled/blocked
  open_at <= server_now < last_start_at
  estimated_min_round_ms <= finish_deadline - now
  capability and published_question_coverage satisfied
can_submit(now, session):
  matching lease_epoch and active task revision
  now <= finish_deadline OR valid parent makeup/review authorization
```

last_start_at为排他的截止点，避免等于19:25时两端理解不同；页面显示按同一服务端参数。已开始录音在close_at后可收尾至finish_deadline；达到finish_deadline只保存草稿/录音，不强行声称失败。迟交进入late_review，不自动标准时，家长可确认学习完成但late标记保留。

静态查看、挑战开始、必要照护、自由装扮分别授权。默认自由互动预算180秒，在已确认日任务后解锁；必要饮水/托管不因预算耗尽被锁。客户端计时仅做展示，服务端心跳聚合日互动预算，无法替代系统级屏幕使用时间。

## 6. 学习会话、题单与判分

### 6.1 外部学习与接触声明

孩子进入任务可查看外部书/课位置，点击去学习只记录开始事件。回到应用选择实际学过的scope子集，服务端检查不得超过计划范围，写StudyExposure与ExposureSlice。未确认部分留待学；不自动减少必需任务条件，不对尚未接触范围启动强制验证。

历史学习导入由家长勾选书课，保存source=parent_import、declared_at和日期精度（known_day/approximate/unknown）。历史声明可进入复习候选，不补发历史物品。家长可安排短诊断，诊断证据与历史声明分开。

### 6.2 会话状态

训练session与验证session都持有不可变scope与题单。mode为training、verification或diagnostic；presentation为home、park、hospital，不把医院当第四种评分模式。

| 状态 | 允许事件 | 结果 |
|---|---|---|
| created | preload_success/preload_failed | ready或blocked_content |
| ready | start | active，发租约与服务端截止 |
| active | answer/hint/save/record/transfer | 保持active并增revision，或转待处理 |
| submitting | commit_success/timeout | awaiting_review/completed/needs_support；超时查幂等结果 |
| awaiting_review | adult_approve/needs_help | completed或needs_support，不能重复提交同复核结果 |
| late_review | adult_accept/reject/resume | 完成（保留late）或待帮助 |
| needs_support | create_remediation/pause | 同目标补救题或paused |
| paused | resume（窗口内或有授权） | active，不换题单版本 |
| completed | read_receipt | 终态；同请求重放返回原结果 |
| blocked_content | replace_invalid_item/parent_override | 新form版本或待处理，原尝试留存 |
| cancelled/expired | archive/parent_review | 不自动发奖，允许保存但不重复写active |

服务端拥有会话业务状态，XState负责前端交互镜像与宠物行为，不自行推断已奖励。challenge_items保存冻结的question_version、公开payload快照、private评分引用、目标要求、选项顺序和变式家族。恢复会话仍得到同一表单，随机打乱只在创建表单时执行。

### 6.3 组题算法

输入为task_scope、task_requirements、actual_exposure、device_capabilities、question_bank_release和seed。先排除退役题、媒体不可用题、能力不符题、源文范围不符题，再按未暴露family、目标覆盖和短用时排序。必需目标先各挑一个，再在预算内补题；同主目标通常最多2项。

使用固定seed的Fisher–Yates确保重放稳定，但seed不作为安全凭证。题单中正确项ID稳定且不包含correct/right等语义。主源片段必须属于本轮范围；context_slice只补阅读语境，不因此把该上下文全部加入测量目标。

优先顺序：必需目标缺证据→最近独立错误且到期→长期未查且适合目标。暖身题可先用识别，再到表达，但不能因暖身总分替代必需朗读。当前家庭数据少，不做题目区分度/IRT自动校准。

训练已经看过答案的family在同日验证中降级为assisted，不计算独立掌握。若必须使用同family，页面可以完成任务，但证据写answer_exposed，之后安排隔日变式；不能仅交换选项顺序清除暴露记录。

题不足时按“同目标合格变式→改变非目标操作→家长确认→待补题”处理；不按总分临时取消必需能力，不抽未学内容凑题。

### 6.4 响应与评分契约

| question_type | 响应 | 服务端评分 |
|---|---|---|
| audio_to_picture / word_to_picture / picture_to_word / sentence_choice / reading_choice | option_id | 是否属于冻结allowed_option_ids且匹配答案集合 |
| cloze_choice | gap_id→option_id映射 | 每空独立判定，缺空标incomplete，整体按蓝图要求 |
| cloze_text | gap_id→text映射 | 按每空normalization与accepted_answers，不拼接所有空模糊比较 |
| matching | left_id→right_id完整映射 | 校验左右元素集合和一对一限制，逐对比较；不接受客户端mistakes=0 |
| word_order | token_id序列 | 校验token多重集合恰好相等，再比较允许序列；重复词用不同token实例 |
| oral_reading | media_asset_id＋recording_metadata | 音频finalized且属于当前孩子/题，进入人工或校准评估 |
| retell | media_asset_id或家长现场确认 | 保存rubric与来源，开放表达不以简单ASR词匹配当全对 |

Grader为纯函数grade(question_private, response, grading_profile)→verdict。verdict包含correct、incorrect、partial、incomplete、unrecognized或pending_review，以及per_target、normalization_applied、reason_codes和评分版本。接口不接受client_correct、score或mistakes作为可信输入。

答案文本先NFC、统一允许的引号、trim与连续空格；大小写、末尾标点、缩写和英美拼写是否等价由题目profile控制。拼写目标禁止全局编辑距离容错；tree≠three，bag≠bags，不能因相差一字母自动通过。句意训练可以接受已明确列出的It is/It's，词形学习则按目标保留差异。评分规则不由LLM生成任意正则并执行。

词序题与填空题按已有词块或允许答案确定性判分，不把“与标准句字符串不相同”一律当错。训练时立即解释与可重试，验证时本轮最终提交前不向其他未答题泄露整套答案；反馈可以按题单策略延后到一轮结束。

### 6.5 验证蓝图与补救

默认全客观表单4项，threshold=3；混合表单3客观＋1朗读，客观threshold=2，朗读required。两种都要求每个task_requirement存在可接受成功证据，不能用总分越过未测目标。

首轮未达标可生成短补救表单，仅覆盖缺少的必需要求。补救表单保留parent_session_id、requirement_id和既有暴露；一次任务只产生一个最终TaskCompletion。两次主动尝试后持续显示求助，不强迫重复整套。补救达到任务完成可以发相同基础资源，独立掌握统计仍排除受提示结果。

### 6.6 口语与复核

P1录音格式运行时探测，最长单词10秒、句子30秒、复述60秒，可由策略调整；上传上限10MiB，真实MIME与时长服务端解码复检。录音上传采用init→上传→finalize；仅finalized、未过期且与孩子/会话/题绑定的音频可以评分，用户不能随意引用别人的asset ID。

家长复核显示教材目标、示范音频、孩子录音与rubric，动作approve、needs_help、unrecognized。approve写parent_confirmed证据；机器原判定不可被原地改写，新增人工判定与supersedes关系。次日复核按原学习日结算，缺失音频时可明确选择现场确认，并保留不同来源。

ASR增强只判断听到的内容，不输出虚假的发音准确率。静音、噪声、网络/设备故障转unrecognized，不进入知识错误分母。专业评测接入后必须以家庭童声样本测试误拒/误放，仍保留人工路径；不以声纹确认孩子身份。

### 6.7 证据与掌握聚合

学习证据由attempt和review产生，唯一键至少包含source_event_id＋objective_id＋skill＋modality。保存independence=independent/prompted/answer_exposed/parent_confirmed、verdict、content_version、发生时间、源题与撤回状态。

初始掌握标签：unseen（无接触）、introduced（有接触无有效验证）、practicing（有帮助或失败）、emerging（一次独立成功）、stable（至少两个不同学习日、至少一个有效变式的独立成功）。这些为产品观察标签，不声称统计概率。一次独立失败使相应能力进入review_due，不删除过去成功；标签与复习到期是并行字段。

同日同family重做不增加独立成功日数。阅读理解题只更新所测理解目标，不把源文里每个词都记成会读；诊断通过只更新诊断所测能力。无效题版本撤回后重算受影响聚合，不改发奖历史。

复习规则P1：下一个计划学习日、约3天、约7天；due_at与scheduled_learning_date分开。排序可参考弱项优先，但每轮受每日预算和scope约束，不能因为题不够就从所有已完成课随机填满。


## 7. 奖励、库存与事务设计

### 7.1 稳定资格

RewardEntitlement保存child、period_kind(day/week)、period_key（本地学习日或周一日期）、stable_slot、冻结policy_version、条件与物品清单。唯一资格不包含可变任务ID、题目ID、内容包版本和规则版本。TaskOccurrence映射已有资格，改计划或补做不得重新铸造。

日粮默认40营养点。N项必需任务以稳定slot排序，前N−1项分配floor(40/N)，最后一项取余；N不能为0，首版N≤3。一天两项各20，一项40。日建材wood=2、cloth=1在冻结必需集合全部完成后一次发放；周履约wood=4、cloth=2一次发放。重复自由练习、诊断、任意新建任务不新增基础资格。

无宠物时仍可获得家庭通用营养券，领养时按物种映射适合食物；首版领养需先于学习可简化此分支。食物适用种属在服务端item_definition中，孩子不能把猫狗食物用于兔类。食品库存单位明确为nutrient_point，界面按40点一餐呈现，不承诺现实动物医学热量。

RewardGrant是某资格成功发放的一次凭据；GrantItems不可变；InventoryLedger记录每个物品delta，InventoryBalance是同事务更新的快照。赠物、补偿与冲正另有source_type和actor，不伪造学习成果。

### 7.2 任务完成与发奖事务

```text
BEGIN;
  bind authenticated family/child context;
  lock child row -> learning_day -> task_occurrence;
  validate session lease/revision and frozen requirements;
  load server attempts/reviews, compute completion (ignore client score);
  if task already completed: return existing completion + receipt;
  mark task completed and persist effective evidence;
  lock eligible entitlement rows in stable ID order;
  for each newly satisfied entitlement:
    insert reward_grant with UNIQUE(entitlement_id);
    insert grant_items and inventory_ledger;
    insert/update inventory_balances atomically;
  update day/week fulfillment using frozen/revised authorized denominator;
  enqueue outbox events inside transaction;
  persist idempotent response;
COMMIT;
return receipt; animate after commit.
```

服务端完成判断、grant和余额属于同一事务。并发设备即使各自请求UUID不同，也被同一资格唯一约束挡住。不要先标任务完成再异步发粮而没有恢复机制；相册/统计可异步，核心物品不能等待外部模型。

所有会修改奖励/库存的命令首先锁同一个child行，之后以固定表顺序/ID升序锁资格与余额，减少死锁。数据库仍保留唯一键和余额非负CHECK。发现40P01/40001最多自动重试3次，重试保留同一幂等键；锁等待超时返回可重试，不转成答错。

### 7.3 请求幂等

写接口需要Idempotency-Key（UUID），服务端组合family、actor scope、operation和key建立记录，保存规范化request_hash。相同key同payload返回原HTTP状态和结果；相同key不同payload返回IDEMPOTENCY_PAYLOAD_CONFLICT；处理中返回202和查询位置。

幂等记录默认保留30天，但奖励资格、grant和消费事件的业务唯一键永久保留至家庭删除。不能用请求幂等TTL承担“一生只领奖一次”。过期重放命令通过source_event/business key仍受保护。

### 7.4 喂食与消费

孩子发送pet_id、item_id、requested_units、expected_revision，不能发送最终饱腹值。服务端materialize宠物后计算need=floor((10000−satiety_cp)/100)，consume=min(stock,requested,need)。consume=0时返回PET_FULL或ITEM_NOT_AVAILABLE，不扣库存。非主食上限、适用种属、每日零食次数和当前疾病限制独立检查。

事务顺序：锁child→pet/state→相关inventory→校验→写唯一PetEvent→扣库存ledger→更新余额和satiety_cp→写outbox/幂等结果→提交。实际吃不下的份额留库存。动画根据已提交event_id播放一次；关闭页面只跳过表现，不能撤销已发生消费。

制作装扮先检查全部材料余额、物种挂点和是否已拥有，再一次事务扣所有物品并增加装饰。预览和场景布局移动不扣费。首版不回售、不交易、不重复买同一非消耗装饰。场景布局保存使用expected_revision，冲突返回最新版供选择，不后写覆盖。

### 7.5 审计与对账

定期对账：balance=Σledger.delta；grant每个entitlement至多一个；ledger的grant/consumption来源可追；周奖次数和日粮额度符合策略；余额非负。差异进入ops告警，停止受影响消费，不能静默重置余额。

账本错误通过追加冲正项修复并引用原项。坏题或评分错误只修证据，不默认回收已发学习物品。家庭整体删除通过专门purge任务和受控角色执行，与日常不可修改账本权限分离；备份按保留期清理，不能宣称主库删除就立即清空旧备份。

## 8. 宠物生命、场景与情感逻辑

### 8.1 宠物状态与时间推进

Pet保存种属、昵称、性格、主宠标记和包版本；PetState保存satiety_cp、hydration_cp、energy_cp、mood_cp、health_cp、hygiene_cp（均0–10000）、成长日、关系里程碑、life_stage、care_mode、disease_state、scene_key、revision、last_evaluated_at和rules_version。不同维度并行，不把“开心的少年生病小狗在公园”编码成一个巨型枚举。

数据库快照与PetEvent互相校验，但首版不要求全面事件溯源。状态推进通过materialize(now)在读取或写命令时惰性执行；后台每天补充里程碑即可，不做逐秒扣饥饿任务。

采用固定5分钟步长的确定性积分，步长和余数存规则/时间字段；重复读取不多扣。每步先计算照护模式、低值边界和休息，再计算资源与情绪。正常陪伴日饱腹衰减总量上限3000cp；饮水可免费补足；active每分钟energy−10cp，resting且饱腹/水分充足每分钟energy＋20cp（上限10000）；具体为试运行参数，可版本化调整。

服务恢复时只补偿最后一次正常心跳之后的安全范围。连续缺席或低饱腹触发托管，托管段不继续不利演化；server_now小于last_evaluated_at时不逆向结算并告警。单次最多计算一个安全窗口，超出时间进入托管，不以长时间停机直接算死。

托管可由请假提前设置，或陪伴模式下satiety≤1000cp/连续24小时未活动触发；进入时照护员保障饱腹/水分最低安全值、暂停疾病恶化与增长，记录非学习照护事件，不发学习材料或伪造照顾日。返回后欢迎并由孩子恢复照护，必要水和托管不限于挑战窗口。

### 8.2 成长与关系

PetDailyRecord唯一pet＋learning_date。当天至少一项有效计划验证与一次成功照护形成growth_day，日上限1；提示后完成和人工确认可计，不把所有状态依赖考试满分。纯赠物、诊断或反复摸头不刷成长。幼年0–13日、少年14–41日、成年42日起，按冻结规则版本执行。

亲密以共同经历里程碑累积，缺席不清零；短期心情可变化，但不使用“你没学习我不爱你”台词。PetMemory使用受控fact_type＋source_event_id唯一，语言模型可改文案但不创造未发生的事实。删除原录音后记忆保留文字里程碑，回放入口显示已删除。

### 8.3 行为与动作调度

BehaviorController接收权威快照和已提交事件，管理四层：attention（眼神/头部朝向）、body（待机/走动/吃喝/睡眠）、expression（表情）、accessory（耳尾/围巾跟随）。动作强度与时长有上限，呼吸和眨眼可本地随机但用seed使重放可测。

优先级：安全暂停/页面隐藏→已确认照护剧情→主动点击回应→短情绪反馈→低频待机。进食动作可在安全点打断为完成姿态，不在网络重试时重复排入长队列；最多保留1个主要动作和1个可替换回应。相同event_id表现去重，重连时取状态而不是重播整天历史。

白名单动作look_at、walk_to、play_action、set_expression、speak_approved_line、equip_owned_item；参数校验stage bounds、duration≤10秒和已拥有装饰。行为控制不允许set_health、grant_food、unlock_window或die。

### 8.4 医院

疾病case状态healthy→mild→examined→recovering→resolved。首版事件仅在家长开启疾病剧情时触发，周冷却至少7天，答错不会随机生病。必要治疗立即开始；复习帮助推进康复互动，不作为紧急生命保障的唯一门槛。

HospitalCase关联pet、cause_event、eligible_scope策略与可复用task_id。进入医院先选择今天未完成的预排复习task，创建presentation=hospital的同一verification session；没有可抵扣任务时可以创建无奖励practice，不额外铸造粮食。复习来源为已接触scope中的薄弱/到期目标，不仅选过去成功题。

康复成功写care_event和case进度，学习证据与奖励仍走learning/rewards服务。服务不可用或两次求助后家长可启用care_assistance完成安全康复，不伪造独立能力证据。宠物医院不能调用另一个独立发奖接口。

### 8.5 公园、装扮与真实户外

公园采用固定热点和路径，点击对象可调用符合当前scope的微训练；自由探索无额外粮食。虚拟散步消耗精力并适量改善心情，每日次数受限，不能通过无限散步创造能量。真实户外记录由家长确认，仅形成关系/心情和相册，不默认采集GPS。

布局采用场景槽位＋有限拖动区域，保存item_id、slot_key、x/y、scale、layer；坐标归一化0–1，后端限制安全区，物品不得遮住宠物主要交互区。TV用槽位选择与方向键微调，提供撤销/重置和布置锁定。

### 8.6 真实生命模式的扩展点

首版life_mode只启用companion；realistic模式保留策略版本字段和feature flag，不启用未定数值。后续需要家长显式开启、展示周期与可暂停规则，健康危急有预警、确认与托管/急救出口。生命结束必须来自明确领域命令及家长确认，不由ASR、AI对白、后台长时间补算触发。

死亡保留档案和相册，不物理删除宠物；系统事故由审计和快照恢复。真实生命模式上线前必须另行完成参数、儿童体验和回滚规则验收，不能将预留状态视为已实现功能。

## 9. 自动素材与AI服务

### 9.1 PetDefinition与SceneManifest

PetDefinition包括definition_version、generator_version、seed、species、比例/颜色参数、parts、hierarchy、pivots、anchors、slots、hit_regions、动作clips、混合/打断规则、声音事件、LOD和runtime_capabilities。SceneManifest定义背景、前后景、可行走区域、热点、喂食/窝坐标与安全区。

参考图精灵路线增加frame_rects、frame_duration_ms、baseline、direction、逐帧挂点与遮挡；无稳定挂点的图集不能宣称支持任意换装。程序化路线支持明确部件层级，复杂大转身需要额外姿态，不仅整体左右翻转。

资产包保存manifest摘要、文件hash/MIME/尺寸、生成模型及参数、许可范围、构建工具版本、检查报告和兼容映射。首版建议单场景加载资源压缩后≤8MiB、解码纹理≤64MiB作为待真机校准预算；2048²RGBA单页约16MiB，不含mipmap与额外副本。

### 9.2 构建与发布

制作请求→规格校验→隔离生成→固定时点渲染→自动几何/时序检查→AI辅助视觉检查→局部重试→打包→能力预览→发布。构建环境只读模板、独立输出目录，无家庭数据和运行库凭据；执行生成的代码必须限制网络、路径、CPU/内存和时长。

检查部件缺失/裁切、透明边缘、接缝、脚掌接地、动作语义、围巾遮挡、连续点击中断和低配静态输出。单动作最多3次生成重试，超过预算进入failed_needs_decision，不能为了自动完成而绕过质量门槛。人工风格评审是选择结果，不能要求用户手工修图绑骨。

发布写入新package版本，所有文件校验后原子更新active指针；活动会话继续使用旧包直到安全切换，旧装饰ID映射到新slots。保留上一版和被历史/活跃会话引用的版本，GC只删除无引用且过保留期的产物。

### 9.3 模型网关

ModelGateway暴露generate_questions、review_questions、generate_dialogue、transcribe、assess_pronunciation和generate_asset意图，provider通过适配器实现。输出必须是受控schema；provider URL由管理员配置且防内网敏感地址访问，用户上传文档中的“指令”只当资料，不影响系统权限。

所有调用经过预算reserve→执行→settle/release，记录run_id、usage、成本估算与实际值、错误类别。每家庭默认同时1个内容生成任务，每调用60秒、整个job15分钟；网络/429/5xx最多3次指数退避并带随机抖动，结构错误允许1次修复，语义失败只重生失败项。超预算停止新调用，已有题库与已发物品不受影响。

宠物对白默认固定模板；AI对白P3每次最多2句、单轮不超过适龄长度、每日预算、时间截止检查。对话超时使用本地句库，不显示“系统提示/Token错误”给孩子。外部模型不获得完整孩子历史、真实身份或任意录音；家长明确开启需要传输的能力。

### 9.4 资产与内容的安全处理

SVG清理script、foreignObject、外部URL和事件属性，必要时栅格化；上传ZIP检查路径穿越、解压体积、文件数和压缩比；媒体MIME与实际解码结果一致；教材宏、脚本、主动HTML均不执行。来源文本进入LLM时用数据边界与明确证据ID，模型没有文件/网络/发奖工具权限。


## 10. 接口、事件与集成契约

### 10.1 HTTP约定

所有业务接口前缀/api/v1，同源Cookie认证。GET无副作用；创建返回201，异步任务返回202＋job_id；更新返回资源和revision。列表使用cursor＋limit（默认20、最大100），不承诺offset在并发更新时稳定。写命令发送Idempotency-Key，修改已有聚合发送expected_revision；服务端也返回ETag供缓存校验。

成功响应统一为data、request_id、server_time和可选next_cursor。列表data.items。private答案、source_quotes里的标准答案以及内部评分说明不通过儿童查询返回；家长预览必须是独立受权路径。

附件OpenAPI定义每个operation_id、权限、阶段、请求/响应schema和错误码。大型媒体走二进制上传端点，不把base64塞进普通JSON。资源查询默认按会话family/child范围过滤，不允许普通用户请求任意family_id来切换家庭。

### 10.2 核心接口示例

```json
{
  "task_id": "40000000-0000-4000-8000-000000000001",
  "mode": "verification",
  "presentation": "home",
  "capability_profile_id": "40000000-0000-4000-8000-000000000002",
  "expected_task_revision": 3
}
```

创建session成功返回session_id、revision、lease_epoch、lease_expires_at、finish_deadline、form_version和公开items。提交answer包含challenge_item_id、response、expected_revision、lease_epoch和client_event_id；response按题型使用option_id、pairs、tokens、gaps或media_asset_id，禁止传correct/score。

```json
{
  "challenge_item_id": "40000000-0000-4000-8000-000000000003",
  "response": {"option_id": "40000000-0000-4000-8000-000000000005"},
  "expected_revision": 1,
  "lease_epoch": 1,
  "client_event_id": "40000000-0000-4000-8000-000000000004"
}
```

终结验证接口只提交会话revision和租约，服务端按已保存attempt/review计算结果。返回completion_status、missing_requirements、review_request_ids和grant_receipts；不能客户端发送“本轮3/4正确”直接领取。

喂食请求只含item_id、requested_units（十进制整数字符串）与expected_revision，返回consumed_units、remaining_units、state和pet_event_id。宠物事件不是新的发奖授权。

## 11. 离线、设备租约与多端同步

### 11.1 权威数据和本地存储

服务端拥有计划、题目版本、开放窗口、证据、库存和宠物状态。IndexedDB只存程序缓存、已下载公开题目、草稿、录音临时块、pending_operations和同步cursor。私有答案不离线下发，P1离线作答只能显示已保存/待确认，不自动给分发粮。

离线操作字段：client_event_id、operation、aggregate_id、lease_epoch、expected_revision、payload_hash、payload、local_created_at和sync_state。local_created_at用于提示，不证明准时。网络恢复先拉session/lease，再顺序发送；同session按事件序号发送，冲突后暂停剩余队列，不能乱序盲重试。

页面前台、online事件和用户点击可触发同步；online不等于NAS真的可达，API成功才显示联网。缓存驱逐可能丢失未同步记录，因此明显展示仅本机保存状态；大录音优先立即上传，不承诺浏览器后台永不丢数据。

### 11.2 会话租约

创建验证时写lease_owner_device、lease_epoch=1、expires_at，默认90秒租约，活跃前台每30秒续期。租约过期不等于新设备自动覆盖；用户选择接管后服务端锁session，epoch＋1，返回最新form与revision。旧设备即使仍在窗口内，其旧epoch提交也返回LEASE_STALE。

HTTP请求幂等、client_event_id唯一与lease_epoch分别处理重试、事件重复和旧拥有者问题，不能只用一个UUID解决所有并发。跨设备读取的pet/reward快照携带server_revision，客户端只接收较新修订。

### 11.3 电视与录音伴侣

TV用D-pad选择、确认、返回和播放/暂停；题型不要求拖拽、hover或精确点击。FocusManager保存focus_key图、默认焦点、弹窗焦点陷阱与返回栈；列表更新后按稳定key恢复，不能跳到页面最上方。

手机/iPad经短时配对加入特定家庭/孩子/会话，权限只允许获取当前oral item、上传对应录音和提交已授权响应。TV仍是主会话拥有者；伴侣命令由服务端绑定同一租约epoch，不能自行替换题单。断线重连拉当前状态，旧命令不能作用于下一题。

WebSocket只传消息command_id、session_id、lease_epoch、expected_revision和受限payload，服务端回ack/new_revision。初版可轮询，P3再用WebSocket改善同步；两种使用相同领域接口。

### 11.4 设备能力矩阵

设备注册上报浏览器/系统版本、WebGL能力、maxTextureSize、录音MIME候选、音频解码、触摸/键盘/方向键、存储估计及prefers-reduced-motion。客户端报告用于优化，服务端不将其视为安全凭证。

P1以真实家中iPad的Safari与主屏PWA为基线，推荐iPadOS17及以上；更低系统需单独实测。TV需明确型号、系统与WebView版本，缺WebGL时使用静态宠物，DOM题目仍可用。缺麦克风走伴侣/人工，不能把识别点选记作口语证据。

## 12. 后台任务、文件与发布一致性

### 12.1 任务执行

background_jobs字段包括job_type、status、attempts、max_attempts、available_at、lease_owner、lease_expires_at、input_ref、result_ref、progress、error_code、dedupe_key。状态queued→running→succeeded；可重试错误转retry_wait，终止为failed/cancelled。获取使用FOR UPDATE SKIP LOCKED，执行长任务前释放数据库事务；心跳续租，提交结果时再验证租约。

轻量worker默认并发2，家庭AI生成并发1，OCR/ASR默认独立worker。重复执行依赖业务唯一键，lease只防大多数并发不保证一次执行。作业输入是不可变版本ID，取消只阻止未提交下一阶段；已发布结果不会因取消撤销。

### 12.2 文件生命周期

媒体状态uploading→staged→validated→finalized→retired/deleted。上传先写临时随机目录，校验大小/MIME/hash/解码与权限，再原子rename到内容寻址目录，数据库finalize记录。文件与数据库无法同事务，采用阶段状态和可重试finalizer；孤儿文件定时清理，不能在DB已引用前立即删临时文件。

私有媒体经认证API或短时受控URL访问，缓存private；宠物公共资源可以immutable长缓存，教材和录音不自动公开。下载响应防内容嗅探，HTML/SVG按隔离策略处理，未经净化的文件仅附件下载。

单次默认限制：图片10MiB、音频10MiB、文档50MiB、ZIP100MiB/解压500MiB/2000文件；管理员可调但服务端强制上限。资源内容摘要可用于去重，但跨家庭不暴露文件是否存在，不能通过hash探测其他家庭资料。

### 12.3 内容与资源发布

发布物包含不可变manifest、源/题版本集合、质量报告引用与兼容能力。先构建临时版本并核对所有引用，再数据库事务写release、绑定题版本并切active指针；缓存通过outbox失效。失败继续旧版本，不让半成品被儿童端加载。

活跃计划引用版本不自动迁移；坏题退役是紧急可见状态，进行中session在下一提交/恢复检查时阻断该项并启动同目标替代，不篡改原attempt。API兼容当前和上一客户端协议版本；service worker新版本等到一轮挑战结束再提示激活。

## 13. 部署、运维与数据保护

### 13.1 容器拓扑

默认api-web、worker、postgres三个逻辑服务；api-web提供静态前端/API/受控媒体，worker可与API共用镜像但不同启动命令。HTTPS使用NAS现有反代；无现有能力可加网关。文档解析/模型服务是compose可选profile，素材构建在开发电脑或独立构建环境，不在NAS儿童运行服务内执行任意AI脚本。

应用端口仅供反代/内网访问，数据库不映射公网。非root运行、只读根文件系统、单独临时目录和持久卷，health与readiness区分进程活着和数据库/媒体可用。数据库镜像固定PostgreSQL16兼容版本，禁止自动追latest。

持久卷分数据库、media、packages、backups与配置。API和worker只写所需目录；媒体下载路径由服务端ID解析，不能接受客户端任意本地路径。环境示例只含占位符与变量说明，真实凭据通过NAS secret/env注入，不进入设计包、日志和浏览器。

### 13.2 HTTPS与初始化向导

向导检查域名解析、证书完整信任链、iPad实际地址访问、麦克风授权/回放/保存、持久卷写入、备份路径和时区。真实域名＋DNS-01签发＋内网DNS可避免公开应用端口；DNS凭据最小权限，证书续期有到期告警。

首个owner创建后录入家庭时区、孩子能力、设备和语音授权，再导入一个自编样例包完成试题和喂食自检。不使用固定admin/admin默认账户，不把生产健康检查误当业务验收。

### 13.3 备份与恢复

默认每日一次PostgreSQL一致性dump，记录schema_version、应用镜像digest、媒体manifest与文件摘要，所有被dump引用的媒体在备份完成前不被GC。备份文件原子写完并校验后标成功；加密密钥由家长独立保管，不与备份同目录明文保存。

初始目标RPO≤24小时、RTO≤60分钟，均需目标NAS实演校准。恢复先到新目录/新数据库，核对表数、资格与库存对账、媒体存在、样例孩子与宠物，再切服务入口。失败保留原数据，不直接覆盖生产卷。PWA未同步草稿不在NAS备份承诺范围内。

升级前备份；先做向后兼容迁移，再发布API/Web，再清理旧字段。破坏性迁移需维护窗口和明确恢复方案；回退不只是换回镜像，还需匹配schema和资源版本。

### 13.4 删除与保留

原始孩子录音默认30天（可调），复核完成后可早删；正在复核的音频设置短延长并提示家长，不能无限自动续期。对外模型传输前家长按能力授权，默认不上传整段学习历史。转写、证据与录音不同保留策略，删除音频不伪装删除所有证据。

家庭删除任务先撤销会话、停止新作业、标记purging，按依赖顺序清理私有文件与业务表，账本在专用维护角色下整体清除，写无个人明细的删除凭据。备份按约定最大保留期淘汰，恢复旧备份后重放删除清单，防已删除家庭重新出现。

### 13.5 可观察性与资源目标

日志包含request_id/job_id/family匿名标识、operation、耗时、错误code和trace_id；不记录密码、token、孩子原音、完整教材和标准答案。模型审计只保存受控产物/引用，不把凭据与整个prompt上下文倾倒到日志。

指标：普通API p95目标300ms（LAN、数据库热盘），已缓存触控反馈100ms，场景稳定30fps为最低目标，冷启动磁盘唤醒单列；测试基线一个家庭3台设备、5个孩子、1万源片段、2万题版本。2GB可用内存作为基础部署试测起点，4GB更从容；OCR/ASR内存另算。上述为验收目标而非已测结果。

运维面板显示备份新鲜度、磁盘、任务积压、AI额度、坏题/媒体错误、证书到期、数据库迁移版本与对账。磁盘不足时先停大文件导入/AI生成，已有学习只读和状态查询尽量可用；数据库写失败时不得显示虚假完成。

开发按垂直闭环推进，先自编一页材料、一个客观题、一次验证、一份粮与一次喂食，再扩到一周真实教材。内容和素材生产链在P0独立验证后再估工，不能假定复杂教材和所有动物自动生成已解决。

### 14.4 尚需实测或配置的参数

家庭NAS型号/架构、iPadOS与TV型号、当前教材版本/实际文件、每天可承受用时、模型服务与预算、宠物风格通过样片确定。默认值已经给出，缺少这些参数不阻止内核开发，但不得将未测兼容和识别效果标为完成。

真实生命模式具体周期、自动发音评测阈值、应用商店发布和跨家庭内容分享为后续独立决策。对应feature flag默认关闭，数据结构保留扩展点，开发验收不将占位字段算成功能完成。

## 17. 组件与数据映射约定

### 17.1 公开契约与存储字段

HTTP DTO是服务端显式投影，不能直接把数据库行序列化。下列映射固定由应用repository/assembler实现，单元测试检查往返和敏感字段剔除。

| 对象 | API/领域字段 | 数据库映射与规则 |
|---|---|---|
| 教材切片 | kind、node_id、normalized_text | source_slices.slice_kind、node_id、normalized_text；kind仅context/sentence/word |
| 题目 | objective_ids | 每个题目恰好1个主目标，对应question_versions.objective_id；多目标蓝图拆成多个槽位 |
| 题目 | prompt/instruction、public_payload | prompt_text/instruction_text与题型JSON分开，payload受题型Schema校验；答案、解释不进入公开列 |
| 选项/空/词块 | UUID子ID | 选项对应question_options.id；词块/空UUID保存在受限public_payload与private评分引用中 |
| 题目状态 | published/retired | question_versions.status为生产状态，published_at/retired_at派生运行发布状态 |
| 计划 | revision、active_revision_id | 计划修订revision_no和最后已发布且未退役修订；不能把task.revision当plan revision |
| 任务 | stable_slot、required | stable_task_key、is_required；奖励资格使用entitlement.stable_slot并冻结映射 |
| 学习日期 | finish_deadline | learning_day收尾时刻与session.submit_deadline_at；补做另有受权审计 |
| 学习声明 | source、date_precision | DB使用self_report/parent/historical/authorized_external来源，API别名统一转换，不与assessment来源混淆 |
| 库存 | item_id、unit_kind | item_definition_id、unit；nutrition_point为营养最小单位，piece为材料/饰品 |
| 宠物 | life_stage | pet_states.growth_stage baby→juvenile、young→adolescent、adult→adult、elder_reserved→senior；后者未启用 |
| 宠物 | care_mode | normal→active、resting→resting、hosted→boarding |
| 宠物 | scene_key、disease_state | location_key；疾病由当前hospital_case与允许规则派生，不新增客户端可写生命字段 |
| 学习证据 | independence | independent→independent、hinted→prompted、demonstrated→answer_exposed、parent_confirmed→parent_confirmed |
| 文件 | finalized | 媒体通过校验且文件落定的运行状态；upload临时阶段不作可评分资源 |
| 后台作业 | retry_wait | queued且available_at晚于当前时间，显示为retry_wait；重试不增发业务资格 |

### 17.2 会话状态的存储映射

created/ready/submitting/paused中的一部分是界面状态，不能全部直接写到SQL CHECK枚举。持久化session使用created、active、submitted、pending_review、completed、expired、cancelled；task承担scheduled、active、pending_review、completed、cancelled、content_blocked生命周期。

| 领域/显示状态 | 存储/判定 |
|---|---|
| created预加载中 | 创建命令尚未提交或客户端本地状态；完整题单提交后DB created对应ready |
| active/paused | DB active；paused为本机草稿/最后活动信息，恢复仍校验租约和窗口 |
| submitting | 客户端请求中；DB submitted表示提交已收齐且待终结评估 |
| awaiting_review | DB pending_review，review_reason=oral或assistance |
| late_review | DB pending_review/expired并有late_sync复核请求；late标签永久保留 |
| needs_support | 存储原尝试与缺少要求；task仍active，结束旧session为completed但不标task成功，再新建补救session |
| blocked_content | task.content_blocked，受影响session不能继续评分；原form保留，新替代表单另建session |
| completed | session已处理完；TaskCompletion是否成功取决于task.status=completed和有效证据，不仅看session终态 |

P1每个verification session的任务完成要求仍由task_requirements决定。补救session关系保存在版本化会话payload/审计关联或显式parent引用，不能重置曝光历史。无task的诊断session不参与奖励；若数据库约束要求证据学习日，则创建无奖励diagnostic task/day容器，不能借用正常发粮资格。

家长选择unrecognized不写approved，不生成passed证据；可以保留pending并说明“需重录/现场确认”，或以needs_help结束此次复核，再另开有效尝试。接口review.status只返回pending/approved/needs_help/cancelled，未识别原因单独显示。

### 17.3 幂等和修订的边界

应用以数据库每个可编辑聚合的revision作为expected_revision依据，发布快照使用version_no/revision_no且不可原地改写。family_settings按policy_key和策略版本更新；发布后新建未来生效版本，不追溯改变历史窗口、学习范围和奖励。

idempotency_records的唯一范围为family＋operation＋key，保存请求者identity与摘要；相同键被不同请求者使用不得返回其他人的原结果。终结响应和私有答案反馈不可通过广泛幂等查询泄露，查询必须匹配原actor或明确授权家长。客户端总是生成高熵UUID避免无意义碰撞，数据库业务唯一键负责真正的防重复。

body.expected_revision用于资源乐观锁，不用payload_hash冒充整数版本；不可变源/题快照的修订传所读version_no，校验后产生新UUID。能力上报profile可使用device.id和capability revision，不必建立第二套重复能力真值。

### 17.4 运行控制表

family_settings记录策略key、schema、版本、未来生效日和payload。content_issues记录孩子/家长的题目或媒体问题、分类、状态、修复关联和revision。ai_provider_configs只保secret_ref和能力/model等配置，真实凭据从部署secret提供。ai_budget_reservations在生成前预留，调用后结算/释放，同run/job唯一。outbox_deliveries按event＋consumer唯一保存投递状态/重试，不能用outbox单个delivered_at代表所有消费者成功。

后台job payload只用于版本化作业参数与结果引用，不代替这几类需要约束、检索、权限和并发的实体。provider自动探测不得回显密钥；变更地址进行SSRF和协议限制，只有owner可配置。

### 17.5 逻辑复用边界

文本与词条采用词形/父词义/多词单位关联，掌握证据不沿父关系自动扩散。源内容与生成题包分离，固定ID和版本支持增量生成。判分采用纯函数、每空允许答案、词块多重集合和逐项反馈，通用容错不覆盖拼写目标。

练习筛选先基于实际接触范围与能力，再按薄弱、到期与近期独立错误排序；错题清除需要之后有意义的独立成功，不能因为同次提示重试最后答对就消失。发布内容只返回公开投影，连线必须服务端校验真实配对，不采用客户端自报错误数。相关具体开源文件和许可映射单列于开发附件，运行产品不依赖这些外部项目在线服务。


## 18. 数据库模型与完整数据字典

### 18.1 基础约定

数据库使用PostgreSQL 16，迁移不依赖扩展。所有UUID由应用生成，不设置随机UUID默认值；日期时间使用timestamptz并将连接时区固定UTC，家庭学习日使用date，家庭IANA时区保存于families。所有余额、营养份额和材料数量使用bigint最小单位，不使用浮点数。

宠物六项身体状态使用smallint centipoint（0..10000，100cp=界面1点），食物库存1单位=1营养点=100cp。食物消耗为min(requested_units, stock, floor((10000-satiety_cp)/100))；小于1营养点的缺口不消耗整点食物，余粮保留。被动衰减保留余秒并按规则版本结算，不靠客户端动画帧数推进身体状态。

物理表包含70张，除平台身份accounts和租户根families外均含family_id NOT NULL。孩子业务表采用(family_id,child_id,id)唯一键与对应复合FK；同家庭其他孩子的宠物、账本、作答或录音也不能互相引用。教材、场景等家庭共享资源只需(family_id,id)FK。outbox/audit的aggregate_id/entity_id属于历史路由元数据，非关系真源，不用于绕过正式FK。

| 公共字段 | 类型 | 可空 | 含义与例外 |
|---|---|---|---|
| id | uuid | 否 | 每表主键，应用生成且不可变；不依赖UUID数据库扩展 |
| family_id | uuid | 否 | 家庭业务表租户键；families本身以id代表家庭，accounts为全局身份不含此列 |
| child_id | uuid | 依表 | 孩子业务表非空并带复合FK；家庭共用内容表不含；录音/审计等多用途表可空且按用途约束 |
| created_at | timestamptz | 否 | 记录创建时刻，默认CURRENT_TIMESTAMP，连接使用UTC |
| updated_at | timestamptz | 否（若存在） | 可维护实体最近更新时刻；追加事实表通常没有该列 |
| revision | bigint | 否（若存在） | 乐观并发版本；领域命令成功后递增，不作为学习证据 |
| published_at | timestamptz | 是 | 内容/计划/资产第一次发布时刻；非空后payload冻结 |
| retired_at | timestamptz | 是 | 可发布版本/定义停止新使用的时间，历史仍保留；不是覆盖payload |

每表字典省略重复的id/family_id/created_at，沿用本共同字段定义；child_id在实际含有的表逐项展示。family_memberships、devices、auth_sessions等属于家庭共享身份表，孩子字段的可空性按表中用途处理。

schema.sql是单一迁移入口；catalog.json为同源机器可读数据字典。DDL创建app、private两个schema，不创建或猜测运行账号和口令，不授予PUBLIC表访问。private.question_answers保存答案、讲解与量规，公开题目表和公开视图不含答案。媒体文件本体位于NAS受控目录，数据库只存键、摘要、大小、权利和引用。

### 18.2 关系与不可变边界

教材关系为curriculum_series→curriculum_editions→content_versions→content_nodes/source_slices；上下文通过slice_contexts，词义与目标通过vocabulary_senses/learning_objectives/slice_objectives关联。生成批次的精确输入单列generation_inputs；候选题发布为question_versions，题源、选项、答案关系化保存，content_releases/release_questions冻结一次可分配题库。

孩子关系为weekly_plans→plan_revisions→learning_days/task_occurrences→task_scopes/task_requirements；外部学习声明进入study_exposures/exposure_slices，训练或验证作答进入challenge_sessions/challenge_items/answer_attempts。家长复核写review_requests，能力事实追加learning_evidence；mastery_snapshots可从有效证据重新计算。计划到期、声明学习、训练答对均不自动等价掌握。

content_versions、question_versions、content_releases、plan_revisions、asset_packages、family_settings设置published_at后payload不可更新或删除；只允许retired_at从空变为首次退役时刻。其子表通过发布父级触发器冻结，父行FOR SHARE锁与发布写锁排他，避免发布过程中并发插子项。题目退役阻止新组题，历史会话保留原版本。词义、目标、题族和物品定义创建后不可变，变更用新身份/版本并保留旧证据。

RLS为二次租户隔离：可信API在认证后事务内SET LOCAL app.family_id，所有家庭表FORCE RLS；值来自账号/设备授权结果，不来自请求体直接信任。用户与浏览器不获得SQL连接或设置GUC权限。auth专用连接访问全局身份，worker专用连接按内部已授权job取得家庭上下文，不能仅凭用户传family_id运行。RLS不替代角色校验、child授权或答案字段投影。

部署时仅迁移owner拥有DDL权限。API非owner角色只获各命令所需表权限；inventory_balances仅SELECT，触发器为唯一写入者；private答案仅评分/受权管理连接可读。认证bootstrap和家庭创建使用专用受控管理路径，普通家庭连接不能创建任意租户或全局账号。不可用同一个超管连接服务所有API。

### 18.3 奖励、库存与事务

reward_entitlements唯一键为(family_id,child_id,period_kind,period_key,stable_slot)。period_key为日日期或周一日期，policy_version只作为冻结数据，不进入唯一键。任务替换、题目升级、政策升级不能获得另一份资格。entitlement_items冻结应发物品，reward_grants每资格最多一条，reward_grant_items复制该份额；延迟约束要求发放明细与资格完全一致且每项在同事务写一条正向库存账。

日粮40营养点按已冻结的任务槽位分配；例如两项任务各20，而不是每新建任务发40。entitlement_items触发器对同孩子同日非管理食物总量限制不超过40；发布计划时必须进一步检查“恰好40”，因为数据库允许未完成草稿分配。日建材2木料/1布料、周4木料/2布料使用各自稳定资格一次；材料种类由item_definitions稳定键识别，具体额度在计划编译和政策回归检查，不能在任意内容包中声明增发。

inventory_ledger追加不可修改或删除。reward条目必须与同家庭同孩子同物品的grant item一致且只可写一次；余额触发器在ledger插入后更新inventory_balances并由CHECK阻止负数。管理纠错写compensation或引用原账的reversal（只能全额反向一条且不能冲正另一条冲正）；普通客户端没有该权限。题目本身错误不得倒扣孩子既得食物。

#### 3.1 完成与发奖事务顺序

1. 认证并SET LOCAL家庭；插入/锁定idempotency_records，验证同键request_digest一致。
2. 锁children行，再按learning_days→task_occurrences→reward_entitlements→inventory_balances固定顺序锁行；检查租约、题单版本、每个必需目标的证据和家长复核。
3. 将任务标记完成，按冻结条件标记日完成/资格qualified_at；插入reward_grants及其明细。
4. 插入inventory_ledger、更新可重算证据/快照、写outbox与最小响应；提交时延迟约束核实完整发放。
5. 响应丢失时使用同幂等键查询原结果；不重新发一份。次日口语复核仍归原学习日，家长操作不受儿童新开挑战窗口限制。

#### 3.2 喂食事务顺序

1. 按同幂等键处理，锁顺序固定为children→pets/pet_states→inventory_balances（多物品按ID排序）。后台衰减也遵守同孩子/宠物锁顺序。
2. 按服务端时间与rules_version结算身体状态，核实物种兼容、库存、请求营养、期望state revision，计算实际消耗整数营养点。
3. 实际消耗为0时不扣库存；否则插入负向feed账目、更新状态增加applied_units×100cp及revision，追加pet_events引用该账目，再写outbox与幂等结果。
4. 延迟约束检查feed账目与宠物事件的孩子、物品、数量、宠物一致；整个事务成功后才向客户端返回动画事件。动画跳过、切后台、WebGL失效均不取消/重复消费。

DDL不提供第二套feed_pet业务函数；上面是后续服务实现必须遵循的事务边界。数据库检查负责归属、金额来源、非负与关联完整性，服务负责具体状态衰减与通过规则。

### 18.4 挑战、内容质量与同步约束

验证会话partial unique约束同task最多一个created/active/submitted/pending_review的verification；训练可另开。challenge_sessions使用lease_epoch栅栏代数和revision，设备转移须递增epoch；answer_attempts提交epoch不匹配、设备不符会被拒绝。租约已过期但仍为当前epoch的录音可走独立late-review intake接口，以pending_review写入原会话证据并生成late_sync复核请求；expired会话仅允许这条待复核路径，不能自动计分。已经被新epoch取代的旧设备仍不得写旧会话，文件可先作为media_assets staging保留，再由受权家长重新提交到当前或诊断复核会话，不伪装原窗口内提交。跨收尾时间补传同样只接受pending_review。客户端先查询幂等结果后重试，避免已提交成功的重放成为新尝试。

#### 4.1 持久状态与领域DTO的明确映射

| 数据库状态 | 领域/界面状态 | 唯一解释与进入条件 |
|---|---|---|
| 尚无challenge_sessions行 | created | API正在事务中校验范围和构建题单；不得把不完整题单提交为ready |
| created | ready | 创建事务同时插入完整challenge_items和form_digest后提交；开始前的可恢复题单 |
| active | active | 孩子已经开始本轮，租约设备可追加作答 |
| active（请求未确认） | submitting | 仅客户端瞬时状态，数据库尚未确认最后提交；超时查幂等结果，不猜已失败 |
| submitted | submitting，phase=evaluating | 服务端已收齐本轮输入，正在确定性/异步评估；尚不代表请求家长复核 |
| pending_review，reason=oral或unrecognized | awaiting_review | 已存在pending review_requests，等待受权家长；不再允许孩子继续写验证 |
| pending_review，reason=late_sync | late_review | 窗口后或租约已到期的证据已进入复核队列，没有自动计分 |
| completed＋有效要求全部满足 | completed，outcome=passed | 按task_requirements和有效证据得到通过；奖励仍独立幂等结算 |
| completed＋要求未满足 | completed，outcome=needs_help | 本轮评估结束但不代表任务完成；孩子可按规则帮助后另开训练或新一轮验证 |
| expired，无pending晚到复核 | expired | 已过租约/时限且没有待复核证据，不能自动通过 |
| expired，有pending late_sync复核 | late_review，underlying_session=expired | 晚到intake保留原存储终态，仅增加复核请求；不重新占用活动验证租约 |
| cancelled | cancelled | 家长取消、任务被替代或内容故障撤销本轮；已写尝试和审计保留 |

submitted只映射“服务端评估中”，不能在没有review_requests时显示awaiting_review。completed的outcome由关联证据与冻结要求计算，不能仅凭status判断通过。结果物化于task_occurrences.completed_at和证据/奖励关联，题单本身不存答案或客户端自报总分。

care_mode的normal/hosted分别映射active/boarding，resting仍为resting；成长baby/young/adult/elder_reserved分别映射juvenile/adolescent/adult/senior_reserved，首版不启用衰老死亡。家长表示“仍未识别”时review_requests保持pending并附review_note，或明确结案needs_help且不产生通过证据，不能把未识别映射approved。复核终态只有approved/needs_help/cancelled，模型的unrecognized是作答机器结果，不混成家长决定。

#### 4.2 暂停与保留机制

内容缺题、错误题或发布撤回使task_occurrences.status=content_blocked，这是任务执行暂停，不是孩子失败；不可改写已发布scope和要求。阻止新验证，保留既有作答/证据，当前本轮由服务取消或结案后等待同目标替代；需要改变范围时发新plan_revision与supersedes_task_id，沿用原奖励资格，不能在原冻结payload中塞新题源。

pending_review是待复核保留态，自动租约过期worker不得将其改expired或删除；它继续占用同task活动验证唯一槽，训练仍可另开。正常流程家长结案后更新证据，session结案completed或cancelled；次日决定仍归原学习日。expired会话的late intake不复活为active，仅新增待复核事实；即使有另一轮完成，原资格唯一键仍防重复结算。

暂停不通过虚构“hold”枚举表达：任务内容暂停用content_blocked，会话人工等待用pending_review，作业等待重试用queued+available_at，宠物托管用care_mode=hosted。各状态在自己的领域内含义固定，暂停解除应有审计和revision，不允许客户端任意更改。

发布任务守卫只冻结定义，白名单明确允许status、completed_at、cancelled_at、revision、updated_at更新；task_scopes和task_requirements没有此白名单，已发布范围和通过条件不可就地修改。

challenge_items冻结题目、目标、题序和选项顺序，不含答案；只允许追加answer_exposed_at提示暴露标记。题单目标要求必须属于同会话task。正式question_type持久值与候选契约完全一致：audio_to_picture、word_to_picture、picture_to_word、oral_reading、sentence_choice、cloze_choice、cloze_text、matching、word_order、reading_choice、retell；P1启用前四种，其他类型由阶段能力开关启用，不能使用word_reading等旧别名入库。private.question_answers将single_choice/text/matching/sequence/manual_review依次展开为option/text/match/order/rubric行，NFC是固定规范化步骤，不作为可配置开关；仅case_sensitive、trim_whitespace、collapse_whitespace、punctuation_mode可配置。

question_versions.public_payload为NOT NULL的版本化JSON object，public_payload_schema_version明确对应应用维护的题型Schema。prompt_text与instruction_text是统一题干/指令的关系列；public_payload补充cloze上下文/缺口、阅读材料和匹配/排序的公开布局配置，不放answer_spec、答案、解析、量规或source_quotes。question_options仍是可提交选项、matching左右项目、word_order词块与媒体FK的关系真源；API组装public_payload中相应项目时校验UUID、side与同题归属一致，不能仅在JSON里定义一套数据库不存在的选项。内容候选按一个主目标落question_versions.objective_id，禁止把objective_ids数组塞入公开配置绕过主目标关系。公开视图包含public_payload与schema版本但不含private答案；嵌套禁止键与每题型布局的完整检查由发布validator执行，数据库顶层禁止键仅作额外防护。

题目是否满足scope、蓝图题型与上下文、选项是否完整排列、答案是否唯一仍由编译/出题检查器核验；数据库对主目标、源内容版本和发布依赖提供关系约束，不能凭SQL CHECK证明自然语言正确。

quality_reports追加记录，题目与资产发布须采用可追溯检查集合。错误题撤回时不覆盖旧answer_attempts；learning_evidence用correction/retraction引用旧证据，唯一后继阻止重复修订；mastery快照重新计算。模型输出、录音转写、复杂检测详情仅保存在受版本schema约束的payload，不用JSON替代家长、孩子、教材、目标、题源、奖励和物品关系。

outbox_events按同事务写入，sequence_no为数据库bigint identity同步游标，payload追加不改而delivered_at可作兼容汇总维护；每个实际消费者的投递事实保存outbox_deliveries，其(family_id,consumer_key,outbox_event_id)唯一键、attempts、available_at、lease与delivered_at独立。不能因一个消费者确认就把其他消费者视为成功。消费者至少一次投递，领域副作用使用自己的业务唯一键。sync_cursors只前进并复合FK引用同家庭outbox。background_jobs以FOR UPDATE SKIP LOCKED和租约领取，失败有限重试；重跑不绕过领域幂等。

#### 4.3 家庭政策、内容问题与AI调用预算

family_settings保存版本号、schema、政策JSON、发布者、effective_from和发布/退役时间；发布后payload冻结，新的设置对未来任务和命令生效，不改旧计划与资格。它只容纳受Schema约束的政策参数，不承担孩子、教材、题目等实体列表。families、children、devices、curriculum_series有revision bigint DEFAULT 1、CHECK>0，数据库守卫要求每次UPDATE递增；API用expected_revision条件更新，维护worker同样遵守。

content_issues通过三个明确可空FK且恰一非空定位question_version/media_asset/source_slice，保存报告孩子或家长、设备、问题类型、说明和处理人。报告出处创建后冻结，处理状态open→triaged→resolved/dismissed并递增revision；替代题须同题族/同目标。题目停用和修订发布另走受权内容命令，报告结案本身不改作答事实或扣孩子奖励。

ai_provider_configs存capability、provider/model、受运维允许的endpoint、secret_ref、白名单选项、币种、日额度、超时和并发上限，不保存API密钥、Token或请求Authorization。secret_ref只是秘密管理器/环境键引用；读取配置的公开DTO应隐藏它或只显示已配置。SQL阻止URL嵌凭据及常见顶层secret字段，服务端还需校验允许列表、DNS/重定向与内网地址防护，不能把正则当完整SSRF防线。

ai_budget_reservations以同家庭provider与generation_run或background_job建立唯一预算预留（run/job恰一），另有reservation_key幂等。预留事务先锁ai_provider_configs行，核验配置revision/币种，累加当日reserved最大金额与settled实际金额，不超过日额度，并校验未决预留并发上限。reserved→settled或released单向结束，费用bigint最小单位且实际额不得超过已批准预留；上游输出/token上限须使最坏费用受预留覆盖，否则先取消尚未发出的调用并重新审批，不能结算后无声超支。

预留过期不等于供应商取消成功。网络结果不明保留reserved并查询供应商请求状态，不能马上释放后用新key重复调用；只有已知未执行/已取消才released=0，已执行用实际费用settled。预算日期按家庭时区形成，保留原date不随时区修改重算；配置额度降低可能低于已有预留，但不撤回既有账。预算行终态不可改或删除，误差补偿由后续审计管理流程处理。

### 18.5 生命周期、留存与删除

所有业务FK采用RESTRICT，避免删除教材或孩子时级联抹去账本/证据。正常业务以归档、退役、录音到期物理删除和元数据保留处理。auth_sessions、配对短码只保存摘要，审计与outbox不写密码、原令牌或私有答案。media_assets删除只更新元数据并清除文件本体，历史证据仍能显示“录音已到期”。

家庭整体清除采用专用离线purge维护角色和审批管理操作：先验证导出/删除请求、撤销会话、停止家庭worker并锁families；创建受控删除manifest；在单独连接事务内临时禁用目标表USER触发器并按依赖从叶到根DELETE；保持FK约束和家庭过滤，恢复触发器后提交；清媒体文件与到期备份。遇到循环FK时可先解除尚未发布且允许清除的可空引用；正式purge脚本需在一次性副本演练。purge角色是表owner或明确授予的维护身份，API/worker无此权限，DDL不提供可由任意请求打开的purge GUC绕过。append-only约束不意味着法律/管理要求下永远无法清除，只是不允许普通业务篡改。
