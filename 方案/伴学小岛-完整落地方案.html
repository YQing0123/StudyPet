伴学小岛
完整落地方案

教材内容、学习证据与宠物生活共用一条可追溯链路，支持家庭自部署与持续更新。

1. 项目定义

一句话：孩子继续用自己熟悉的工具（点读笔、RAZ / 新概念 APP）学生词和课文，回到伴学小岛用同一批内容做训练与验证，验证结果转化为宠物的粮食、成长和生活事件。

核心闭环（七步）

  1. 家长选定教材与范围（如 RAZ《The Bag》第 3–6 页）→ 制定本周每日计划
  2. 系统把原文切成可定位的语义片，绑定学习目标
  3. AI 按蓝图生成候选题，质量门拦截后入库
  4. 孩子照常用点读笔学习，家长确认「今天学了哪几页」
  5. 孩子在小岛完成训练（可帮助）与验证（独立作答）
  6. 验证结果产生掌握标签与复习到期，同时结算奖励
  7. 奖励变成粮食/装扮/回忆，宠物状态随时间推进

产品的不可替代点：不是又一个题库 App，而是「同一批教材内容」的闭环验证 + 有生命感的宠物。少了前者是普通游戏，少了后者是普通刷题。

1.1 可度量验收目标

维度 目标 判定方式
内容可回查 任意一道题可定位到教材页、句、码点区间 抽检 30 题，全部命中
计划稳定性 改计划不重置已发奖励 同一资格重放 50 次，账本不增加

响应性能 儿童端交互 60fps，低配 30fps 不崩 真机性能面板

1.2 差异化位置

类型 代表 强项 缺口
分级阅读 App RAZ / 牛津树配套 内容权威、体系完整 无长线激励，孩子被动
打卡养成 App 各类宠物养成 激励强、粘性高 学习与宠物脱钩，可「只玩不学」
通用题库 各类英语练习 题量大 与孩子实际所学教材不对齐
本项目 — 同一批教材内容 + 有生命感的宠物 + 证据可追溯 内容导入与素材生产是主要成本

护城河不在题量，在三件事：教材版本对齐的精度、验证与证据的区分度、宠物的生命感。三者任一缺失，都会退化成上面某一类产品。

2. 关键设计决策

# 决策点 采用 理由 已否决
D1 美术生产技术 AI 生成高质感立绘 + 自动抠图 + 自动网格变形 保留水彩绘本感染力，且无需手工绑骨 纯参数化 SVG（质感塌陷为贴纸风）
D2 动效引擎 WebGL2 网格变形，Canvas2D 降级 单张立绘即可持续运动，资产极小 逐帧序列（体积×30）、Spine（需人工作业）
D3 宠物换装 分层挂点，不依赖整图 避免重新生成全身 每次换装重出整图（一致性差、成本高）
D4 已学范围来源 家长显式确认 + 可选扫码/拍照辅助 点读笔闭源，无法可靠自动同步 「自动同步点读笔数据」（不可实现）
D5 发音评测 三档置信度，低置信不下「错」结论 误判比不判更伤信任 二元对错
D6 出题生产形态 外部 Agent 出题 + MCP/文件导入 系统不绑定模型，prompt 可快速迭代，成本透明 系统内接模型（换模型即改代码）、内置 Web 出题界面
D7 部署形态 单家庭 Docker Compose + NAS 数据留在家中，运维成本低 多租户 SaaS（首版无必要）
D8 前端框架 React 19 + PixiJS 8 封装 业务与渲染解耦，逐帧不触发 React 重渲染 游戏引擎（教材管理与家长端不合适）
D9 英文字体 Andika（SIL OFL） 专为识字设计，单层 a/g，符合教材习惯 装饰性手写体（字形辨识差）
D10 外部引用方式 自然键（页码/句序/相对路径）由系统解析 agent 会编造 UUID，但不会编造页码 直接传 UUID（必然产生悬空引用）
D11 视频生成 不做 不能交互、不能响应事件、无法换装组合，体积大 用视频做宠物动作
D12 Blender 三维 不做主路线 水彩笔触在 3D 渲染中丢失，复杂度陡增 三维建模做宠物

4. 内容链路

4.1 教材树

出版社 → 系列 → 级别/册 → 单元/课 → 页 → 句 → 语义片
                                    ↘ 媒体（页图、音频）

每层带稳定 ID 与版本号。已发布层不可改，只能发新版本。

4.2 导入

输入 处理 产物
教材 PDF OCR + 版面还原 页图 + 文本块 + 坐标
官方音频 切分对齐 句级音频 + 时间戳
结构化 CSV/Excel 列映射向导 页-句-词三层记录
扫描照片 纠偏 + OCR 同上，低置信标记

导入状态机：uploaded → parsed → reviewed → published，失败可重试，错误隔离在本次导入。

4.3 语义切片

原则：切片是「可出题的最小语义单位」，不是固定词数切分。

片类型 定义 用途
原子片 单个词或固定短语 + 词义 ID 词图识别、词序、拼写
上下文片 完整句 + 前后各一句 阅读理解、完形、复述

每个片必须携带：slice_id、来源角色、原文引文、码点区间。没有码点区间的片不允许出题。

4.4 学习目标

不用「RAZ 级别 = CEFR」这种粗暴映射，也不用年龄推识字量。

目标粒度示例：在《The Bag》语境下，看词识别 bag（词义ID v_bag_01）。

  • 能力：listening / word_recognition / oral_reading / sentence_comprehension / spelling / oral_expression
  • 通道：audio / visual / text / speech
  • 一个候选题恰有一个主目标

4.5 出题与质量门

蓝图（目标 + 允许源片 + 题型 + 难度 + 呈现意图）
  → 模板生成（客观题，确定性）
  → 模型生成（开放题，受控 schema）
  → 结构校验（JSON Schema）
  → 语义检查（答案唯一性、干扰项合理性、原文可回查）
  → 分级发布（P0 自动、P1 人工抽检、P2 必审）

11 种题型已有契约：sentence_choice、cloze_choice、cloze_text、word_order、matching、word_to_picture、picture_to_word、audio_to_picture、reading_choice、oral_reading、retell。

硬规则：公开 DTO 不得包含 explanation、answer_spec、family_id。已用负例验证会被 Schema 拒绝。

4.6 出题成本模型

单本成本 = 题数 × (输入token × 单价_in + 输出token × 单价_out) × 重试系数
变量 RAZ 一本 新概念一课
页数 / 句数 12–16 页，24–40 句 1 课，15–25 句
生成题数 40–60 30–45
单题输入 token ~1,500（切片 + 上下文 + 蓝图 + few-shot） 同
单题输出 token ~400 同
重试系数 1.3 1.3

按中端模型（输入 $2.5/M、输出 $10/M）估算：一本约 $0.5–0.8（3.5–5.5 元）；换低成本模型可降到 0.2–0.4 元。

控制手段：结果缓存（同片同目标不重复生成）、蓝图去重、失败只重生失败项、每家庭并发 1 个生成任务。

生产外置后成本由外部 agent 侧承担，但上述估算仍是单价参考——用于判断走中端模型还是低成本模型、以及一次批量导入是否值得重跑。

4.7 题库生产形态：外部 Agent + 导入

系统内部不接模型。题库的生产完全外置：

外部 Agent（任意模型）
  ① 通过 MCP 读取教材切片、上下文与蓝图
  ② 自行出题（模型与 prompt 由 agent 侧决定）
  ③ 产出 import bundle
  ④ 通过 MCP 或界面上传
  ⑤ 系统校验 → 质量门 → 题库抽检 → 发布

收益：换模型不改代码；prompt 迭代不触碰业务；成本用自己的额度、完全透明；可批量重跑与 diff。

代价：必须有一个 MCP Server；外部输入一律不可信，校验要严。

导入格式

三种入口共用同一套校验：MCP 工具、HTTP 上传、界面拖拽。

bundle/
  manifest.json      批次信息
  candidates.jsonl   每行一个候选题
  assets/            图片、音频（按相对路径引用）

manifest.json

{
  "schema_version": "1.0.0",
  "bundle_id": "01J9Z8K3QW",
  "created_by": "agent:claude-code",
  "library_ref": { "series": "RAZ", "level": "B", "book": "The Bag" },
  "generator": { "provider": "openai", "model": "gpt-5", "prompt_version": "v3" },
  "candidate_count": 42,
  "note": "第 3-6 页，词图识别 + 句子理解"
}

candidates.jsonl —— 每行沿用既有 23 字段契约，但引用一律用自然键：

{"schema_version":"1.0.0","question_type":"word_to_picture","question_family_key":"raz.b.bag.w2p.01","phase":"p1","source_refs":[{"page":3,"sentence_index":1}],"objective_refs":["raz.b.bag.read.bag"],"skill":"word_recognition","modality":"visual","difficulty":1,"estimated_seconds":15,"presentation_kind":"verbatim","prompt_text":"bag","instruction_text":"选出单词对应的图片。","public_payload":{"options":[{"asset":"images/bag.png"},{"asset":"images/cup.png"},{"asset":"images/dog.png"}]},"answer_spec":{"answer_kind":"single_choice","accepted_option_indices":[0]},"explanation":"bag 是书包。","quality_risks":[],"requires_microphone":false,"requires_typing":false}

关键设计：外部只写自然键，系统负责解析成 UUID。

外部写法 系统解析为 为什么
page + sentence_index source_slice_ids agent 会编造 UUID，页码句序不会
objective_refs objective_ids 同上
assets/xxx.png asset_id 按内容哈希注册，天然幂等
accepted_option_indices accepted_option_ids 按 options 顺序映射

解析失败不猜测，直接拒绝并给出行号与原因——agent 据此修正后重跑。

5. 教材来源与已学范围

5.1 可用资源评估

点读笔配套资源是本项目最被低估的资产。按可用性分四类：

资源 价值 用途 可用性
原版朗读音频 ★★★ 听力题、发音示范、跟读比对 直接可用，质量远高于 TTS
教材扫描页图 ★★★ 页级定位、词图识别素材、家长端对照 直接可用
点读码表 / oid 表 ★★★ 天然的「页 → 句 → 音频」索引，切片自动化 需确认格式是否可解析
铺码 PDF ★★ 反推词/句边界与位置 需工具解析
点读笔本体 ☆ 无法自动同步进度（闭源），仍需家长确认 不作为数据源

结论：点读笔资源很有用，但价值集中在音频、页图、码表三项，不在「自动上报进度」。

最值钱的是点读码表。点读笔的工作原理是「点击位置 → oid → 播放对应音频」，这份映射本质上就是 页号 + 句子位置 + 音频文件 的三元组。拿到它，语义切片与音频对齐可以从「人工校对」变成「程序生成」， 是整个内容链路的加速器。

需要确认的三个问题：

  1. 手里是点读笔配套的整包资源（含 oid 码表），还是只有 MP3 音频？
  2. 码表格式是什么（.oid / .bnl / .bpi / Excel 码表 / 内嵌在铺码 PDF 里）？
  3. 音频是按句切分还是整页一条？

第 3 点尤其关键：整页一条音频需要强制切分，按句切分则直接可用，工作量差一个量级。

5.1.1 小达人 .dab 实测结论

对实际样本（376 MB，单个 .dab）做了只读结构分析，结果如下。

可确认的部分

位置 内容
0x00 魔数 deb3
0x04 GBK 编码的书名（如「吴明兰55」）
0xC8 包 GUID {7BEEA67A-…}
0x12A 制作者 Administrator
0x14E 数值 55，与文件名中的编号一致
0x18A Create by Builder 2019-08-02 14:56:27
末尾 EOID 结束标记，紧邻 8 KB 的 BOID…EOID 区间
0x15A 16 字节随机值，疑似密钥或 IV

不能确认的部分

目标 实测 判断
音频流 正文熵 6.99–7.97，接近随机；zlib/gzip/MP3 签名出现次数等于随机期望 已加密，非明文音频
码表 BOID…EOID 区间 8 KB，99% 为零，无递增整数序列 不是完整 OID 表
块结构 无固定周期、无可复用块头 单一加密流

结论：属于路径 C —— 不能直接解包。

5.1.2 因此采用的方案

不逆向 .dab。理由不是技术难度，而是三点：解密属于规避技术保护措施，存在法律风险； 不同 Builder 版本密钥可能不同，维护成本高；一旦失效就阻塞整条内容链。

改为三条合规且可落地的取音途径：

途径 质量 工作量 说明
教材配套 MP3 高 低 首选。RAZ / 新概念等常见教材多配有官方音频
点读笔录音采集 中 中 播放点读笔 → 高保真录音 → 按静音切分，自用合规
TTS 合成 低 低 仅用于兜底，不适合作为主要朗读来源

对产品的影响

点读笔的码表拿不到，意味着「页 → 句 → 音频」的自动对齐不能靠它。 退回方案默认路径：家长勾选页码 + 音频按句切分。产品闭环不受影响，失去的只是一个加速项。

仍然可用的点读笔价值

孩子继续用点读笔学习这件事本身不变。点读笔是学习工具，不是数据源—— 应用不依赖它的数据，只依赖家长的确认。这也正是 5.3 的设计前提。

5.2 版本一致性

这是内容链路最容易翻车的地方。

风险 后果 对策
同一本书存在多个发行版本 页数、句子编号不一致，切片对不上 首次导入时生成「版本指纹」并锁定
音频与文本版本不匹配 听力题播了另一版内容 指纹绑定音频时长与句数校验
点读码表版本与手中教材不一致 oid 对错句 抽样试听 5 页人工确认

版本指纹：sha256(页数 | 每页句数序列 | 首末句文本 | 音频总时长)。 指纹不同的资源不允许混入同一 unit；需要并存时建独立版本，已产生的学习记录不受影响。

5.3 已学范围的形成

方式 操作 适用 可信度
家长勾选 在教材树上点选今天读的页 默认，零设备要求 高（家长负责）
扫码/拍照 拍教材页，OCR 定位到版本与页 减少操作 中（依赖版本指纹）
点读笔音频指纹 用点读笔录音与官方音频匹配 未来增强 低（首版不做）

流程：家长确认 → 写入 contact_declaration（孩子、日期、教材版本、页范围、来源方式） → 计划编译时据此生成当日任务 → 训练/验证只针对已声明范围。

边界：不声明则不出题；声明与实际学习不一致时以最后一次确认为准，并保留历史供复习。

6.1 风格锚定

令牌 值 用途

风格：温暖绘本 × 轻量生活模拟。避免做成家长统计仪表盘，避免无意义漂浮粒子。

6.2 三条生产技术路线对比

路线 审美上限 自动化程度 换装 资产体积 结论
A 参数化 SVG / PixiJS Graphics 低（扁平矢量） 高 好 小 不作为主路线，仅用于图标与道具
B AI 精灵图序列 高 中（需状态一致性校验） 差（需逐帧挂点） 大（×30） 用于状态切换（吃、睡、生病）
C AI 立绘 + 自动网格变形 高 高（实测可行） 中（分层挂点） 极小 主路线，承担持续生命感

选型结论：以 C 为日常表现主力，B 补离散状态，A 做 UI 图标。三者共存，不互相替代。

6.2.1 视频与三维的取舍

方案 结论 理由
图像生成 主力，全部静态资产 质感最好，可控性最高，成本最低
视频生成 不做 视频无法交互、无法响应点击/喂食/生病等事件，不能换装组合，体积是图片的数十倍；且已有网格变形提供连续运动。唯一可能的例外是相册里程碑的短片段（纯播放、不参与交互），P3 之后再评估
Blender 三维 不做主路线 水彩笔触属于二维绘画语言，三维渲染会丢失笔触与纸感；引入三维后要多做建模、材质、骨骼、导出与性能验证，收益不抵成本

唯一保留的三维场景：如果未来需要宠物真正转身（侧身、背面），二维镜像不够用，可单独评估用 Blender 预渲染四方向序列帧。这是 P3 之后的可选项，不进入首版。

这意味着：首版全部美术产出来自图像生成，一条链路、一套工具、一种校验，不引入第二个生产体系。

6.3 生产工序（六步，全自动）

① 白底生成    AI 出图，纯白背景，同一参考图锁定身份
② 自动抠图    边缘泛洪 + 距离羽化 → 干净 alpha
③ 规格校验    透明边缘、包围盒、主色、尺寸档
④ 分层拆分    围巾/帽子挂点层单独出图
⑤ 网格生成    按 alpha 轮廓自适应网格（57×85）
⑥ 打包发布    清单 + 哈希 + 原子切换

关键实测结论：图像服务不输出真实透明通道——所谓「透明背景」是把棋盘格画进 RGB。因此第②步是必经工序，不能用「生成时就透明」替代。

抠图实现：对四边连通的近白区域泛洪（只清除外部，保留角色内部高光），再对 alpha 做小半径均值羽化。实测输出 644×962、透明 29.8%、半透明边缘 4.8%，边缘干净无白边。

7. 动效实现

7.1 原理

单张立绘铺成细分网格（57×85 = 4,845 顶点，9,240 三角形），在顶点着色器里按区域权重施加位移：

权重区 判定 承担动作
头部 上半部平滑过渡 转向、点头、倾斜
耳朵 头部两侧 滞后跟随
尾巴 左下区域 摇摆
下半身 底部 呼吸起伏、弹跳
眼部带 中上部条带 眨眼压缩

这是「不绑骨、不拆件」的关键：位移是 uv 空间函数，权重由坐标计算，无需人工标注关节。单一纹理不存在接缝问题。

7.2 实测数据

指标 实测值
网格 57×85 顶点 / 9,240 三角形
软件渲染（SwiftShader，无 GPU） 34 fps @ 1176×932 CSS px，DPR 2
预估真机（iPad GPU） 60 fps，余量充足
单帧 draw call 1
纹理显存 约 2.4 MB（644×962 RGBA + mipmap）
动画资产体积 立绘 900 KB，无序列帧

7.3 状态机

待机 idle ──指针进入──> 注视 look ──指针离开──> 待机
   │                     │
   ├──点击头部──> 摸头 pat ──> 待机
   ├──喂食事件──> 进食 feed ──> 满足 content ──> 待机
   ├──夜间/事件──> 入睡 sleep ──> 惊醒 wake ──> 待机
   └──健康事件──> 生病 sick ──> 就诊 hospital ──> 康复 recover ──> 待机

约束：状态切换由服务端权威快照 + 已提交事件驱动，动画回调不改业务状态。

7.4 动效规格表

动作 时长 曲线 打断 说明

统一约束：单动作位移不超过画面高度 6%；同时活动动作不超过 3 层；连续点击合并不叠加。

7.5 降级策略

层级 条件 表现
L0 完整 WebGL2 可用 网格变形 + 全部动作
L1 降级 WebGL2 不可用，Canvas2D 可用 分层位移/缩放，动作简化为 4 种

9.1 训练 / 验证分离

标签 条件

9.4 发音评测三档

置信度 处置 给孩子看到
高 自动判定 通过 / 某个音再试一次

人力假设：1 名全栈 + 1 名后端可并行；素材与内容生产由脚本承担，不设动画师岗位。
