# 伴学小岛：开源参考与内容体系优化报告

## 1. 优先决策

保留“同版本教材→周日计划→外部学习→内部训练验证→宠物生活”的主线，将教材内容工作台与题目质量生产提升为首版核心。宠物负责情感与动机，内容系统负责学习范围、题目正确性和证据，两者通过受控事件连接。

建议采用组合复用：从Lute借鉴内容与词条管理，从Anzo借鉴家庭部署、内容检查和纠错，从TypeWords借鉴按句训练，从Finch和Study Bunny借鉴陪伴与空间建设；核心奖励账本、教材范围与验证证据仍按本产品需求实现。没有理由仅为了宠物养成就整体改造一个成人背词或习惯打卡系统。

本次核验的项目中，未找到已证实同时覆盖教材对齐、家庭计划、学习验证、宠物生活、NAS、多端和免手工素材生产的现成应用。现成库可以减少基础设施工作，不能替代教材内容与儿童体验的专门设计。

| 优先级 | 应做调整 | 价值 |
|---|---|---|
| P0 | 建立教材来源、导入、切片、目标与版本链 | 保证学的和考的是同一内容 |
| P0 | AI候选题、检查、发布与挑战组题分离 | 防止未经检查的即时结果影响奖励 |
| P0 | 已学声明、训练参与、验证证据、掌握趋势分开 | 不把排计划或计时当作学会 |
| P0 | 试做一只自动生产宠物与一周真实教材 | 同时验证最难的两条生产链 |
| P0 | 修正喂食事务、饱腹上限、题目变式与设备回退 | 消除规则冲突和兼容性假设 |
| P1 | 家长内容问题收件箱、版本撤回和批量修复 | 让持续更新可以维护 |
| P2 | 自适应复习、ASR与专业发音评测试验 | 在有效数据与真机验证后增强 |

## 2. 开源英语学习项目

### 2.1 精选对比

| 项目 | 已核实能力 | 可复用/参考部分 | 不直接作为整体底座的原因 |
|---|---|---|---|
| [Lute v3](https://github.com/LuteOrg/lute-v3) | Python/Flask独立Web应用，文本学习、语言与词典配置、词条/多词短语、父词条及词图 | 优先参考教材文本、语境、词形/词义、例句和词条关联；MIT代码可评估局部复用 | 以阅读学习为中心，缺少本产品周计划、儿童题型验证和宠物规则；其数据模型不自动提供精确教材版本映射 |
| [Anzo](https://github.com/eduardwichner/anzo) | 家庭自部署、浏览器/平板使用、多账号、多题型、管理员纠错、音频检查、内容包校验与进度 | 最值得参考内容源→生成题包→校验→原子更新→纠错回滚的结构，参考家庭运维状态页 | 个人项目、维护规模小且不承诺支持；现成课程面向其他母语背景，不对应RAZ/新概念；内容和依赖许可不等于全部MIT |
| [TypeWords](https://github.com/zyronon/TypeWords) | 词汇练习、跟打/默写/自测、文章导入、按句输入与发音、错词和掌握集合 | 参考句段训练、文章与词汇互相定位、错题与训练反馈；GPL代码可在满足许可时复用 | Nuxt技术栈、键盘输入导向；本地数据跨设备要处理备份；触屏低龄和电视不能照搬 |
| [Qwerty Learner](https://github.com/RealKai42/qwerty-learner) | React单词记忆、音标发音、章节默写、词库JSON与导入索引 | 参考简单词库规范、错误反馈与练习组织；GPL代码可评估 | 面向键盘工作者；内置词表不等于完整教材内容，词形输入不等于听说能力 |
| [Enjoy / 人人都能用英语](https://github.com/ZuodaoTech/everyone-can-use-english) | 官方仓库提供学习软件源码与训练文档；README当前展示网页、电子书、闪卡、课程和浏览器插件方向 | 参考材料驱动练习、媒体/句段组织与学习工具组合 | GPL代码；线上服务能力是否与仓库完整对应需进一步核对，不能仅凭网页截图宣称新版全部可复用 |
| [OpenPronounce](https://github.com/Halleck45/OpenPronounce) | 参考文本＋录音的音素/单词分析、CLI/Python/API、Docker，代码MIT | 作为后续自托管发音反馈研究候选，可对家庭样本测试 | 作者明确披露童声、强口音、噪声影响以及误报问题；非首版自动通关裁判，模型和TTS依赖需另审 |

[Lute手册](https://luteorg.github.io/lute-manual/)明确列出多词条、父词条和词图，适合改善本方案“同一单词不同词义/词形”的结构。[Qwerty的词库导入说明](https://github.com/RealKai42/qwerty-learner/blob/master/docs/toBuildDict.md)使用词条JSON及索引，便于批量处理，但不足以承载页图、原句、音频片段、题源和能力证据，不能直接当教材schema。

[Anzo架构文档](https://github.com/eduardwichner/anzo/blob/main/docs/developer/architecture.md)值得优先阅读：其源内容、确定性题目生成、Ajv跨字段检查、稳定ID锁、音频manifest、服务端判分、内容原子重载和历史完整性检查，都是本项目可落地借鉴的组织方式。其服务流程与安全实现仍需代码审查，文档列出某项检查不等于已经满足本项目奖励幂等与反重放要求。

### 3.1 新增的产品优化

外部APP已做测验或已有奖励时，内部验证采用短抽样、薄弱项优先或家长认可的已有证据，不重复要求整套训练。没有平台接口时不把截图OCR或计时伪装成官方成绩。

学习时段、必要照护、自由装扮和静态查看分开配置。允许等待家长复核的孩子查看完成记录，基础托管不被学习门禁锁死；装扮预览不消费，保存可撤销，电视采用槽位选择。

宠物成年后用新发现、共同相册和少量生活故事延续意义，避免只能不断加高材料价格。不同年龄孩子的题量与速度不直接决定生存资源，先保证完成各自合理计划的基础供给公平。

### 4.1 素材路线的调整

纯参数化角色继续作为可确定重建的基础路线，但不应过早排除AI参考图精灵图。可以用同一只宠物与相同互动比较：程序部件动画、参考图分状态生成精灵图，两者都经过自动检查与重试。

hatch-pet值得借鉴的重点是“图像模型负责视觉，确定性程序负责几何与打包”，而不是让模型一次生成精确可用图集。它现成的失败、等待、工作等状态不直接映射儿童学习表现；须重新定义温和的动作词汇，并增加进食、睡眠、饮水和康复。换装若采用整套精灵图会产生组合成本，应单独定义挂点和遮挡或限制为少量套装。

素材AI在隔离构建环境操作，无家庭隐私与生产密钥；生成的代码不在儿童客户端任意执行。失败重试有预算上限，不能以“必须无人操作”为理由发布不合格资产。用户只评审喜好，不负责修图绑骨。

| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | 后续 | 可选本地ASR worker，平台独立适配 | 发音音素评分、童声准确率、说话人身份 |

首版保持React/TypeScript/Vite＋Fastify＋PostgreSQL＋Docker。内容工具放导入/生成worker，不常驻挤占NAS；不因采用AI出题就强加向量库、LangChain、Redis、整套H5P平台和实时三维引擎。

### 5.1 版本与设备陷阱

2026-11-06核验npm发布元数据：[@pixi/react 8.0.5](https://registry.npmjs.org/@pixi/react/latest)要求React>=19、PixiJS ^8.2.6；[XState 5.33.3](https://registry.npmjs.org/xstate/latest)为稳定发布，官网alpha文档不应直接混用；[ts-fsrs 6.0.0](https://registry.npmjs.org/ts-fsrs/latest)要求Node>=24。开发时锁精确版本并再次核验，不把文档main分支等同已发布兼容范围。

[PixiJS当前v8渲染器指南](https://pixijs.com/8.x/guides/components/renderers)将WebGL列为推荐，WebGPU为实验，CanvasRenderer为coming-soon。首版低配回退应采用独立DOM/SVG静态或低动效视图，不能承诺自动切Canvas就兼容所有电视。

[whisper.cpp](https://github.com/ggml-org/whisper.cpp)提供CPU、量化与Docker入口，但浏览器录音仍需格式探测、解码与资源限制，NAS速度要实测。[OpenPronounce](https://github.com/Halleck45/OpenPronounce)是发音研究候选，作者明确披露成人训练语音对童声的局限和误报，不用它未经校准的分数决定孩子是否拿到食物。

## 6. 教材内容生产与管理

### 6.1 可扩展数据结构

统一模型为“教材系列→版本→层级内容节点→源片段→学习目标”。RAZ和新概念用适配映射配置，其他绘本、学校课本和家庭原创内容也映射到同一结构。新增教材不应修改宠物、奖励和挑战业务代码。

教材原文、目标词义、教学能力、题目、孩子证据分别保存。同一个单词的不同词义不合并；同一词义的听辨、词形识别、朗读、拼写也不合并成一个掌握值。原图、教材音频和合成示范明确区分。

### 6.2 原文来源与导入

真实教材从可合法使用的文档/结构化包进入；AI可以提取、对齐、标注与切片，不能靠“记得某课”生成原文。AI原创扩展内容另立教材类型。

导入支持结构化JSON/ZIP、XLSX/CSV、纯文本，PDF/EPUB/DOCX和扫描图通过可选worker。保存原文件摘要、页码、阅读顺序、文字坐标、音频时间片和提取结果。重复导入先比较版本和内容摘要，显示新增、重复、修订和缺失项，不原地覆盖。

导入任务有进度、失败原因、暂停重试和按单元发布；异常片段进入隔离区，不拖累已完成内容。原文件只读，提取文本与规范化文本分开；修订产生新版本并显示受影响计划与题目。

### 6.3 语义切片

按完整页段/对话保留上下文，再将句子与目标词作为可选择原子片。图片相关信息与音频片段随语义绑定。代词、问答和否定句不被机械字数切片割断。

SourceSlice必须可回答：来自哪个版本、哪本书/课、哪页/句、依赖哪段上下文、哪些图片/音频、所含词义与目标、源内容摘要和切片版本是什么。

首版先按计划ID精确筛选，再按需要带入上下文；不用向量相似度决定学习范围。未来语义检索也先做版本和范围过滤。

## 7. AI出题与挑战生产

### 7.1 生产流程

教材原文入库→语义切片→学习目标蓝图→AI生成候选题→schema和领域规则检查→语义复核→可执行预览→发布题库→今日计划组题→孩子作答→验证证据与复习更新。

AI出题是后台生产能力，挑战组题是受规则约束的运行能力。二者分离后，可以批量扩充、失败重试和控成本，也能在模型不可用时正常训练。

### 7.2 出题输入与输出

| 对象 | 必需内容 |
|---|---|
| 输入范围 | 已发布教材版本、选中片段、必要上下文、允许复习范围 |
| 教学蓝图 | 所测目标、能力类型、题型、难度、孩子识字/拼写前提、设备输入方式 |
| 词汇约束 | 目标词义、已学干扰词、语言变体、不得增加的理解前提 |
| 题目输出 | 题干、稳定选项ID、答案/允许答案集合、解释、提示、媒体引用 |
| 可追溯信息 | 具体源句ID与证据摘录、原文/变式标签、question_family_id |
| 生产记录 | model、prompt/template版本、源摘要、成本、检查报告、发布时间 |

基础客观题优先由可靠模板抽取/组装，AI补充多样性和核对；理解题和情境表达由AI生成但需要更严的质量门槛。不要让模型自由生成评分代码。

### 7.3 自动质量门槛

检查引用和scope、源句忠实性、单选唯一性、填空多解、词图/音文一致、指令是否泄题、难度与能力前提、训练暴露和题目家族重复，以及目标设备可操作性。

复核模型先依据源文独立答题，再比较答案并报告歧义。模型一致只降低风险，不构成无误证明。低风险且可确定校验的模板题可按启用策略自动发布；不确定源文、开放题与分歧项隔离等待确认或重生成。

标准反例要覆盖：blue图同时出现多种颜色、a/an空格多解、bag/bags评分目标混淆、否定句遗漏not、代词缺上下文、听力提示念出阅读答案、缩写与等价答案、选项仅换序却当独立新题。

### 7.4 一个可检验的小例子

家庭自编源片段：“This is my bag. It is blue.”。当天只选这两句与bag、blue。可生成bag词图关联、blue颜色识别、原句朗读或听句选图，源句关系保持可查。

“The bag is under the table.”不能成为当天必需验证，因为under the table未在所选材料和已学范围中。即使模型觉得“题目很简单”，也不能越过scope。

“Whose bag is it?”涉及my的归属理解，如果当日蓝图只测bag词形识别，应单独标记所测能力或不用。出题依据不仅是文本相似，还必须符合能力目标。

### 7.5 场景调用与错误修复

医院、公园和小家调用同一题库与证据系统；场景传目标和允许范围，不直接生成一条任意题决定治疗或发奖。缺题时同目标替换、转帮助或暂停，不拿超纲题凑数。

题目报告后先停用受影响版本，再生成修订并回归。已经作答的孩子保留原题快照和修正说明；无效证据可修订，不追扣已获材料，不把教材或题目错误算孩子失败。

## 8. 已学内容与学习证据

| 状态/事实 | 由什么产生 | 是否证明掌握 |
|---|---|---|
| 已计划 | 家长选定范围并发布计划 | 否 |
| 声明已学 | 孩子在原工具学习后确认实际页句，或家长导入历史 | 否，保存来源 |
| 已训练 | 应用内实际练习、试听、提示与跟读事件 | 仅说明参与与帮助程度 |
| 已验证 | 客观判分、经校准评估或家长确认，绑定能力与题源 | 本次证据 |
| 掌握趋势 | 多次有间隔且能力相符的证据汇总 | 支持当前趋势，非永久保证 |

“已学集合”由真实学习声明/来源记录形成，计划过去不自动加入。历史学过内容可用勾选书课初始化，不补发过去奖励，也不自动标全会；必要时安排短诊断。

医院应该从已经接触、当前适合且需要复习的范围抽取，而不是只从答对过的题抽取。否则最薄弱内容反而永远不进入复习。

## 9. 现有方案覆盖与缺口

| 领域 | 原有覆盖 | 优化结论 |
|---|---|---|
| 同教材与页句scope | 已有明确主线 | 保留，增加通用教材适配与source slice |
| 导入与版本包 | 已有导入/发布描述 | 补导入job、差异预览、原文对照、隔离、稳定ID与撤回 |
| AI出题 | 原偏向题目草稿 | 提升为后台生产主线，加入蓝图、复核、质量报告和成本缓存 |
| 已学与掌握 | 已区分学习/验证/掌握概念 | 补可执行事实来源、历史初始化和医院候选规则 |
| 题型与通过条件 | 已有多题型和人工兜底 | 明确分母与必需能力，不能总分掩盖未测能力 |
| 周计划 | 已有周日安排与窗口 | 补draft/validated/published编译、稳定奖励资格、改计划分母规则 |
| 宠物生命与情绪 | 已覆盖身体状态、成长与场所 | 继续，新增成年后故事与非交易化陪伴 |
| 饱腹与消费 | 事务描述和动画文案冲突 | 统一服务端先提交后表现，食物份额未吃下部分保留 |
| 自动素材 | 已有程序化角色路线 | 补hatch-pet试验路线、包构建契约、重试停止和隔离执行 |
| 电视与低配 | 已有遥控和伴侣录音 | 补WebGL能力矩阵、独立静态回退，不能假定Canvas自动可用 |
| 离线与多设备 | 已有服务端账本与待同步 | 补租约/修订号、迟到提交、次日复核归原学习日 |
| 家长维护负担 | 已有计划和录音复核 | 补问题收件箱、批量发布/修复、成本与导入状态 |

## 10. 下一阶段的验证顺序

先做一周内容生产样本：RAZ实际版本的若干页和新概念实际版本的一小段课文，完成导入、对齐、切片、目标蓝图、AI候选题与检查报告。包含故意错误和缺媒体样本，验证确实会阻止发布。

再做两个素材样片：参数化角色与参考图精灵图采用相同场景、动作和围巾，比较生成稳定性、重试成本与设备表现；两者都不要求用户手动修图。选定一条主路线后再扩大素材量。

随后把真实iPadHTTPS录音、目标电视遥控/回退、双设备重复提交和次日复核接入最小闭环。P0通过后重新估算首版工期，不把尚未验证的自动内容与动画生产成本藏在原估算中。

首版不追求整套RAZ/新概念一口气入库。先证明增加新书、改一条源句、撤回一道错误题、升级一个宠物包，都不需要重写业务，也不破坏孩子已有记录。可持续更新的正确链路，比首发数量更重要。
