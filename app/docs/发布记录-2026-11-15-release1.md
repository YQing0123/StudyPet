## 数据保护与部署细节

仅短暂停止本项目容器，复制原 Compose 及完整 data。辅助容器逐文件比较冷备和停止后的原目录，完成冷备 SQLite 完整性检查，再生成权限 0600 的 `banxue-consistent.sqlite` 并再次检查完整性；全部成功后才更新 Compose。辅助容器已清理，上一版本镜像和冷备保留。

fnOS 当前 Docker 客户端的镜像导入参数为 `filePath`。首次使用 `path` 时请求失败，确认镜像不存在后按设备客户端实际参数修正；第二次请求虽仍返回代理错误，但后续只读 inspect 确认导入成功，没有重复导入。归档在 NAS 上的 SHA-256 已独立验证。

本机 Docker 使用 OCI 镜像索引，inspect 的顶层 ID 与 NAS 的镜像配置 ID 不同。验收以离线包内配置文件实际 SHA-256 和全部 RootFS 层为准，二者均与 NAS 一致，不将索引摘要误作配置摘要。

Git 代码回退与业务数据库恢复是两项操作。回退前应先检查当前数据与旧代码的兼容性并备份最新数据，不应直接用发布前整库覆盖发布后的真实业务记录。
