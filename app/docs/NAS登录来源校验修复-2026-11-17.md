# NAS 登录来源校验修复

## 原因

2026.11.16-release1 将公网 API 请求限制为配置的 HTTPS Origin。内网 IP 本来不在允许地址中；公网 NAS 转发链路也改写了 Origin，导致正式域名登录请求在验证账号前收到 403「请求来源不受信任」。先前上线只验收登录页读取，没有执行登录 POST，未发现这个兼容问题。

实测：携带正式域名 Origin 的登录空对象，经内网直连到达账号字段校验（400）；同一请求走公网转发却收到来源拒绝（403）。只提供正式 Referer 时公网可到达字段校验，说明转发后的 Origin 与预期不符。

## 修复

保留精确公网 Origin 校验。对于被转发改写 Origin 的浏览器请求，仅在 `Sec-Fetch-Site: same-origin` 且 Referer 的 origin 精确等于配置的 HTTPS 地址时允许；单独 Referer、same-site、cross-site、不透明 Origin 和非正式来源不能绕过。浏览器不能由网页脚本自行设置 Fetch Metadata 与 Referer。正常 Cookie、认证、JSON 类型、角色及到期校验保留。

站点 Referrer-Policy 从 no-referrer 改为 same-origin，使同源 API 保留 Referer，跨站仍不发送。独立通知照片继续使用 no-referrer。错误提示明确给出正式入口 https://studypet.iepose.cn 。HTTP 内网 IP 不作为登录入口，因为正式会话使用 Secure Cookie。

## 验收

新增隔离回归覆盖 NAS 改写、缺少 Fetch Metadata、错误 Referer、same-site/cross-site 和 opaque/null Origin；47 项订阅/安全测试通过。完整回归及真实公网浏览器登录 POST 随发布补记。
