# 宠物素材是怎么做出来的，以及如何修复

这份说明回答三件事：原程序的素材到底怎么来的、我们为什么会出现「原来看起来正常、网页里不正常」、后面新增宠物应该怎么生产。

## 一、原程序的素材构成

逆向结论（见 `MengChong_Research_20261111/research/研究报告.md`）：

- 全部动作是 **预制视频**，不是骨骼、Live2D、Spine 或 3D 模型。
- 视频统一 **VP9、512×512、24/30fps、0.7–5.042 秒**，共 227 条（226 个 `.webm` + 1 个备份）。
- 每个品种有 6 张姿态 PNG：`sit / walk / jump / sleep / stretch / roll`，用于待机、回退和视频缺失时的兜底。
- 动作视频分三类：
  1. **alpha 直穿**：`*.alpha.webm`，视频自带 alpha 通道；
  2. **绿幕**：用 `dom = g - max(r,b)` 实时算透明度；
  3. **蓝幕**：用 `dom = b - max(r,g)`，绿羽鸟、蓝壳龟必须用蓝幕，否则身体会被抠穿。
- 动作不是实时生成，而是 **片头/循环/片尾/倒放片** 拼出来的：
  - 走路：`walk-start → walk(loop) → walk-stop`
  - 摸头：`petted → petted-out`
  - 吃饭：`eat ↔ eatrev` 乒乓
  - 睡觉：`sleep` 播一次定格，醒来播 `wake`
  - 照顾：`feedcatch / play / hug`

## 二、写实 vs 卡通

两类素材的生产链其实是同一条，只是风格提示不同：

| 类型 | 画面来源 | 动作来源 | 抠像 |
|---|---|---|---|
| 写实猫狗 | AI 生成的写实静帧/视频 | 图像转视频，按动作提示生成 3–5 秒片 | 绿/蓝幕或离线 alpha |
| 水彩卡通鸟龟 | AI 生成的水彩插画静帧 | 以静帧为参考做图像转视频，保持同一构图 | 绿/蓝幕或离线 alpha |

原程序源码注释里提到“豆包生成源片、ffmpeg 制作倒放片/平移补偿、离线连通域抠像”。这说明作者用的是 **生成式视频 + 后期工具链**，不是手工逐帧画。

**所以新宠物不是“画一套骨骼”，而是“生成一套风格统一的静帧 + 每组动作一段短视频”。**

## 三、新增一只宠物的工作流

### 1. 定风格圣经

写一页角色设定：

- 品种、体型、毛色、眼睛颜色、耳朵/尾巴特征；
- 画风：水彩/厚涂/赛璐璐/写实；
- 相机：正面、平视、固定机位、主体占画幅 60–75%；
- 背景：纯绿 `#00B140` 或纯蓝 `#0047BB`，不要阴影、不要渐变、不要地面；
- 光：柔和顶光，避免高光过曝和纯黑区域。

### 2. 生成 6 张姿态

用同一角色参考图生成：

```
sit, walk, jump, sleep, stretch, roll
```

要求：同一角色、同一画风、同一画幅、同一脚底线；不要文字、水印、地面、道具。输出 512×512 PNG，透明底或纯色底。

### 3. 生成动作视频

以姿态图为参考，逐条生成：

```
walk-start, walk, walk-stop,
greet, petted, petted-out,
eat, eatrev?（可由 eat 倒放）,
sleep, wake,
feedcatch, play, hug
```

约束：

- 512×512，24fps，3–5 秒，固定机位，不要镜头运动；
- 主体始终完整入画，脚不超出画幅；
- 走路要“头朝向 = 前进方向”，否则会倒退；
- 特写动作（摸头）保持和走路同一体型，避免切换时忽大忽小；
- 纯色背景，主体边缘不要有半透明阴影。

### 4. 抠像与验收

- 绿/蓝幕：实时键控即可；检查边缘是否残留绿边/蓝边。
- 带透明道具（球、碗、纸）的动作，优先走 **离线 alpha**；但离线抠像容易把 **黑色/白色/高光** 误删，必须逐帧检查。
- 验收三张底：浅色、深色、纯绿。只看白底会漏掉白边/黑块。
- 用 `alpha>0` 的连通域检查：
  - 主体外是否还有孤立色块；
  - 主体内是否有被误删的透明洞；
  - 脚掌、眼睛、道具是否完整。

### 5. 量尺寸补偿

新宠物必须量：

- 坐姿身体 bbox；
- 走路片身体 bbox；
- 每个动作片主体 bbox；
- 素材自然朝向（朝左/朝右）。

然后填 `FR_COMP / VD_COMP / ACT_COMP / CARE_COMP / WALK_FACING`（见 `web/src/mvp/breedConfig.ts`）。不填就会出现“摸头突然变大”“走路比坐着大”“往前走位置倒退”。

### 6. 打包

```
breeds/<breed>/frames/frame-*.png
videos/<breed>/<action>.webm
avatars/<breed>.png
manifest.json
```

`scripts/copy-pet-assets.mjs` 会自动生成 manifest，并按文件名判断 alpha/绿/蓝模式。

## 四、为什么原来看起来正常，网页里不正常

有三个叠加原因：

1. **原程序的桌面背景更暗/更花**，白色纸边、灰色阴影、透明洞不明显；我们的水彩书房是浅色，问题被放大。
2. **原程序也会遇到同样的 alpha 缺陷**。例如柯基 `play.alpha.webm` 的小球黑色条纹在源文件里 alpha=0，这不是我们实时键控造成的。
3. **我们自己的修补引入过新问题**：为了清柯基右下的纸边，误删了狗的左前脚像素，导致“前脚透明”。现在已回退，只保留瞳孔修补和外圈纸边清理。

结论：**先判断是源素材问题还是渲染问题，再修；不要用大范围颜色阈值直接抹 alpha。** 任何修补都要在浅色、深色、绿色三种底上验收。

| 品种 | 问题 | 处理 |
|---|---|---|
| 柯基 | 瞳孔偏灰像空洞；右下纸边；play 小球 alpha 有洞 | 瞳孔已修、纸边已清、play 改用 PNG 打滚帧 |
| 金毛 | 坐姿脚下有白色椭圆投影/纸边 | 待逐帧清理 |
| 德牧 | 右下黑色素描块 | 待清理 |
| 布偶 | 右下白色纸边 | 待清理 |
| 黑猫 | 脚边灰色投影 | 可保留为阴影，必要时清 |
| 鹦鹉/鸽子 | 栖木两端有背景残留色块 | 待逐帧清理 |
| 龟类 | 脚边深色阴影/描边 | 可保留为阴影，必要时清 |

**当前建议**：16 个品种的素材与引擎已经接入，但只把 4 个重点品种（橘猫、柯基、虎皮鹦鹉、巴西红耳龟）作为“已验收”；其余 12 个在逐帧清理完成前，不建议作为默认推荐。

## 六、修复工具建议

- `ffmpeg -c:v libvpx-vp9 -pix_fmt rgba` 解码 alpha 帧；
- Python + Pillow + SciPy：连通域、闭运算、距离变换；
- 修补 alpha 时只用 **局部 ROI**，不要全图阈值；
- 修补后重新编码：`libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -metadata:s:v:0 alpha_mode=1`；
- 每只宠物生成三底 contact sheet，人工过一眼再入库。
