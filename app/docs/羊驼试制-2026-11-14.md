# 羊驼试制：单年龄一只新宠物

本轮按用户指定使用宿主 image 2.6 高精版（`gpt-image-2.6-sunburst` / high，2048×2048），新建一只可领养、可更换的卡通羊驼 `alpaca_toon`，新增物种 `alpaca`，项目可选品种由 18 增至 19。本轮只做单年龄，不包含六阶段成长外观。

## 结果

- 角色：奶油白绒毛、沙杏色背斑、香蕉耳、深棕眼、粉色腮红，水彩绘本风，三分之四朝右，固定机位。
- 素材：一张 2048×2048 的 6 列 × 8 行姿态图集，48 个姿态；11 个动作视频共 609 帧；6 张静态姿态兜底；头像 256×240。
- 引擎：11 个动作全部在真实 WebGL 引擎中播放，脚线固定在 y=450（`bottom=0.878906`），主体始终在 512 画布内；走路使用素材自带 gait 参数与位移同步；视频失败时回退同龄静态图。
- 验证：19 品种领养/更换、类型检查、生产构建、207 项隔离业务断言通过。

## 生成与切分

母版与图集提示词都要求：单个角色、同一张脸与毛色、四腿、洋红 `#FF00FF` 纯净背景、无阴影/地面/文字，6 列是连续关键帧。图集行序与管线一致：

| 行 | 内容 | 生成的六帧 |
|---|---|---|
| 1 | 站立打招呼 | 呼吸、眨眼、歪头、回正 |
| 2 | 走路 | 六相位原地步态 |
| 3 | 吃饭 | 低头吃碗里的青草、抬头回正 |
| 4 | 抚摸 | 闭眼、歪头、放松 |
| 5 | 陪玩 | 前腿拨鼠尾草绿球 |
| 6 | 抱抱 | 坐起、双前腿抱胸 |
| 7 | 睡觉 | 卧下、闭眼入睡 |
| 8 | 伸懒腰 | 前腿前伸、低头拉长 |

`scripts/build-alpaca-toon.py --prepare` 不按数学网格切：先用洋红阈值与连通域找回 48 个真实主体，按行中心排序后重建每行边界，避免生成图行距漂移切到脚。然后统一归一：

- 坐姿中位身高缩放到 **330px**；
- 主体连通域中心对齐 **x=246**；
- 最低点对齐 **y=450**；
- 只做一次统一缩放，不逐姿态改大小。

洋红背景在轮廓处会留下绿边（洋红没有绿色，回收前景色时会把绿抬起来）。处理时只对距轮廓 3px 以内的像素做绿色钳制，保留腮红、内耳和画面内部的绒毛颜色；主体内部 alpha 置为 1，只有一圈抗锯齿边，避免插帧产生半透明鬼影。

## 走路：图集的第六帧几乎没有步态

第一张图集的走路行六帧几乎都是站立，只是耳朵和头略动。直接拿去做 RIFE 只会得到“站着平移”，正是此前柯基滑步的同类问题。曾单独生成一张 3×2 走路循环，六帧确实有抬腿，但体型比图集更敦实，换进去会像换了一只动物，因此没有采用，只保留在 output 作为否决不采用的记录。

最终做法是在现有站立姿态上做**四蹄位移场**：四只蹄子在 y≥405 处彼此分离（x≈149/201/271/309），身体在 398–430 之间用平滑权重过渡，因此不需要切开绒毛，也不会露出接缝。

- 相位：远后 0、近后 0.5、远前 0.75、近前 0.25，四拍步态；
- 支撑相占 68%，蹄子从前往后推；摆动相抬腿 12px、平滑前摆；
- 步幅 20px，编码 48 帧 / 30fps / 1.6 秒；
- 发布 `gait = { stridePixels: 40, supportSeconds: 1.088, canvasPixels: 512 }`，引擎据此计算平移动画时长，避免“脚在原地但身体滑”。

这条路线不做骨骼绑定，也不假装是骨骼动画：它只保证同一身份、同一尺度、脚底接触连续，步幅小于真实四足动物。

## 其余动作

除走路外，10 段视频用已有的 RIFE 4.25 离线补帧（30fps、VP9 alpha、`yuva420p`、`auto-alt-ref 0`、crf 22）：

| 动作键 | 帧数 | 关键帧 | 说明 |
|---|---:|---|---|
| greet | 72 | 站立 6 帧 | 循环呼吸与眨眼 |
| eat | 48 | 吃的前 4 帧 | 低头进食 |
| eatrev | 24 | 吃的后 3 帧 | 抬头退出 |
| petted | 48 | 抚摸前 4 帧 | 闭眼享受 |
| petted-out | 21 | 抚摸后 3 帧 | 退出片，首帧接进入片尾帧 |
| play | 72 | 陪玩 6 帧 | 拨球循环 |
| hug | 66 | 抱抱 6 帧 | 坐下抱胸后回正 |
| sleep | 72 | 睡下 6 帧 | 播放后定格 |
| wake | 60 | 睡下反向 6 帧 | 醒来由睡姿倒推 |
| stretch | 78 | 伸懒腰 6 帧 | 前腿前伸 |

静态兜底姿态：`sit`（站立）、`walk`、`sleep`、`stretch`、`roll`（取自陪玩）、`jump`（取自抱抱）。`roll` / `jump` 只是姿态兜底，不是独立翻滚或跳跃动画。

## 登记点

新增物种而不是复用猫狗，因此需要同时改七处：

| 文件 | 改动 |
|---|---|
| `server/daily.mjs` | `BREEDS` 增加 `alpaca_toon`；`SOUND_SPECIES` 增加 `alpaca` |
| `server/pet-progression.mjs` | 成长速率 `alpaca: .88` |
| `web/src/mvp/petBreeds.ts` | `SPECIES_META.alpaca` 与 `BREED_LIST` 一行（名字、默认名、介绍、台词） |
| `web/src/mvp/breedConfig.ts` | `fr:1`、`vd:196/230`、`facing:1`、`sound:'alpaca'`，并扩展声音联合类型 |
| `web/src/mvp/petEngine.ts` | `SOUND_MAP.alpaca`（暂无专属音效，显式空数组而不是静默缺失） |
| `web/src/mvp/Adopt.tsx` | 领养页物种筛选「羊驼」；羊驼与卡皮巴拉共用狗的蛋图破壳 |
| `web/src/v2/PetPicker.tsx` | 选择器筛选「羊驼」与「新伙伴」标记 |
| `scripts/verify-pet-selection.mjs` | 品种数 18 → 19 |

自有包由 `copy-pet-assets.mjs` 读取 `pet.json` 自动发布，并生成 `compatible` H.264 带透明打包的 mp4；Chromium 能播 H.264 时引擎优先使用该副本，绕开部分解码器丢弃 VP9 alpha 的问题。

## 验证与限制

已核对：

- 图集 48 个主体全部找回，切分后无缺腿、缺耳；静帧在浅底/深底/透明预览下无绿边。
- 11 段视频用 libvpx 解码成功，共 609 帧；发布文件与生产目录哈希一致。
- 真实引擎逐动作：greet / eat / petted / play / hug / sleep / wake / stretch 全部 `renderer=video`；四边像素边界均在画布内，最低点统一在 y=450（WebGL 读取为 62）。
- 走路：位置 50 → 30 时容器同步左移，视频用 gait 计算时长；播放中打断、失败回退到 `frame-sit.png` 均正常。
- 1440×900 首页、选择器、动作截图与 320px 场景裁切图已人工查看；真实家庭数据未被用于测试，测试库为一次性临时目录。

限制：

- 单年龄。若要做六阶段成长外观，需要 6 张图集和每套 11 个动作，按柯基/卡皮巴拉的成本另算。
- 走路是“绕髋关节刚性旋转 + 摆动抬腿”的二维装配，不是骨骼或原生步态；四条腿彼此靠得很近，步幅（26px）比真实四足小。
- 没有 `walk-start` / `walk-stop`，`walkTransitions=false`；开关打开前需要逐片审核起止构图。
- 生成式图集仍有轻微身形与脸部差异（例如耳朵角度、背斑边界），不是逐像素一致的角色绑定。
- 未做 iPad Safari 真机验收；透明视频降级路径只在 Chromium 与本机浏览器验证。
- 羊驼暂无专属音效，抚摸/陪玩只有现有提示音或无音效。

证据：`output/alpaca-toon-20261114/`（图集原图、切分预览、走路条、生产参数）与 `output/alpaca-toon-20261114/playwright/`（首页、选择器、逐动作截图）。


## 2026-11-15 动作修复 v2（对照卡皮巴拉 v2）

按卡皮巴拉 v2 的问题与验收线，对羊驼 RIFE 交叉淡入产生的内部半透明重影做了量化审计：

| 动作 | 修前内部半透明像素峰值 | 修后 |
|---|---:|---:|
| walk | 25 | 0 |
| play | 13 | 0 |
| petted | 0 | 0（改为固定脚底的表情形变） |
| petted-out | 0 | 0 |
| stretch | 5133 | 0 |
| hug | 484 | 0 |
| eat | 225 | 仍为 RIFE |
| sleep | 990 | 仍为 RIFE |
| wake | 1032 | 仍为 RIFE |

根因与卡皮巴拉一致：RIFE 在两套不同姿态之间做 RGBA 混合，重叠不到的肢体就变成半透明；短腿用水平剪切还会被拉成橡皮腿；玩球的深色轮廓不在绿色阈值内，只抠绿色会留下月牙。修法与卡皮巴拉 v2 相同——**每段动作只用一张干净母帧，内部不透明，不做帧间淡入**：

- **walk**：四只蹄子在 y≥405 分离，按 x 中点切成四个独立层；绕髋关节（y=405）**刚性旋转** 13px 步幅、摆动相抬腿 6px，腿根 399–405 羽化，接缝不露；四拍相位 0/.5/.75/.25，48 帧/1.6s，循环缝 0.81 → 0.27。
- **play**：改用球与身体分离的第 6 帧作母帧，整颗球连同深色轮廓作为独立层移除，再滚动回位；前爪轻压与低头跟随用同一张纹理的连续形变完成，72 帧。
- **petted / petted-out**：单张闭眼母帧 + 抬头蹭手形变，脚底锁定在 448；退出片首帧与进入片尾帧 alpha 完全相等（seam 0.0）。
- **stretch**：单张伸懒腰母帧 + 前段水平拉伸与躯干微倾，蹄子固定在 448，60 帧。
- **hug**：单张坐姿抱抱母帧 + 呼吸与轻压，60 帧；动作从坐姿开始，只切一次，不再站—坐—站两次硬切。

共 6 段 309 帧，无内部半透明像素，四个着地动作脚底在 448–449。版本升到 `2026-11-15.alpaca-motion-v2`，走路 gait 按实际步幅改为 `stridePixels: 26`、`supportSeconds: 1.088`。

复现：

```sh

python3 scripts/verify-alpaca-motion.py
python3 scripts/repair-alpaca-motion.py --publish
npm run assets:copy
npm run typecheck
npm test
npm run build
```

验证：`verify-alpaca-motion.py` 通过（6 段 309 帧、内部半透明 0、最小同时支撑 2、petting 接缝 0）；真实引擎 8 个动作仍为 `renderer=video`，脚线 61–63（画布 450），失败回退 `frame-sit.png`；类型检查、生产构建与隔离业务回归通过。

仍未修：eat / sleep / wake 保持 RIFE，重影水平与卡皮巴拉已接受的范围同类（卡皮巴拉 sleep 为 1283，羊驼 990），若要彻底消除需同样改成单纹理形变，但“低头吃饭”“躺下睡觉”没有单张母帧可同时覆盖起止姿态，需另做两段过渡或接受硬切。验证证据：`output/alpaca-motion-repair-20261115/`。
