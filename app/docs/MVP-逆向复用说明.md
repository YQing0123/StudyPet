# 萌宠逆向成果在「伴学小岛」里的复用说明

本文对应 MVP 的实现。目标不是重做一个桌宠壳，而是把逆向出来的**渲染链、动作拼接和养成数值**，接到「计划 → 打卡 → 积分 → 材料 → 养成」的学习闭环上。

## 一、原程序是什么结构

| 层 | 原程序 | 我们实际复用什么 |
|---|---|---|
| 宿主 | Rust/Tauri + WebView2，窗口移动、拖拽、置顶、壁纸由原生实现 | 不复用宿主；网页内用 CSS 横向移动代替 OS 窗口移动 |
| 桥接 | `petapi-shim.js`：状态读写、互动数值、成长、定制包、云同步 | 复用它的数值规则与数据结构思路 |
| 宠物页 | `pet.html`：17 态状态机、PNG/视频双层、WebGL 抠像、热区、音效 | 复用渲染链、状态机骨架、尺寸补偿表 |
| 管理面板 | `app.html`：品种、外观、成长、百宝箱 | 只参考交互结构，MVP 重写为网页 UI |
| 资源 | 454 个 Brotli 资源：226 个 VP9 WebM、143 张 PNG、23 个 MP3 等 | 复制 4 个品种的帧图、13 类动作视频、蛋/破壳、头像、音效 |

原程序的动画不是骨骼/Live2D，而是**预制视频 + 姿态图 + 实时抠像**；这一点决定了复用方式。

## 二、渲染链：为什么普通播放器看到绿底

`pet.html` 的 `initVideoLayer()`（约第 1023 行）创建 `<video>`、Canvas 和 WebGL program。浏览器解码 VP9，`requestAnimationFrame` 把视频帧上传成纹理，片元着色器计算透明度：

```glsl
// 绿幕
float dom = c.g - max(c.r, c.b);
// 蓝幕
float dom = c.b - max(c.r, c.g);
float a = 1.0 - smoothstep(0.06, 0.17, dom);
```

再做去溢色。带 `*.alpha.webm` 的片子直接使用视频 alpha，并按 `dom>0.30 && r<0.20` 修边缘绿线。原程序用 `ALPHA_KEYS` / `BLUE_KEY_TAGS` 两张注册表决定每条片子的抠像模式。

MVP 的 `web/src/mvp/petEngine.ts` 原样实现了这三条路径，并在构建素材时把每条视频的 `mode` 写进 `pets/manifest.json`：

- `*.alpha.webm` → `alpha`
- 虎皮鹦鹉/牡丹鹦鹉的非 alpha 片 → `blue`
- 巴西红耳龟的 walk 系 → `green`，其余动作 → `blue`
- 猫、狗 → `green`

这样前端不需要硬编码几十条品种/动作判断，也不存在「蓝幕品种用了绿幕公式」的穿帮。

### 尺寸补偿

原程序为了消除「摸头突然变大」「走路比坐着大」的问题，维护了四张表：

- `FR_COMP`：帧图品种归一
- `VD_COMP`：视频层品种归一（含 196/230 容器比补偿）
- `ACT_COMP`：品种 × 动作补偿
- `CARE_COMP`：投喂/陪玩/抱抱补偿

MVP 把 4 个品种的这四张表复制进 `petEngine.ts` 的 `BREED_COMP`，并保留 `FRAMES` 的 196px 与视频的 230px 两层容器比例，再乘一个网页展示用的全局倍率。因此切动作时脚线不被破坏，帧↔视频的体量连续。

## 三、动作如何拼成连贯行为

| 行为 | 原程序做法 | MVP |
|---|---|---|
| 走路 | `walk-start → walk(loop) → walk-stop`，原生窗口同步移动 | 网页内 `left` 平移动画 + 同三段视频；朝向按 `WALK_FACING` 镜像 |
| 摸头 | `petted → petted-out`，收尾片是手收回 | 同两段链；视频结束后落回坐姿 |
| 吃饭 | `eat` 正放与 `eatrev` 倒放交替，形成「吃—缩回—再吃」 | MVP 只播一遍 `eat`，播完落坐，避免网页里拖太久 |
| 睡觉/醒来 | `sleep` 播一次定格末帧，`wake` 独立片 | 同：sleep 定格，小憩按钮/点击叫醒播放 wake |
| 投喂/陪玩/抱抱 | `feedcatch / play / hug` 独立片 | 同，播放完回 IDLE；缺素材自动回退帧图 |

状态机在原程序有 17 态（`BOOT/IDLE/WANDER/HAPPY/GREET/SLEEPY/SLEEP/WAKING/DRAGGED/GO_NEST/GO_FOOD/IN_NEST/EATING/PETTED/FEEDCATCH/PLAY/HUG`），并带优先级抢占。MVP 去掉了窗口导航、拖拽、窝/食盆锚点，保留 11 态：

`IDLE / WANDER / HAPPY / GREET / SLEEPY / SLEEP / WAKING / EATING / PETTED / PLAY / HUG`

`IDLE` 的自主行为按原程序思路做加权随机：散步、开心、伸懒腰、打招呼、偶尔打盹；用户一点击就打断并接管。原程序待机 28–50 秒评估一次，MVP 放宽到 32–56 秒，避免学习时太闹。

## 四、养成数值

原程序 `petapi-shim.js` 的 `tick()`（约第 1660 行）每 30 秒衰减一次，只有当前窗口绑定的宠物参与：

- 饱食 −0.05、精力 −0.04、心情 −0.03、清洁 −0.02（每 30 秒）
- 投喂：饱食 +32、成长 +2
- 抚摸/陪玩/抱抱：心情 +10、成长 +1
- 每 50 成长值掉一次百宝箱
- 阶段按领养天数 × 物种速率：基础阈值 1/3/7/14/30/45 天；大型犬 0.72、小型犬 0.88、猫 1.0、鸟 1.15、龟 0.55；在线陪伴最多加 20% 天数
- 阶段体型 0.62/0.80/0.92/1.00/1.00/0.94，视频速度 1.12/1.12/1/1/1/0.85

MVP 的换算：

- 衰减改为按小时连续计算（饱食 4.4/h、精力 3.4/h、心情 2.4/h、清洁 1.8/h），单次最多结算 12 小时，避免离线回来直接归零。
- 动作奖励按原值保留，另把「材料」接进来：食物补饱食、玩具补心情、清洁补清洁、装扮进入 `outfit`。
- 成长值仍然每 50 掉材料；MVP 直接掉进背包，不再弹「百宝箱」弹窗，减少打断。
- 阶段仍按领养天数 + 物种速率，当前 4 个品种的速率是猫 1.0、柯基 0.88、虎皮鹦鹉 1.15、红耳龟 0.55。

## 六、在 MVP 里新加的业务闭环

原程序是「桌宠 + 互动」，没有学习计划。MVP 新增：

1. **今日计划**：任务名、科目、预计分钟、完成奖励；完成后立即记积分，全部完成额外 +15。
2. **积分账本**：`point_ledger` 以 `dedupe_key` 保证重放不重复发奖；撤销会退回积分，已花掉则拒绝撤销。
3. **材料铺**：9 种材料，食物/玩具/清洁/装扮四类，用星贝兑换。
4. **背包与使用**：食物触发吃饭视频并补饱食；玩具触发陪玩；清洁触发摸头/理毛；装扮直接叠加到宠物身上。
5. **养成**：四项需求、成长值、百宝箱、阶段、头像/档案、重置。
6. **领养**：4 个品种可选，先领养再落 3 个示例任务；领养时播放蛋→破壳。

## 八、边界与下一步

- 没有做原生透明置顶窗、点击穿透、拖拽、多显示器/DPI；这些是 Tauri 宿主能力，不是网页能等价复刻的。
- 没有复刻云同步、定制包、婚礼、荣养、装扮图层等原程序长尾功能。
- 多宠物、周计划模板、跨天补卡、家长端、教材/题目训练尚未接回；MVC 先保证「一天」的闭环跑通。
- 原程序的部分视频构图差异较大（特写/卧姿），当前沿用原补偿表；后续可对每条片做 alpha 包围盒实测，生成逐片补偿，进一步收紧体量。
- 原素材的离线抠像在柯基 `play.alpha.webm` 中把小球黑色条纹误删成透明；已在 `scripts/patches/dog_corgi/` 做逐帧 alpha 修补并在复制脚本中覆盖。4 品种 × feedcatch/play/hug 共 12 条照顾片逐帧抽检，除柯基 play 外其余 11 条正常。
- 个别姿态图自带素描阴影/纸边（如柯基坐姿脚下），属于源素材，不是实时抠像产生。


## 九、v2 新增：把宠物接进「学生 + 家长」的日常

v2 没有改渲染链，只在外面加了计划与审核：

- **周期计划**：`plan_rule` 保存星期、时段、积分、审核/拍照要求；`v2_task` 按天实例化，同一规则同一天只生成一条。
- **审核才发分**：学生提交 → `submitted`；家长通过 → `approved` 并写 `point_ledger`；退回 → `rejected`，可重交，但同一任务只发一次。
- **时间窗**：提交时间早于 `start_time` 记提前，晚于 `end_time` 记超时；按规则的早鸟分/超时扣分算预计星贝。
- **心愿与材料**：材料仍由 `daily.mjs` 提供，家长只覆盖价格；心愿奖励单独建 `reward_item` / `redemption`，兑现由家长处理。
- **情感层**：任务状态、对话台词、状态说明、`今天的小纸条`、审核通过的彩带与星贝飘字，都是 v2 新增，不依赖原程序。

宠物数值没有被审核逻辑改写：审核只加心情 +2，不直接加成长；成长仍来自喂食、陪玩、摸摸、抱抱，保持「学习给积分、照顾给成长」两条节奏。
