# 宠物共用场景服务、清洁与房间布置

本次在现有宠物、作息、背包和星贝系统中实现；未部署到线上。开发、接口与浏览器验收使用独立的临时家庭数据库。

## 1. 可持续扩展的结构

```text
场景入口 / 状态阈值 / 时间机制
          ↓
共享场景配置 petScenarios.mjs
（条件、每日次数、状态增减、动作、动效、台词）
          ↓
服务端资格校验与事务结算 ──→ changePetState
          ↓                         ↓
最新状态 + scenario + stateDelta   上下限 / 归属 / 幂等回执
          ↓
PetEngine 动作原语 + sceneVisuals 覆盖层
          ↓
背景 → 后层家具 → 宠物/身体装扮/清洁动效 → 前层家具 → 提醒气泡
```

- `server/pet-state.mjs`：四项状态的统一写入服务，支持 `delta` 增减、`set` 指定值、`caps` 恢复上限、变化原因和可选事件幂等键。返回真正发生的增减量。恢复上限不会倒扣已经更高的状态。
- 被动衰减、睡眠精力恢复、任务心情奖励、喂食、玩具、梳毛、泡澡、首次穿戴、免费互动、小憩及睡眠打扰扣值，都通过状态服务结算。被动结算与 `last_tick` 同事务更新。
- 成长继续由 `pet-progression.mjs` 管理每日分类额度与百宝箱；星贝继续由积分账本管理。
- `web/src/shared/petScenarios.mjs`：前后端共享的场景、动作映射、状态条件、日常提醒、睡眠梦话、脏污分级和素材登记。
- `server/pet-scenarios.mjs`：执行状态条件、北京时间每日一次与状态写入。每日记录按孩子保存，换宠物、重养、恢复备份不重领。
- `POST /api/v2/pet/scenario {scenario}`：仅执行配置中 `publicInteraction: true` 的场景；内部场景不能借此绕过休息冷却、材料消耗或成长额度。当前开放 `shower`。保留 `/api/v2/pet/shower` 兼容入口。
- `PetEngine`：复用摸摸、陪玩、抱抱、睡觉等动作原语，通用清洁流程读取动效与时长。清洁可以被定时睡眠中断；所有覆盖层和定时器随中断/卸载清理。
- `sceneVisuals.ts`：统一 PNG 图集与原生 GIF 的加载、解码、绿幕透明合成、帧缓存和播放。每份素材只解码一次；后台暂停推进，减少动态效果时使用静态帧。

新增使用现有动作类型的场景，例如每日伸懒腰，可以登记：

```js
morningStretch: {
  publicInteraction: true,
  action: 'stretch',
  label: '早安伸懒腰',
  delta: { energy: 4, mood: 2 },
  oncePerDay: true,
  limitMessage: '今天已经伸过懒腰啦，明天再一起活动。',
  conditions: [{ stat: 'energy', below: 95, message: '现在精神很好啦。' }],
  line: '伸伸胳膊，今天也一起加油！'
}
```

添加入口后调用通用接口，前端播放返回的场景；状态结算、每日资格、动作服务可直接复用。若引入现有动作和条件无法表达的全新机制，需要扩展对应原语或规则，避免把任意业务脚本塞进配置。

## 2. 清洁玩法

| 清洁度 | 共用脏污覆盖 |
| --- | --- |
| ≥65 | 无虫蝇 |
| 50～不足65 | 1只小卡通苍蝇 |
| 30～不足50 | 2只小卡通苍蝇 |
| 不足30 | 2只小卡通苍蝇、1只小卡通爬虫 |

按用户反馈降低虫蝇的视觉强度：苍蝇覆盖画布宽高从25%缩为12%，虫子从22%缩为8%，并将总量上限从5只苍蝇、2只虫子降为2只苍蝇、1只虫子。保持原生GIF的弧线飞行、停靠和卡通造型，显示比例跟随宠物舞台；清洁度65及以上完全移除虫蝇覆盖层。

低于80加入洗澡提醒；低于50明确提醒需要🛀泡泡浴。沿用统一提醒间隔，避免连续刷屏；睡眠期间优先梦话。

- 免费简单淋浴：北京时间每天一次；清洁度至少50且不足95时可用；增加20，上限95。已经很清爽时不浪费每日次数。
- 泡泡香香浴：图标🛀，默认62星贝，家长价格覆盖继续生效。每次消耗一件，清洁设为100，心情最多增加8，沿用清洁用品的成长分类额度。
- 低于50时梳子也不能绕过认真泡澡的要求；摸摸不再恢复清洁。
- 简单淋浴播放约3秒，再闪光1秒；泡澡播放约3.5秒，再闪光1秒；梳毛沿用工具上下晃动2秒、再闪光1秒。
- 每日次数、库存扣除、状态、成长奖励和百宝箱结算由服务端事务保证。睡眠中尝试使用只触发原有梦话/提醒规则，不扣用品、不领次数。
- 状态反馈使用实际增减量；阈值判断与清洁度显示统一到一位小数，避免显示50.0却被微量衰减拦截。状态接近上限时，不显示超出上限的恢复数字。

## 3. 永久场景与家具

初始永久拥有小书房。新增阳光花房（120）、海风小屋（160）、林间木屋（200），均为星贝默认价。场景兑换后在背包切换，切换场景保留家具布置。

首批16件家具，覆盖自然原木、奶油简约、暖杏田园三类：龟背竹、小花陶盆、落地灯、双人沙发、扶手椅、彩电与电视柜套组、餐桌与双椅套组、书架、地毯、茶几、宠物床、迷你冰箱、空气净化器、收音机、大榕树和花瓶斗柜。默认价格45～200星贝；沙发180、餐桌椅套组180、电视柜套组200。2026-11-16按收集目标下调高价商品，原本低价的小摆件不涨价；家长手动设置的价格仍优先。

- 场景和家具永久收藏，重复购买/批量购买被服务端拒绝，不重复扣款。
- 每件家具可摆放一次；套组为一个完整素材。收回后继续保留所有权，重摆免费。
- 长按450毫秒进入编辑；鼠标/触控拖动；旋转每次15度；支持0.6～1.5倍缩放、宠物前/后层切换、收回、取消和完成。
- 点编辑区之外保存；回车进入编辑，方向键微调位置，Escape取消。
- 位置保存为场景百分比，随屏幕适配。服务端校验所有权、数量、位置、角度、缩放和层级。版本号防止旧页面覆盖较新布置。
- 房间数据按孩子保存。换宠物、重养与宠物备份恢复均保留收藏和布置。
- 家具使用带体积和阴影的2D贴图，旋转为平面旋转；房间层级负责前后遮挡。宠物提醒气泡始终高于前层家具。

配置与持久化分别位于 `web/src/shared/roomCatalog.mjs`、`server/pet-room.mjs`；新商品只需登记图、目录信息、默认价格和尺寸，复用现有购买、永久收藏、背包及编辑器。

**苍蝇生成历史：** 首次返回非GIF，后续两次请求返回 `invalid_output_format`（仅支持PNG/JPEG/WebP）。在获得原生GIF前，苍蝇使用统一的程序飞行动效，`EFFECT_ASSETS.fly = null`。未用静态图拼接冒充原生 GIF。

2026-11-16 按用户要求再次调用 `/Users/yqing/.codex/bin/image2`，显式使用 `gpt-image-2.6`、`quality=medium`、`size=auto`、`output_format=gif`。提示词要求苍蝇在左下、右侧、下方中间三个位置轮流停靠，沿连续弧线飞行并循环。上游仍在生成前返回 HTTP 400 `invalid_output_format`，没有产出GIF，未修改生产素材登记。

随后用户指定 `gpt-image-2.6-sunburst`，使用 `quality=high`、`size=auto`、`output_format=gif` 和相同提示词，成功返回438×390的原生循环GIF。逐帧检查确认左下、右侧有落脚收翅的停靠姿势，中间沿弧线飞行；主体像素重心横向移动约174.52像素、纵向约159.61像素。实际是1.8秒、主要两个停靠位置，未完整达到提示词约4秒、三个独立停靠点的要求。已将原始返回字节复制到生产目录，登记为 `EFFECT_ASSETS.fly = 'pets/effects/fly.gif'`，所有宠物共用绿幕合成与清洁度分级覆盖层。

初次接入时，苍蝇按取模计算位置，第4、5只与第1、2只的位置相近；切换原生GIF后同步播放使重叠明显，当时先改为5个分散坐标。该次使用正式 `PetEngine` 和 `sceneVisuals` 的独立无头浏览器核验通过：9种不同播放帧、绿色底色透明合成、旧规则下5只苍蝇与2只虫子的分级显示、苍蝇位置无重复、清洁度达到旧阈值80后移除覆盖层、减少动态效果时冻结画面。历史记录和截图位于 `app/output/playwright/fly-sunburst/`，未连接家庭数据。
