# 宠物素材制作与接入

## 先理解当前播放方式

当前入口是 `web/src/v2/V2App.tsx`，宠物由 `mvp/PetStage.tsx` 包装 `mvp/petEngine.ts`。静止时是透明 PNG 加轻微 CSS 呼吸；多数品种交叉淡入，卡皮巴拉直接切换以避免双轮廓。动作优先使用H.264兼容片段：alpha素材将RGB和蒙版左右打包，由WebGL同帧恢复透明；保留VP9 alpha/绿幕/蓝幕WebM回退。走路位移由容器沿地面移动，视频负责腿部动作；有`gait`元数据的品种按脚部支撑速度同步位移。它不是骨骼绑定、Spine、Live2D 或三维模型。

原程序是 Rust/Tauri + WebView2。REA 研究从 PE 资源表的路径/数据指针定位嵌入资源，再 Brotli 解压出 HTML、脚本与媒体；并未还原原始 Rust 工程。视频是已经烘焙好的画面，反编译不能重新得到动物的骨骼或拍摄场景。写实外观不等于确定是实拍：原资料也出现生成批次说明，应按逐个素材证据判断来源。

## 建议怎样逐步替换

优先选一只宠物统一重做一套：坐姿、走路、进食、抚摸、陪玩、睡下/醒来。先锁定同一角色的脸、毛色、体型、朝向、画风、镜头和光线，再做动作。不要把不同生成批次或不同风格的短片直接拼成同一只宠物。

- **写实路线**：固定镜头/焦距和地面，真实拍摄或同一角色参考生成；保留原始无损视频与分割蒙版，人工检查毛发、黑眼睛、脚爪、道具。绿幕会误伤绿色鸟和龟，蓝幕会误伤蓝羽毛，优先制作可靠的独立 alpha 蒙版。
- **卡通路线**：同一角色分层绘制再做二维骨骼或逐帧动画；也可三维绑定后固定镜头渲染。当前项目最省接入工作的方法是导出透明 PNG 序列，再编码成 VP9 alpha，继续使用现有引擎。
- **AI 视频路线**：一张角色定稿不能保证不同动作身份一致，需要参考图、首尾帧约束与逐帧验收。先小批量做好一个动作再扩展。GIF 是预览格式，当前播放器的生产格式仍为 WebM/PNG。

第一轮局部修补没有调用付费生图/生视频，均基于已有文件。后续新增卡通柯基已按用户指定调用 gpt-image-2.6-sunburst，见文末。原柯基球的黑色区域是恢复原 RGB 对应的 alpha；前爪和行走颜色使用局部合成/插值，不能称为原始细节恢复。

## 交付规格

1. 素材主档保留 PNG 序列、独立蒙版、角色参考和制作工程；网页文件只做发布版本。
2. 当前兼容画布是 512×512，宠物居中、脚底位置固定，动作全过程不出画。建议主档至少 1024 方形，最后统一缩至发布尺寸。
3. 保持 24/30 fps 和真实时间戳。走路片首尾接近且无镜头位移；静止、进入、退出动作的首尾造型应能接上。
4. 道具如球、食盆、栖木须纳入蒙版，深色眼睛和球纹不能按“黑色背景”直接删除。不要把灰色纸面投影烘进宠物，舞台已有接地阴影。
5. 所有动画必须在浅底、深底、棋盘格和真实房间背景检查；重点看手指、毛发、脚趾、半透明边缘、动作中途和首尾衔接。

透明序列编码示例（fps 按实际素材调整）：

```sh
ffmpeg -framerate 24 -i frame-%04d.png -an -c:v libvpx-vp9 \
  -pix_fmt yuva420p -auto-alt-ref 0 -crf 24 -b:v 0 pet.alpha.webm
# 验证透明帧必须用支持 alpha 的 libvpx 解码
ffmpeg -c:v libvpx-vp9 -i pet.alpha.webm -frames:v 1 check.png
```

## 在代码中增加品种

现有目录是 `web/public/pets/breeds/<breed>/frames/`、`videos/<breed>/`、`avatars/`。复制程序的来源是只读研究归档，新增原创素材不要写进归档。每个自有包放在 `assets/pets/<breed>/`，用 `pet.json` 声明头像、姿态和动作；复制脚本会自动登记并发布其中声明的媒体。原件、提示词放 `source/`，不会发布到网页。`scripts/patches/` 仅用于原有素材修补。

需要改的登记点：

| 文件 | 内容 |
|---|---|
| `scripts/copy-pet-assets.mjs` | 品种、源目录、动作抠像方式、透明补丁优先级、可用走路过渡 |
| `web/src/mvp/breedConfig.ts` | 静态/视频尺寸补偿、动作补偿、自然朝向、声音物种 |
| `server/daily.mjs` | 后端品种、名字、物种、成长速度 |
| `web/src/mvp/petBreeds.ts` | 名称、介绍、物种、默认名字；领养页与选择器共同使用 |

现有六姿态键：`sit / walk / jump / sleep / stretch / roll`。13 个视频键：`walk-start / walk / walk-stop / greet / eat / eatrev / petted / petted-out / sleep / wake / feedcatch / play / hug`。文件缺失时引擎可退回静态图；没有独立姿态就明确记录，不伪造“六套动画”。喂食当前走 eat→eatrev，抚摸走 petted→petted-out；feedcatch 保留为未来接食动作。

原有归档素材修补后顺序运行素材复制、`audit-pet-assets.py` 和再次复制，把实际落地点写入 manifest；自有包直接在 `pet.json` 声明实测 bottom，避免通用归档审核脚本覆盖其专用定位。检查六姿态及实际提供动作的首中末帧，再测试走动中摸头、睡着时唤醒/喂食、连续切动作、视频404、WebGL失效、换品种和重新挂载。最后运行 `npm run typecheck`、`npm test`。H.264兼容转码见`scripts/build-compatible-pet-videos.mjs`；iPad仍须真机检查，后台WebKit与静态回退不能据此宣称真机动画全部通过。

卡皮巴拉当前使用`2026-11-15.capybara-motion-v3`，定向复现与发布见[卡皮巴拉制作说明](docs/宠物成长与卡皮巴拉-2026-11-14.md)。补帧前先检查关键姿态，不能用两个不同嘴鼻/肢体轮廓的RGBA加权叠加掩盖不匹配；alpha检测也不能发现所有RGB内部重影。

## 本轮资源状态

原有 16 品种均保留资源和解码检查图，现已按用户要求全部开放；连同卡通柯基、卡皮巴拉与羊驼，共 19 个可选品种。原品种仍有动作间身份/风格差异，建议继续逐套替换。不要用全图亮度阈值删除纸边：白毛和脚掌正是这种做法最容易损坏的位置。

## 第一套自有素材：卡通柯基

`assets/pets/dog_corgi_toon/` 为已接入的示范包。先用原卡通柯基参考生成一张母版，六段动作都引用同一母版并重复角色约束；模型为用户选定的 `gpt-image-2.6-sunburst` / high，使用 CLI fallback。母版为 2K，原生动画实际返回约 414–439px、9 帧/1.8 秒，不能称为 2K 或原生 24 帧动画。

脚本 `scripts/build-corgi-toon.py` 离线处理洋红底、边缘去色、统一眼间距与脚线，保留原生关键帧，编码到 24 fps 的 VP9 alpha 容器。已去掉造成脚爪/球重影的光流插帧。醒来由睡下倒放，抱抱复用抚摸；静态 jump/roll/stretch 从相邻动作提取，尚无独立跳跃、翻滚或伸懒腰动画。

复现：先 `python3 scripts/build-corgi-toon.py`，结束后 `npm run assets:copy`，再 `npm run typecheck`、`npm test` 和 `npm run build`。这个过程使用已保存原件，不会再次收费生成。完整提示词在包的 `source/prompts/`，原件散列与制作参数在 `source/production.json`。详见 [试制记录](docs/卡通柯基试制-2026-11-13.md)。


## 2026-11-13：同角色平滑动作 v2

用户认可的卡通柯基保留原母版与原生GIF，新增RIFE 4.25离线神经补帧，9段动作共489个独立中间/关键画面，30fps VP9透明WebM。新增动作不再用重复关键帧伪装高帧率。每段21–78帧；hug仍复用抚摸，wake仍由sleep反向关键帧推导。

复现顺序：

```sh
python3 scripts/build-corgi-toon.py --export-keys /绝对路径/original-keys.npz
# 在含torch、numpy、Pillow的独立Python环境运行；rife-dir含IFNet_HDv3.py和model.pkl。
python scripts/smooth-corgi-toon.py --keys /绝对路径/original-keys.npz --rife-dir /绝对路径/rife --out /绝对路径/smooth
python3 scripts/build-corgi-toon.py --smooth-from /绝对路径/smooth
npm run assets:copy
npm run build
```

模型与代码来源、SHA256及MIT许可见scripts/lib/rife；本次构建环境和权重保留在工作区output/family-smooth-20261113。权重仅用于离线制作，不加入前端运行依赖。新动作仍需原始连续画面支持，补帧无法替代缺失的表演，也无法保证修复原始生成中的所有结构偏差。默认构建脚本拒绝无参数覆盖已发布的v2包。


## v3：陪玩多余前腿修复

逐帧复查发现，原生陪玩GIF第4、5、7张关键帧（从1计数；数组索引3、4、6）已经有多余前腿，RIFE将错误形体延续到了相邻帧。原GIF保留不改，发布时排除这三张，只在索引0、1、2、5、7、8的正常姿态之间补帧；保留原时间位置和2.6秒时长。静态roll回退也不再取错误的索引4，改取正常索引5；它仍只是兼容姿态，没有独立翻滚动画。

发布包版本为2026-11-13.v3，陪玩仍是78帧/30fps，其余8段WebM字节保持一致。关键帧筛选带规范化原始数组SHA256，记录在source/key-curation.json；构建脚本拒绝用未筛选旧素材覆盖v3。播放器素材URL携带sourceVersion，刷新后可取到新视频。

当前版本复现（app目录；使用此前含torch/numpy/OpenCV/Pillow的Python环境，权重保留在output）：

```sh
python scripts/build-corgi-toon.py --export-keys ../output/family-smooth-20261113/original-keys.npz
python scripts/smooth-corgi-toon.py \
  --keys ../output/family-smooth-20261113/original-keys.npz \
  --rife-dir ../output/family-smooth-20261113/rife \
  --out ../output/corgi-play-fix-20261113/smooth \
  --key-curation assets/pets/dog_corgi_toon/source/key-curation.json
python scripts/build-corgi-toon.py --smooth-from ../output/corgi-play-fix-20261113/smooth
npm run assets:copy
npm run typecheck
npm run build
```

本次没有调用Image API。验证包括78帧全量展开与前腿局部复查、透明解码、原GIF哈希、其他视频不变、发布目录及HTTP响应一致，以及后台浏览器在原问题时段定位播放。证据见output/corgi-play-fix-20261113，实际播放器截图见output/playwright/corgi-play-fix-20261113。

后续素材验收须先检查所有原始关键帧的肢体数量、遮挡关系、脸和道具，再补帧并展开检查全部输出；帧数和透明通道通过不足以证明形体正确。


## 2026-11-14：单年龄羊驼

`assets/pets/alpaca_toon/` 是第二套完全自有的素材包，也是第一只新物种（`alpaca`）。母版与 6×8 图集由 image 2.6 高精版生成，提示词、图集与生产参数留在包内 `source/`。切分不按网格，而用连通域找回 48 个主体；洋红边缘只做轮廓 3px 内的绿色钳制。

该图集的走路行几乎没有步态，因此没有用 RIFE 硬补，而是在站立姿态上按四只蹄子的位置做位移场：四拍相位、支撑相 68%、抬腿 12px、步幅 20px，48 帧 / 1.6 秒。它保证同一身份与连续脚底接触，但不是骨骼动画，步幅偏小。其余 10 段仍用 RIFE 4.25。

新增物种需要七处登记（服务端品种与声音、成长速率、前端品种表、尺寸补偿、引擎声音表、领养页筛选与蛋图回退、选择器筛选），并把 `verify-pet-selection.mjs` 的品种数改为 19。完整说明、验证与限制见[羊驼试制记录](docs/羊驼试制-2026-11-14.md)。
