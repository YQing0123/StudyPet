# 宠物素材修补（2026-11-13）

原始逆向归档只读。这里是项目自有修补，`npm run assets:copy` 按相对路径覆盖并更新 manifest。README、报告不作为媒体复制。先生成全部修补，再复制，最后验收；不要同时运行生成和复制。

## 已处理

- 3 种龟的 19 个非透明动作：纠正蓝幕登记；保留走路绿幕。
- 虎皮坐姿：撤掉不透明米色底补丁，从归档透明原图重新裁去两端栖木残块。
- 33 张姿态图：按确认的局部轮廓清除布偶黑色外缘、猫狗纸边/地面、龟脚下色块、鹦鹉栖木端部。只把相同原图散列的姿态应用同一个坐姿轮廓，不把坐姿遮罩套到其他动作。
- 柯基坐姿右前爪：原图颜色与 alpha 都损坏，采用完整左前爪的局部镜像合成；这是重建，非找回原像素。保留原眼部颜色修补。
- 柯基玩球 121 帧：根据球的白色外弧拟合中心和半径，只补球内部 alpha，保留原 RGB；92–97 帧与身体重叠的区间采用记录的中心坐标。
- 柯基行走及起止 3 片：保留原画面，局部修复青色污染并输出透明 VP9。颜色修补属于插值重建。
- 虎皮站栖木的 7 片：离线蓝幕转换、清除角落及进食片左侧灰块并收短栖木；地面玩耍/飞动片不使用相同遮罩。

## 重建步骤

需要 Python 的 Pillow/numpy/OpenCV 和 ffmpeg/libvpx-vp9。App 运行与普通复制不依赖这些离线工具，也不依赖下载的抠图模型。

```sh
# 在 app 目录；请顺序执行，等待每一步完成
python3 scripts/repair-static-pets.py
python3 scripts/repair-corgi-ball.py
python3 scripts/repair-video-pets.py
node scripts/copy-pet-assets.mjs
python3 scripts/audit-pet-assets.py
node scripts/copy-pet-assets.mjs  # 将最新脚底定位写入 manifest
```

`asset-bounds.json` 是根据实际解码帧生成的姿态/动作落地点；替换文件后必须重算。`static-repairs.json`、`video-repairs.json` 与玩球 `.repair.json` 记录实际采用的处理。

## 仍然属于源素材的问题

同一品种存在写实、水彩、卡通之间的造型变化；个别片带有人的手、源画投影、低分辨率和轮廓锯齿。抠像不能统一角色身份。部分静态六姿态实际重复，不能把它们称作六套独立动画。新增/替换建议见 `app/宠物素材制作与接入.md`。

目前产品领养入口继续提供 4 个代表品种；另外 12 个保留资源和技术播放能力，尚未因能解码就开放领养。Safari/iPad 真机仍需单独验收；不支持 VP9 透明通道的解码器会回退姿态图。
